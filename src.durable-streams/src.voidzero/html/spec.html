2. What the Project Is

VoidZero is an organization that builds one unified toolchain for web development, and the projects in this snapshot show the toolchain and the framework that uses it.

  • Vite+ (vite-plus) is the unified toolchain. One dependency supplies the

JavaScript runtime, package management, project creation, the development server, checking, testing, building, packing, and monorepo task caching. The command is vp. The command is split in two parts. A Node.js script loads a TypeScript entry point, which handles the global commands. Every other command goes to a Rust core through Native API (NAPI) bindings. A separate Rust global command-line binary resolves and starts a local installation. The Rust workspace has fifteen crates, and the TypeScript side has four packages.

  • Vite Task (vite-task) is the task runner inside Vite+. It has a

dependency-aware scheduler with a persistent and remote cache. It contains fspy, a file-system proxy that traces the files that a task reads and writes, so that a cache key describes the real inputs rather than a declared guess.

  • setup-vp (setup-vp) installs vp in GitHub Actions, GitLab CI/CD, and

Azure Pipelines.

  • Void (void) is a full-stack framework that builds with Vite and deploys

to Cloudflare Workers. It adds file-based server and page routing, typed database, storage, and AI access, migrations, resource provisioning, and a one-command deployment. It also carries a self-hosted team platform.

  • void-fbtee (void-fbtee) is an internationalization add-on for Void. It

uses fbtee for strings and the browser Intl Application Programming Interface (API) for numbers, dates, and lists.

  • chrome-capture (chrome-capture) records a Chrome tab to an AV1 .mp4

file with the Chrome DevTools Protocol (CDP) Page.startScreenRecording command, with no ffmpeg dependency.

  • lite-youtube-embed (lite-youtube-embed) is a custom HyperText Markup

Language (HTML) element that renders a YouTube player with a small facade, so the page loads much faster than an embedded iframe.

A reader must be able to:

  1. State what VoidZero builds, and how the seven repositories relate.
  2. Map every repository and name the package or crate that holds each concern.
  3. Trace one vp command from the shell to the TypeScript handler or the

Rust core.

  1. Explain how Vite+ resolves a Node.js version, installs packages, and runs

the development server.

  1. Explain how Vite Task builds a task graph, selects tasks, computes a cache

key, and restores an artifact.

  1. Explain how fspy observes file access on Linux and on Windows.
  2. Trace one Void request from the Cloudflare Worker entry point to a page, a

server route, or a resource binding.

  1. Explain how Void provisions a resource, applies a migration, and deploys.
  2. State what the self-hosted Void Platform adds.
  3. Explain how setup-vp, void-fbtee, chrome-capture, and

lite-youtube-embed work.

  1. Compare Vite+ with pnpm, Nx, and Turborepo, and compare Void with Next.js

on Cloudflare Workers.

  1. State the limits and the open questions that the source does not answer.

7. Quality Requirements

The ten Iron Rules from markdown_engineering/documentation_directive.md apply:

  1. Detailed sections with code snippets from the source.
  2. The thesis in the first paragraph.
  3. One idea per sentence, in ASD Simplified Technical English. Spell out every

abbreviation at first use in each file.

  1. At least two Mermaid diagrams per document.
  2. Tables, trees, and diagrams as visual assets.
  3. Generated HTML with consistent navigation.
  4. Cross-references between documents.
  5. Source paths and line numbers for implementation claims.
  6. At least one Aha moment per document.
  7. An index and previous and next navigation on every page.

Each deep-dive document must hold at least ten code snippets. Every claim about behaviour must cite one of the seven repositories at the commit above, or one of their documents. A claim about an external system must name the external document.
