There are two repositories but one system. The Electric repository contains the Electric Agents platform, which stands on the Durable Streams protocol. The Durable Streams repository contains the protocol and its implementations. This exploration treats the two repositories as one architecture and states which repository each component comes from.

2. What the Project Is

Electric is two products in one repository:

  1. Electric Sync — an Elixir service that reads the PostgreSQL logical

replication stream and serves read-only subsets, called Shapes, over HTTP.

  1. Electric Agents — a TypeScript platform for durable artificial

intelligence agents. Each agent is an entity with one append-only event stream. A server materializes the stream into typed collections, wakes the entity handler, and records the agent's work back into the same stream.

Durable Streams is the storage and delivery primitive under Electric Agents. It is an HTTP protocol for persistent, addressable, append-only byte streams with offset-based resumable reads and live tailing.

3. Documentation Goal

  1. Know how the two repositories fit together and what each package does.
  2. Know, in complete detail, how the agent runtime sets up a durable stream.
  3. Know where stream bytes and stream metadata are stored, on every supported

deployment.

  1. Know the full request path from a user message to an agent run and back.
  2. Know the wake model: webhook wakes, pull wakes, the scheduler, signals, and

entity lifecycle states.

  1. Know the entity stream event schema and how the runtime materializes it into

TanStack DB collections.

  1. Know the Durable Streams protocol: offsets, JSON mode, producers, forking,

live reads, subscriptions, and the state protocol.

  1. Know the server implementation: PostgreSQL registry, stream client, routes,

projector, bridges, sandboxes, and tenancy.

  1. Know each remaining package at a depth that permits maintenance.
  2. Know the limits and open questions in the current code.

6. Build System

cd /Users/darkvoid/Dev/explorations/src.durable-streams

One build generates both the Electric and the Resonate sites and the root comparison page. The build script reads every src./markdown//.md, writes html//*.html with the same relative layout, and writes one index.html per directory. It then builds ../index.md to ../index.html. It uses only the Python standard library. Each directory's pages get prev/next navigation within that directory. Each index lists that directory's child directories and documents.

7. Quality Requirements

The ten Iron Rules from markdown_engineering/documentation_directive.md apply without exception:

  1. Detailed sections with code snippets from the source.
  2. Teach key facts quickly; the first paragraph is the thesis.
  3. Clear articulation; one idea per sentence.
  4. At least two Mermaid diagrams per document.
  5. Good visual assets: tables, trees, diagrams.
  6. Generated HTML with consistent navigation.
  7. Cross-references between documents.
  8. Source paths and line numbers for implementation claims.
  9. At least one Aha moment per document.
  10. Index plus prev/next navigation on every page.

Additional rules from CLAUDE.md:

  • Write in ASD-STE100 Simplified Technical English.
  • Spell out every abbreviation at the point of first use.
  • Never invent a name, number, or flow. Verify against the source.

8. Expected Outcome

After reading, an engineer can:

  • Explain how an agent entity becomes a durable stream, byte for byte.
  • State where the stream bytes and metadata live in each deployment.
  • Trace a wake from the Durable Streams server to an agent handler and back.
  • Describe the entity event schema and the materialization into TanStack DB.
  • Explain the Durable Streams protocol and implement a compatible client.
  • Maintain or extend every package in both repositories.
