Glossary

This glossary defines the key terms and abbreviations used in this exploration. Terms are grouped by area. Each entry names the source file when the term is a code identifier.

Aha: the vocabulary follows the architecture. Most terms describe a position in a log or a rule for delivering the next position. Few terms describe business data. That imbalance is the design: the system stores events, and the meaning of an event belongs to the handler.

Core concepts

TermDefinition
AgentA long-lived software worker that reads events, calls a model, uses tools, and writes events. In this system, an agent is an entity with a handler.
EntityThe unit of agent identity. An entity has a type, an identifier, a status, one main stream, and a set of permissions. Source: packages/agents-server/src/entity-manager.ts.
Entity typeA named template. It declares the state collections, the inbox schemas, the slash commands, the creation schema, and the default dispatch policy.
HandlerThe async function that runs on each wake. It receives a handler context and the wake description.
Durable streamAn append-only byte sequence, reachable by HTTP at a URL, with ordered offsets and live reads.
WakeA request to run a handler because something changed.
MaterializationThe process of reading stream events and applying them to typed in-memory collections.
ProjectionA derived view of events. The collections are a projection. The /_entities/ streams are another projection.

Stream terms

TermDefinition
OffsetAn opaque, lexicographically sortable token that names a position in a stream.
Tail offsetThe position immediately after the last byte. New appends write here.
Sentinel offsetOne of two special values: -1 for the beginning, now for the current tail.
Catch-up readA read from an offset to the current tail that then stops.
Long-poll readA read that waits for new data until data arrives or a timeout expires.
Server-Sent Events (SSE)A one-way HTTP streaming mode. The server pushes events on an open response.
JSON modeThe special behavior of streams created with Content-Type: application/json. Message boundaries are preserved, arrays flatten one level, and reads return arrays.
Content typeThe Multipurpose Internet Mail Extensions (MIME) type set at stream creation.
Closed streamA stream in the terminal state. It rejects appends.
Soft-deleted streamA deleted stream whose data remains for live forks. Its own URL returns 410 Gone.
ForkA stream that inherits a prefix from a source stream without copying bytes.
Fork offsetThe divergence point between a source stream and its fork.
Sub-offsetA position inside one message, used as the fork point when the split must occur inside a message: an element count in JSON mode, a byte count in binary mode.
Reference countThe number of forks that point at a source stream.
Time to live (TTL)An optional expiry rule for a stream.
SegmentOne append-only log file that holds stream bytes.
LMDBLightning Memory-Mapped Database. The embedded key-value store that holds stream metadata.
Base64urlA URL-safe Base64 encoding. Used for cron stream paths and signatures.

Producer terms

TermDefinition
Idempotent producerA writer that supplies a stable identifier, an epoch, and a sequence number so the server can drop duplicate appends.
Producer identifierThe stable writer name. The runtime uses entity-${entityUrl}.
Producer epochA generation number. A new epoch tells the server that the writer restarted.
Producer sequenceA per-epoch counter.
Stream-SeqA per-writer ordering header. Values compare lexicographically.

Delivery terms

TermDefinition
SubscriptionA server-side rule that watches streams and delivers new data to a target.
Webhook subscriptionA subscription that sends an HTTP POST to a URL.
Pull-wake subscriptionA subscription that writes a wake record into a wake stream for a runner to claim.
Wake recordOne JSON message in a wake stream, with the subscription identifier, the changed stream, the generation, and a timestamp.
Wake streamThe stream that receives pull-wake records for one runner.
ClaimThe act of taking ownership of a wake. A claim has a lease.
AckThe act of marking a wake complete.
ReleaseThe act of returning a claimed wake so another worker can take it.
LeaseA time limit on a claim. An expired lease allows another worker to reclaim the wake.
Wake registryThe agents-server component that holds wake conditions and matches events to them. Source: packages/agents-server/src/wake-registry.ts.
ManifestA stream event that declares a side effect, such as a future send, a shared state link, or an entity source.
Forward routeThe agents-server path /_electric/subscription-webhooks/:subscriptionId that receives stream notifications and forwards them to the real target.
Loopback rewriteThe replacement of 127.0.0.1 with host.docker.internal so a container can reach the host.

Control-plane terms

TermDefinition
Control planeThe HTTP and PostgreSQL layer that manages entity types, entities, permissions, runners, and schedules.
Data planeThe Durable Streams layer that stores and delivers event bytes.
Execution planeThe runtime layer that materializes streams and runs handlers.
Entity managerThe agents-server class that performs spawn, send, fork, signal, kill, and related operations.
Entity registryThe PostgreSQL-backed store for entity types and entity records. Source: packages/agents-server/src/entity-registry.ts.
Entity projectorThe component that writes entity and tag records into /_entities/ streams. Source: packages/agents-server/src/entity-projector.ts.
RunnerA process or host that claims pull wakes and runs handlers.
SandboxAn isolated execution environment for tools.
BridgeA connector between an entity stream and an external source or destination.
PostgreSQL sync (pg-sync)A bridge that replicates entity events into PostgreSQL.
SchedulerThe component that runs delayed sends and cron ticks. Source: packages/agents-server/src/scheduler.ts.
Delayed sendA scheduled message append.
Cron tickA scheduled event on a cron stream. Cron schedules are declared by rows in wake_registrations, not by a manifest.
Cron streamA stream whose path encodes a cron expression and timezone: /_cron/.
Shared stateA stream that several entities can read and write: /_electric/shared-state/.

Security terms

TermDefinition
PrincipalAn identity with a kind, an identifier, a key, and a URL.
TenantAn isolated workspace. The identifier selects the PostgreSQL rows and appears in their composite keys. The default routing adapter does not add it to stream paths.
Permission grantA record that allows a subject to perform one verb on one resource.
PropagationWhether a grant applies to the entity alone or to its descendants.
Authorization hookA caller-supplied function that makes the final access decision.
Per-entity write tokenA secret stored as entities.write_token and returned in the x-write-token response header at spawn. One entity.
Per-wake write tokenA secret minted at the wake claim callback. It authorizes appends to the entity stream for one wake.
Pull-wake lease claim tokenA secret returned by a runner claim. It is the bearer token for acknowledge and release.
JSON Web Key Set (JWKS)A JSON document that publishes public signing keys. Served at /__ds/jwks.json.
Ed25519An elliptic-curve signature algorithm. Used for webhook signatures.
Webhook signatureA header with the form t=,kid=,ed25519=.
Replay attackResending a captured valid request. A timestamp tolerance window prevents it.

Electric Sync terms

TermDefinition
Electric SyncThe Elixir service that reads the PostgreSQL replication stream and serves Shapes.
ShapeA read-only, filtered subset of a PostgreSQL table served over HTTP.
Shape streamA client object that follows a Shape and yields change messages.
Shape logThe stored sequence of changes for a Shape.
Logical replicationThe PostgreSQL mechanism that publishes row changes as a stream.
Replica fullA Shape mode that sends the full current state, not only changes.

Client and tooling terms

TermDefinition
TanStack DBA reactive client-side database library. The runtime uses its collection model.
CollectionA typed table inside the materialized stream database.
ActionA generated write function such as _insert, _update, or _delete.
Model Context Protocol (MCP)An open protocol for exposing tools and resources to language models.
AI Software Development Kit (AI SDK)A TypeScript toolkit for model calls and streaming.
Command-line interface (CLI)A text interface. The electric-ax package is the CLI.
Conflict-free Replicated Data Type (CRDT)A data type that merges concurrent edits without conflict.
YjsA CRDT library for shared editing.
Single-page application (SPA)A browser application that updates without full page reloads.
ElectronA framework for desktop applications built with web technology.
Content Delivery Network (CDN)A distributed cache network.

Repository terms

TermDefinition
PackageOne workspace unit with its own package.json or mix.exs. Each package in this exploration has its own markdown/ directory.
WorkspaceA monorepo managed by pnpm.
ChangesetA release note file used by the Changesets tool.
Conformance testA test suite that checks whether an implementation follows a protocol.
Grandfather reviewA documentation review that checks names, numbers, flows, and coverage against the source.
Fresh-reader reviewA documentation review by an agent with no prior context and no tool use.

The event type selects the collection. The materializer reads an event, dispatches on its type, and writes one row into the matching collection. The handler then reads the collection, not the raw stream.

flowchart LR E["Stream event<br/>type + payload"] --> D{"type"} D -->|inbox| C1["inbox collection"] D -->|run| C2["runs collection"] D -->|text, text_delta| C3["texts, textDeltas"] D -->|tool_call| C4["toolCalls"] D -->|wake| C5["wakes"] D -->|manifest| C6["manifests"] C1 --> H["Handler context"] C2 --> H C3 --> H C4 --> H C5 --> H C6 --> H

This is why the glossary lists each event type beside its collection. The pair is the contract between the storage format and the handler.
