Glossary

This file defines the terms that the other celld documents use as terms of art. A term of art is a word that this exploration uses with a precise meaning. Some words carry more than one precise sense, such as lease, fence, generation, session, and state. The section Terms that look alike separates those senses. Ordinary English words keep their usual meaning. The definitions use Simplified Technical English (STE) from the AeroSpace and Defence (ASD) association: the ASD Simplified Technical English, issue 100 (ASD-STE100) standard. Read the definition, then follow the Read more link when you need the full mechanism that belongs to another document.

Sources: the whole celld repository at commit 8702f6d186c77698dbfb30cf29e3b1922a88f008, version 0.6.3. The checkout used for this exploration is /Users/darkvoid/GitSources/src.s3/celld. Each code snippet names its file and line.

The map shows the main path only. A container runs on the node that owns the cell which starts it, so the cell supervises the container. Static assets are served from the deployment. R2 reads and writes the bucket directly. A Dynamic Worker runs in an isolate pool and does not become a cell. The service edge names the services that use a cell; R2 and a Dynamic Worker do not.

Base terms

TermExpansionDefinitionRead more
celld—The open-source server program that implements the Cloudflare Durable Objects interface, at version 0.6.3. It is the subject of this exploration. The name is never an abbreviation.Overview
Application—The set of scripts, assets, and bindings that one fleet serves. A fleet runs one application, in one stored deployment at a time.Overview
Two promises—The two guarantees that celld makes. First, exactly one node serves a cell at a time. Second, celld does not acknowledge a write until the write survives the loss of the node that acknowledged it.Overview
Object—One named thing. A Durable Object is a programming interface with private storage. A bucket object is one stored file. A JavaScript object is one value in a heap.Terms that look alike
Object storage—A store that keeps named byte objects. A read can take a whole object or a byte range. A write replaces the whole object; a conditional write applies only if the object is absent or unchanged. The bucket is object storage.Cell storage and durability
Work—One unit that a cell must process, such as an incoming request, an alarm, a queue message, or a WebSocket message. An event is one delivery of work to the runtime.Durable Objects
Wake—The action that makes a cell resident. The owning node wakes a dormant cell; another node wakes a cell after it acquires the ownership record.Durable Objects
Phase—The lifecycle position of a cell: resident, dormant, or inactive. A phase tells whether the cell has a runtime and an owner.Durable Objects
State—A stored value in a record or a promise. A Resonate promise state is pending, resolved, or rejected. Do not confuse a stored state with a cell phase.Terms that look alike
Bucket—The object storage that every node shares. It holds deployments, cell state, ownership records, node leases, the fleet secret, wake entries, and R2 objects. In fleet mode a follower node also keeps a local copy of each acknowledged segment, and a takeover can recover that copy; the owner still uploads the segment to the bucket afterwards.Cell storage and durability
Bucket prefix—The leading part of an object key that belongs to one cell. For a cell the prefix is cells//, where is the Class:ID scope. A node does not have one prefix: it writes the record nodes/.json and the prefix log///, where is the process generation of the node session. The prefix names the owner, and that owner writes inside it.Cell storage and durability
Object key—The full path of one object in the bucket, such as cells/Class:ID/own.json.Cell storage and durability
Record—One JavaScript Object Notation (JSON) object that celld reads or writes in the bucket.Cell storage and durability
Authority—The right to act for a cell or a node. A bucket record grants authority. An expiry ends it, and a record that names a different owner or a different epoch takes it away.Ownership, failure, and rebalancing
Tenant—One logical data group inside the application, such as one document, one chat room, or one agent. A tenant is not a separate security boundary, and this sense is not a storage partition.Security and tenancy
Tenancy unit—The object that groups tenants for trust. In celld the fleet is the tenancy unit.Security and tenancy
Account—A billing and identity record on a hosted platform. celld has no account object.Security and tenancy
Cloudflare—The company that operates the hosted Cloudflare Workers platform.Limitations and compatibility
Cloudflare Workers—The hosted platform that Cloudflare operates, and whose interface and behavior celld implements. celld copies a subset of that platform.Limitations and compatibility

Platform and deployment

TermExpansionDefinitionRead more
Fleet—The set of nodes that share one bucket, one fleet secret, and one deployment. One fleet runs one application.Security and tenancy
Node—One running celld process on one machine. A node owns some cells and forwards requests for the rest.System architecture
Operator—The person or process that runs the nodes and holds the bucket credentials.Deployment and operations
Deployment—One stored version of the application: the scripts, static assets, and bindings of one stored build. A deployment identity names that stored version. A fleet serves the deployment that deploy/current.json names.Deployment and operations
Active deployment—The deployment that deploy/current.json names now. That object is the deployment pointer. A node checks the pointer on a slow periodic interval; POST /reload or a notification from the managed control plane makes it read the pointer at once.Deployment and operations
Script—One uploaded Worker program with its own name, modules, assets, and bindings. One deployment can hold more than one script.The Worker runtime
Worker—The application code that the V8 engine runs for one script. It handles events, which are the inputs that the runtime delivers, and calls bindings.The Worker runtime
Binding—An object in the Worker env argument, such as env.DB, that grants the operations of one service. A binding grants those operations, not the node's other authority, and it does not grant another script's bindings.The services
env—The second argument of a Worker handler function. It holds the bindings, which expose services, and the configuration values of the script.The Worker runtime
Service—One platform feature that a binding exposes: Key-Value (KV), Queues, D1, R2, Workflows, Cron Triggers, Dynamic Workers, or containers. Static assets have no binding; the node serves them from the deployment.The services
Deployment generation—A loaded build of a deployment inside a node. It keeps the isolate pools that serve that build; an isolate is one V8 execution context. A new deployment creates a new generation.System architecture
Control plane—A separate hosted service, controlled by Cloudflare, that deploys code and tracks node presence. It does not take part in the path that acknowledges a write. A standalone node runs without it.System architecture
Placement—The assignment of cells to nodes. Nodes make it as they claim ownership records, and the planner moves cells to balance the fleet; the control plane does not make it.Ownership, failure, and rebalancing
Standalone mode—The operating mode in which a node reads the deployment from the bucket and serves it without the managed control plane.Deployment and operations
Managed mode—The operating mode in which a node runs under the hosted control plane. Set CELLD_CLOUD=1.Deployment and operations
Peer—Another node in the same fleet.Security and tenancy
Fleet secret—The 32-byte key in fleet/peer-auth.json. It authenticates peer control requests with a Keyed-Hash Message Authentication Code (HMAC).Security and tenancy

The peer constants set the protocol version and the limits that stop a replay. DOMAIN separates this protocol from every other use of the key:

// crates/celld/peer_auth.rs:16-29
pub const PROTOCOL_VERSION: u16 = 5;
pub const PROTOCOL_VERSION_TEXT: &str = "5";
const SECRET_KEY: &str = "fleet/peer-auth.json";
const SECRET_VERSION: u8 = 1;
const DOMAIN: &str = "cells-peer-request-v1";
const CLOCK_WINDOW_MS: u64 = 30_000;
const REPLAY_RETENTION_MS: u64 = CLOCK_WINDOW_MS * 2;
const MAX_REPLAY_ENTRIES: usize = 1_000_000;

The clock window accepts a request timestamp within 30 seconds of the local clock. The retention is twice the window, so a nonce stays in the replay cache for the full time in which a copy could arrive. The cache holds at most one million nonces; when it is full, the node rejects new peer requests until entries expire.

Identity and placement

TermExpansionDefinitionRead more
Durable Object (DO)—The Cloudflare programming interface for a named object with private SQLite storage (SQLite is the embedded relational database that each cell uses). A Durable Object is an instance of a class that a Worker exports. Calls reach it as a fetch request or a Remote Procedure Call (RPC), and the application obtains it from a binding to a Durable Object namespace. One node owns the object at a time.Durable Objects
Cell—The durable unit behind one Durable Object: one root SQLite database, one bucket prefix cells//, and one ownership epoch counter. A facet adds a child database that the same cell owns and restores. A cell continues to exist when no node runs it.Cell storage and durability
Cell scope—The Class:ID string that names one cell, for example __D1Database:3f0c.... The class comes first, and ID is 64 hexadecimal digits derived from a namespace key and a name. A namespace key is a byte string that the namespace fixes. For an application class, the namespace key contains the script name, so the same class name in two scripts gives two identifiers.Durable Objects
Class—The first part of a cell scope. It names the implementation that handles the object.Durable Objects
Durable Object class—A JavaScript class that a Worker exports and that the runtime instantiates for a cell.Durable Objects
Reserved class—A class that the runtime registers in every isolate (one V8 execution context), such as __D1Database. A deployment configuration that names one in durable_objects or migrations is refused. The runtime also forms the workflow class __Workflow.
