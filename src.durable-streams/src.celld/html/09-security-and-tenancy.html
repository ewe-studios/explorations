Security and tenancy

celld is the node server that runs the deployed Worker. It has one security model, and it is narrow. One fleet (a set of celld nodes that share one bucket, one deployment, and one fleet secret) runs one application. The operator trusts the application code, the nodes, and the people who hold the credentials for the bucket, the object store that holds all fleet state. The model puts the internal listener behind a private network and the public listener behind a proxy that authenticates users. It does not isolate hostile tenants from each other. The public listener itself authenticates no one.

This document states that model, then follows each boundary: the two listeners, the peer signature, the operator Application Programming Interface (API), the cell name validator, the request body limit, and the isolation of a Dynamic Worker (a Worker that the application loads at run time) and a container.

Sources: docs/security.md, docs/limitations.md, docs/guarantees.md, crates/celld/peer_auth.rs, crates/logic/cell.rs, crates/celld/deploy.rs, crates/celld/actor.rs, crates/celld/container.rs, and crates/celld/js/harness.js at commit 8702f6d186c77698dbfb30cf29e3b1922a88f008, version 0.6.3.

The trust model

The security page states the rule directly: celld version 0.6.3 is a beta release, and it is not safe for hostile multi-tenant use. One fleet runs one application. The application code, the fleet nodes, and the operators are trusted (docs/security.md).

That rule has two consequences. First, a cell is not a security boundary between tenants. The ownership epoch fences storage consistency, so a node that lost its lease cannot change the current state. It does not stop one tenant's code from consuming shared node resources or from using the bindings that the deployment gave it. A binding is an object in the Worker env, such as env.DB; it grants exactly the operations of that service and nothing more.

Second, the fleet has two places where authority crosses its edge: the trusted private network in front of the internal listener, and the object storage credentials. The bucket holds the deployments, the cell state, the ownership and node leases (nodes/.json), the per-cell ownership record (cells//own.json), and the fleet secret. A holder of the bucket credentials controls the fleet (docs/security.md).

The bucket credential is the root of authority because the bucket is the only shared state. A holder can do four things:

  1. Read fleet/peer-auth.json, so it can sign peer requests.
  2. Replace deploy/current.json, so it can serve new code.
  3. Change cells//own.json, so it can move ownership.
  4. Read every cell's state.

A read-only credential is weaker, but it is still dangerous. It can read the fleet secret, so it can sign peer requests from any machine that reaches the internal listener. It can also read every cell's state. Only a write credential can replace code or move ownership. Grant write access only to the operator process.

No account database exists alongside the bucket, so no second place exists to revoke a disclosed credential. Rotation of the bucket credential is the revocation procedure. celld encrypts nothing in the bucket; confidentiality depends on the transport secrecy and the encryption at rest that the object store provides.

Two fencing mechanisms work together. The node lease is a record in the bucket with an expiry time, and the owner renews it while the node is alive. The ownership epoch is a counter that grows at each activation. The replication path writes each cell under a key prefix that names its epoch, cells//ltx/e/. A stale owner can still write, but only into a superseded prefix that no restore selects. After each write is durable in the bucket, celld reads cells//own.json and acknowledges only if the record still names this node at this epoch. A node that lost its lease therefore stops acknowledging, and the next activation fences it out with a higher epoch. Ownership, failure, and rebalancing gives the full protocol.

The public listener does not authenticate anyone. celld serves the Worker there and leaves authentication to a proxy or to the application. The "boundary" on that side is the proxy, not celld.

Separate the listeners

celld opens two HTTP listeners, and it terminates TLS on neither:

ListenerServesRequired protection
--listenThe deployed Worker.Terminate TLS and authenticate users in a proxy or in the application.
--internal-listenThe peer protocol and the operator API.Restrict access to trusted operators and fleet nodes. Never expose it to the public internet.

Each listener has one flag and one environment variable: --listen or CELLD_ADDR for the public listener, and --internal-listen or CELLD_INTERNAL_ADDR for the internal one. An explicit flag wins over the environment variable. Standalone mode starts a node from the operator's flags, and the operator supplies the bucket and its credentials. Managed mode (CELLD_CLOUD=1 or --control-plane) enrolls the node with the hosted control plane at celld.dev. That control plane issues one bucket and its storage credentials to the fleet, and it supplies the active deployment. In standalone mode the public listener defaults to 127.0.0.1:8080. In managed mode it tries the loopback ports 8080 to 8099 in order and uses the first free one (crates/celld/main/cli.rs:112, :141-142).

The internal listener defaults to 127.0.0.1:0. Port 0 tells the operating system to choose a free port; celld reads the assigned port after the bind. Peers cannot guess that port, so a multi-node fleet needs an explicit --internal-listen and an --advertise value. celld rejects --advertise without an explicit internal listener because the default port changes at each start. It also rejects a non-loopback public --listen without an explicit internal listener, because it never reuses the public socket for peer traffic.

--advertise accepts IP:PORT or HOST:PORT. The hostname is not resolved at startup, because reachability depends on each peer's network. celld rejects a public Internet Protocol (IP) advertise address unless the operator also passes --unsafe-public-advertise, because the operator API has no caller authentication and peer HTTP has no built-in encryption. Use an encrypted overlay, such as WireGuard or Tailscale, when the private network does not provide confidentiality. celld cannot verify a hostname or a translated port, so the operator must route the advertised address to the internal listener.

The public listener reserves only /.well-known/celld/health. That path returns 200 with {"ok":true} only when the node is not draining, the fleet is ready, and the node reports healthy; otherwise it returns 503. "Draining" means that a shutdown has started, so the node refuses new public work. "Fleet ready" means that the one-shot readiness gate is open: no donor is mid-handoff and every live peer publishes successor capacity. "Healthy" means that the node is not fenced, is not resuming a clean reload, and holds a fresh node lease. The Worker owns every other public path, including /health.

The two listeners have separate routers, so no path belongs to both. The internal listener returns 404 for an unknown path, so an operator request cannot become an application request. The reverse is also true for the routers: a public request cannot enter an operator route through the public listener. The deployed Worker can still send its own request to the internal listener, as the isolation section explains.

A node finds its peers by listing the nodes/ prefix in the bucket (crates/celld/fleet.rs:518-528). For each name, it reads nodes/.json and decodes the lease (crates/celld/fleet.rs:483-514). The lease holds the address that the peer advertised with --advertise, its peer protocol version, and its lease generation. An expired lease, or one with an empty address, is not a live peer. A node sends its peer requests to that address over plain HTTP. That listing is why the bucket, not a separate discovery service, is the membership record.

Peer authentication

Every route under /peer/ and /runtime/ carries a signature. This includes the /peer/tunnel establishment request. The cell fetch and RPC calls that then travel inside the tunnel are not signed again; the section below states the limit of that choice. The fleet secret is one 32-byte key in the bucket:

// crates/celld/peer_auth.rs:16-17, 20-24, 29
pub const PROTOCOL_VERSION: u16 = 5;
pub const PROTOCOL_VERSION_TEXT: &str = "5";
const SECRET_KEY: &str = "fleet/peer-auth.json";
const SECRET_VERSION: u8 = 1;
const DOMAIN: &str = "cells-peer-request-v1";
const CLOCK_WINDOW_MS: u64 = 30_000;
const REPLAY_RETENTION_MS: u64 = CLOCK_WINDOW_MS * 2;
const MAX_REPLAY_ENTRIES: usize = 1_000_000;

The first node creates the key with a conditional write. put_cas is a compare-and-swap: it writes only if the object still matches the expected value. The expected value None means "the object must not exist". A second node that races the first one loses the write and reads the winner's key:

// crates/celld/peer_auth.rs:275-300 (abridged)
pub async fn load_or_create(bucket: &Bucket) -> anyhow::Result<[u8; 32]> {
    if let Some(key) = load(bucket).await? {
        return Ok(key);
    }
    let mut key = [0_u8; 32];
    rand::rngs::OsRng.fill_bytes(&mut key);
    let stored = StoredSecret {
        version: SECRET_VERSION,
        key: encode_hex(&key),
    };
    match bucket
        .put_cas(SECRET_KEY, serde_json::to_vec(&stored)?, None)
        .await
    {
        Ok(Some(_)) => Ok(key),
        Ok(None) => load(bucket),
        ...

The signature covers a canonical string. A canonical string is the fixed text form that both nodes build from the same request, so any difference in framing produces a different signature. A running node reads the key once at startup with load_or_create, which creates the key when the fleet has none, so it keeps that key for its whole life. An operator client reads the same key with load_existing. celld has no fleet-secret rotation command. To replace the key, stop every node, overwrite fleet/peer-auth.json with a new key, and start the fleet. A mixed fleet cannot work: a node with the old key cannot verify a request that a node with the new key signed. This string names a fixed domain tag (cells-peer-request-v1), the protocol version, the method, the path and query, the body hash, the source node, the target node, the timestamp, and the nonce, in that order, with one newline between fields:

// crates/celld/peer_auth.rs:254-273 (abridged)
fn mac(&self, request: &CanonicalRequest<'_>) -> Hmac<Sha256> {
    let canonical = format!(
        "{DOMAIN}\n{PROTOCOL_VERSION}\n{method}\n{path_and_query}\n{body_hash}\n\
         {source}\n{target}\n{timestamp}\n{nonce}"
    );
    let mut mac =
        <Hmac<Sha256> as Mac>::new_from_slice(&self.key).expect("HMAC accepts a 32-byte key");
    mac.update(canonical.as_bytes());
    mac
}

The target node is in the signed string, so a request for one node cannot be replayed against another. The body hash binds the body to the signature. The timestamp must be inside the 30-second clock window, so the nodes must keep their clocks synchronized to well under 30 seconds; run a time service such as the Network Time Protocol (NTP) on every node. The nonce must not appear twice inside that window. The cache keeps each entry for twice the window, which is 60 seconds, so a nonce cannot expire while its signature is still acceptable.

The replay cache is in memory in one process. A restart clears it, so a captured request can be replayed after a restart until its timestamp leaves the 30-second window. The window bounds that exposure.

The request carries seven headers:

HeaderValuePurpose
x-cells-peer-version"5"The protocol version.
x-cells-peer-sourceThe source node name.Names the sender.
x-cells-peer-targetThe target node name.Names the receiver.
x-cells-peer-timestampMilliseconds since the Unix epoch.Sets the clock window.
x-cells-peer-nonce16 random bytes, hex-encoded.Makes each request unique.
x-cells-peer-body-sha256The SHA-256 hash of the body, hex-encoded.Binds the body.
x-cells-peer-signature32 HMAC bytes, hex-encoded.The signature.

The receiver checks the fields in a fixed order, and it stops at the first failure (crates/celld/peer_auth.rs:180-249):

  1. The version header must equal "5". A missing header returns 401, and any

other value returns 426.

  1. The source and target names must pass validate_node_name. A bad name

returns 401.

  1. The timestamp must parse and fall inside the 30-second window. A bad value

returns 401.

  1. The nonce must decode to 16 bytes. A bad value returns 401.
  2. The body hash header must equal the SHA-256 hash of the received body. A

mismatch returns 401.

  1. The signature must verify against the canonical string. A bad signature

returns 401.

  1. The target must equal the node's own name. A mismatch returns 409.
  2. The nonce must be absent from the replay cache. A hit returns 409. A full

cache returns 503. A pass inserts the nonce.

Step 7 compares the target header to the receiving node's own name. The 409 message calls that name a node session.

The check runs in this order for a reason. Every cheap test runs before the expensive hash, and the replay cache is consulted only after the signature is proven. An attacker cannot fill the cache with unsigned requests.

validate_node_name accepts 1 to 128 bytes, and each byte must be an ASCII letter, a number, a dot, a dash, or an underscore (crates/celld/machine.rs:12-22). The same rule applies to a storage key, a local path, and a peer message, so one bad name cannot become a path escape.

The response is not signed. The receiver sends x-cells-peer-version, and the sender checks that one header with validate_response (crates/celld/peer_auth.rs:324-336). A missing header, or a value other than "5", fails the call with an error, and the caller does not use the response body. The fleet trusts the private network for response integrity. A reply that an attacker changes inside an open tunnel is not detected.

The verifier maps each failure to a status:

// crates/celld/peer_auth.rs:67-88 (abridged)
pub enum VerifyError {
    Unauthorized,
    WrongTarget,
    IncompatibleVersion,
    Replay,
    ReplayCapacity,
}

impl VerifyError {
    pub fn status(&self) -> axum::http::StatusCode {
        match self {
            Self::Unauthorized => axum::http::StatusCode::UNAUTHORIZED,
            Self::WrongTarget => axum::http::StatusCode::CONFLICT,
            Self::IncompatibleVersion => axum::http::StatusCode::UPGRADE_REQUIRED,
            Self::Replay => axum::http::StatusCode::CONFLICT,
            Self::ReplayCapacity => axum::http::StatusCode::SERVICE_UNAVAILABLE,
        }
    }
}

The replay cache holds at most one million entries. A full cache refuses new requests with 503, because the node cannot prove that a new request is not a replay.

The signature authenticates the start of a tunnel. It does not sign every call inside the tunnel, and it does not encrypt any byte. The private network therefore remains necessary. A node that reaches the internal listener can read and change traffic after the tunnel is open.

The operator API

The operator API is an alpha interface, and a release can change its paths or response formats. These routes do not authenticate the caller. The private network is their only access control. The one exception is /runtime/, which requires the fleet HMAC because it can carry application data:

  • /state reports node state.
  • /cell/ resolves or activates a cell. Activation starts the cell on

the receiving node when the cell is not resident there.

  • /evict/ tries to evict a resident cell and reports the result.

"Resident" means that the cell is in memory on this node. An active cell runs code, an idle cell waits for work and can leave memory after a timer, and a hibernated cell keeps its WebSocket clients on the node while its code does not run.

  • /do/ sends a direct request to an ordinary Durable Object. is a

Durable Object identifier, and celld derives the scope from the class and the identifier.

  • POST /shutdown starts a graceful ownership handoff. The node stops

accepting new work, moves its cells, and exits. handoff=preserve keeps the ownership records so a new process on the same node can adopt the cells.

An operator command such as celld d1 signs /runtime/ with the same seven-header scheme as a peer request. The command reads fleet/peer-auth.json with its bucket credentials, builds the canonical string, and sends the signature. The check proves possession of the fleet secret, not a separate user identity.

/do/ refuses every reserved runtime class, such as Cloudflare D1 (a managed SQLite database), Cloudflare Workflows (a durable workflow service), Key-Value (KV), and Cloudflare Queues (a message queue service), because their protocols can reach application data. An ordinary Durable Object handler is application code, and the public listener already serves that code without authentication. A reserved class instead exposes an operator protocol, such as arbitrary SQL for D1, on the cell fetch surface. The refusal is one predicate, not one test for each class:

// crates/celld/deploy.rs:148-164 (abridged)
pub fn reserved_class_of(scope: &str) -> Option<&str> {
    let (class, _) = scope.split_once(':')?;
    is_reserved_class(class).then_some(class)
}

pub fn is_reserved_scope(scope: &str) -> bool {
    reserved_class_of(scope).is_some()
}

A new reserved class is refused on the /do/ route with no new code. The source comment states why this shape matters: a forgotten refusal is not a missing feature, but an unauthenticated route onto a cell whose whole surface is an operator protocol. The HMAC-authenticated /runtime/ route serves those classes instead.

An accepted eviction waits for the operation to finish, and a refused one returns at once. Concurrent callers can join one eviction, so the success count does not equal the stop count. Inside the node, the success value is one of two variants. Evicted confirms a completed runtime stop. AlreadyAbsent confirms settled local absence with no pending transition. The HTTP route collapses both into 200 with {"ok":true}, so an HTTP caller cannot tell which one occurred. A caller that needs proof of a stop must use a stronger signal, such as /state or the ownership record. An error body has this form:

{"ok":false,"error":{"kind":"refused","reason":"cell_active"}}

A cell with active work returns 409 with reason: cell_active. A cell with another lifecycle transition returns 409 with cell_transitioning. A node that cannot accept the eviction returns 503 with node_unavailable. The full table is in docs/security.md. An error does not prove that the runtime is still resident.

Names are a security fence

A cell scope becomes a path component and an object-store key. The validator therefore accepts a small character set and a small length. The limit is MAX_CELL_SCOPE, which is 255 bytes (crates/logic/cell.rs:18). Where a scope arrives percent-encoded in a path, celld decodes it first (crates/celld/main.rs:2221-2227), so an encoded / becomes / and then fails the character set:

// crates/logic/cell.rs:43-51
pub fn valid_cell_scope(scope: &str) -> bool {
    !scope.is_empty()
        && scope.len() <= MAX_CELL_SCOPE
        && scope != "."
        && scope != ".."
        && scope
            .bytes()
            .all(|b| b.is_ascii_alphanumeric() || matches!(b, b'_' | b'-' | b'.' | b':' | b'$'))
}

The validator rejects . and .., so a scope cannot escape its directory. It rejects every other byte, including /, \, and @. The workflow class uses a dot to separate the script name, and the source explains the choice: the dot is inside this character set, while @ is not (crates/celld/deploy.rs:104-111).

A scope has the form Class:ID. The class is the text before the first colon, and the identifier is the text after it. /do/ accepts a full scope, or a bare identifier with no colon. A bare identifier takes the class from the deployment's default Durable Object class, and the route refuses the request when the deployment has no single default class (crates/celld/cell_runtime.rs:144-160). The composed Class:ID value is validated again, so a long class name cannot push the scope past MAX_CELL_SCOPE.

The check for a workflow class is one reading of the shape, so the separator cannot come to mean two things:

// crates/celld/deploy.rs:130-140
pub fn is_workflow_class(class: &str) -> bool {
    class
        .strip_prefix(WORKFLOW_CLASS)
        .is_some_and(|rest| rest.starts_with('.'))
}

pub fn is_reserved_class(class: &str) -> bool {
    RESERVED_CLASSES.contains(&class) || is_workflow_class(class)
}

The runtime supplies these class names, not the application. RESERVED_CLASSES holds __D1Database, __Workflow, __KvNamespace, and __Queue, and is_workflow_class adds every __Workflow.
