System architecture

A celld node is one process. It opens two Hypertext Transfer Protocol (HTTP) listeners, runs one serial actor loop, executes JavaScript in V8 isolates, keeps SQLite databases for the cells that it owns, and reads and writes one object store bucket. The process has no separate controller, scheduler, or database server. The bucket holds every fact that survives a restart. V8 is the JavaScript engine that celld embeds. A turn is one uninterrupted run of JavaScript in a V8 isolate.

Two words in that summary need care. The actor is a Rust asynchronous task: a future that the Tokio runtime schedules on a worker thread. Tokio is the Rust library that provides the asynchronous runtime. In this document, "task" alone always means that Rust future, never a task in the Resonate durable execution system; Resonate S3 and celld covers that system. "Serial" means the actor handles one input at a time, in arrival order, for the whole node; it does not mean that the node serves one request at a time, because V8 turns and bucket calls run outside the actor.

Every node can accept a request for any cell. Only the owner may execute that request, because only the owner holds the cell's JavaScript instance and SQLite database. A non-owner accepts the request and forwards it over a tunnel that is signed when it is established and carries unsigned HTTP inside. Ownership is one owner per cell, and the ownership record in the bucket says which node that is.

This document follows the node from start-up to a served request. It covers the listeners, the route decision, deployment adoption, and the background loops. The isolate internals are in the Worker runtime. Ownership and recovery are in ownership, failure, and rebalancing.

The words this document uses

WordMeaning
NodeOne celld process. A node has a name and one set of listeners.
FleetThe set of nodes that share one bucket. A node learns the fleet from the node leases in the bucket.
BucketOne object store bucket. It holds the deployment pointers, the ownership records, the cell logs, the snapshots, the node leases, the fleet capacity sample, the fleet secret, and the asset index, among other objects. The fleet capacity sample is one shared object in which nodes publish their load, so that placement decisions see the fleet. The fleet secret is the shared key that authenticates peer requests. A snapshot is a whole-database copy of a cell at one point, from which a restore can start without replaying every earlier segment. In this document, "object store" means a service that stores opaque objects under keys, such as Amazon Simple Storage Service (S3) or a compatible store.
WorkerThe deployed JavaScript application script. The Worker is the code that the public listener runs.
V8 isolateOne JavaScript engine heap. V8 is the JavaScript engine that celld embeds. An isolate is not bound to a thread.
CloudflareThe platform vendor that defines the Durable Objects programming model. celld implements a compatible subset of that model.
Durable Object (DO)The object model that the application programs against: one class, one stable identifier, one serial event stream, and durable storage.
ClassOne exported Durable Object class, such as Order. The class is the first part of a cell scope.
CellOne Durable Object instance. A cell is a runtime object; its name is the cell scope. A cell is resident when this node runs it, dormant when an owner still names this node but no runtime is loaded, and inactive when no node holds it.
Cell scopeThe string that names a cell, of the form :. It is also the storage key and the dispatch key. The dispatch key is the value that the dispatcher hashes to choose a cell and that the owning node uses to find the cell's runtime.
Resident cellA cell whose SQLite database and JavaScript instance are on this node.
ActivationThe operation that makes a cell resident, either at its first request or after an eviction or a move. An eviction unloads a resident cell from the memory of a node; an idle eviction keeps the ownership record and leaves the cell dormant, and a rebalancing eviction releases the record and leaves the cell inactive. A generation switch is not an activation and does not increase the epoch.
GenerationOne compiled deployment that a node can serve. A node has one current generation and may still drain the generation before it.
DeploymentOne version of a script and its bindings, stored under deploy/
