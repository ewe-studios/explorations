Deployment and operations

One celld process is a node. The nodes that share one bucket are a fleet, and each node serves cells. A cell is one Durable Object with a private SQLite database. The bucket is the object store that holds the fleet state.

A fleet has two control surfaces. The first surface turns a project into a deployment. A deployment is a set of immutable objects in the fleet bucket, and one small pointer object selects the current deployment. The second surface keeps a node healthy. A node reads the pointer, adopts the deployment, serves cells, and hands its cells to a peer when it stops.

This document follows one deployment from celld deploy to a serving node. It then covers the operator commands, the health paths, the autoscaler signals, the shutdown sequence, telemetry, and the test strategy.
