Durable objects

A Durable Object is one instance of a JavaScript class that the platform keeps for the application. Each instance has a name, one serial event stream, durable storage, and alarms. The application does not start the instance, stop it, or find out where it runs. It asks for a stub, and the platform sends each call to the one place that holds that instance.

Cloudflare defines this model. celld is this repository's implementation of it. The model is the contract; the implementation is the subject of this document. The document covers identity, the namespace, the lifecycle, the concurrency rules, the three storage surfaces, transactions, alarms, WebSocket hibernation, and facets. It also names the parts of the model that celld does not implement.

Sources: crates/celld/engine_api.rs, crates/celld/js.rs, crates/celld/js/harness.js, crates/logic/lib.rs, crates/logic/cell.rs, crates/logic/alarm.rs, crates/logic/wake.rs, and crates/logic/types.rs at commit 8702f6d186c77698dbfb30cf29e3b1922a88f008, version 0.6.3.

The model in one page

Promise of the modelHow celld keeps it
A name always reaches the same instanceThe name is hashed with the namespace key, so the identifier is a pure function of the namespace key and the name
Only one instance runs for one identityThe ownership record in the bucket names one node and one epoch (document 06)
One event at a timeThe input gate and the turn lane
Storage survives a crashEvery commit becomes an LTX segment, and the reply waits for a proof (document 05)
Alarms survive a crashThe alarm is a row in SQLite, and the wake entry is a bucket object
Code can sleep and wakeHibernation keeps the sockets and drops the memory
A class can own a child objectFacets, with the root plus three facet levels

The model does not promise low latency, a fixed location, or an upper bound on the number of objects. celld also makes no such promise.

Identity: a name becomes 64 hexadecimal digits

An application normally supplies a name, and the platform derives the identifier. It may also pass back an identifier that it received earlier, and the platform validates that identifier instead of deriving it. The derivation has two inputs: the namespace key and the name.

The namespace key contains the script name and the class name:

// crates/celld/engine_api.rs:545-550
pub(crate) fn namespace_key(script_name: &str, class_name: &str) -> String {
    match shared_namespace_key(class_name) {
        Some(shared) => shared.to_string(),
        None => format!("cells:v1:{}:{script_name}:{class_name}", script_name.len()),
    }
}
