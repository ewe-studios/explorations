02 -- Logic and Executor: the decision core and the effect shell

The workspace splits cleanly. crates/logic holds every decision. The executor in crates/celld holds every side effect. The binary comment states the division in two lines:

The executor owns time and the outside world. Its timer wheel coalesces every scheduled activity, from the node lease renewal to a cell alarm to an operation deadline:

// Source: crates/celld/actor.rs, lines 54-72
#[derive(Clone, Debug, PartialEq, Eq, PartialOrd, Ord)]
pub enum TimerSlot {
    NodeLeaseRenew,
    NodeLeaseFence,
    CellAlarm(String),
    /// Keyed by operation, deliberately. Every other timer here coalesces
    /// because only its newest arming matters; a deadline is the opposite --
    /// each watches a different outstanding operation, and a shared slot
    /// would let arming one silently cancel another, leaving every activation
    /// but the most recent with nothing watching it.
    OperationDeadline(OpId),
    /// Keyed by cell and generation for the same reason as the deadline
    /// above: a node parks many cells at once, and one slot per cell would
    /// let a later parking disarm an earlier one.
    QueuedActivation(String, u64),
    /// Keyed like `QueuedActivation`: one pending retry per cell, and a
    /// newer episode's arming supersedes a stale one.
    OwnerLogRecoveryRetry(String, u64),
}

The cycle

The cycle is small and strict. The executor delivers an event. The core mutates only its own state and returns effects. The executor performs the effects. When an effect is asynchronous, its completion becomes a new event with a version number, and the cycle repeats.

Why the split exists

Because the core has no side effects, the same on_event runs in production and in a deterministic simulator. The simulator feeds the same events and performs the same effects, so a test can replay an event log and assert the exact resulting state. That is what makes the durability guarantees in Document 03 testable as pure functions rather than as a network of live daemons.

%%{init: {"flowchart": {"htmlLabels": false}}}%% flowchart TD subgraph Prod["Production"] Actor["Actor"] end subgraph Sim["Simulator"] Sim["Deterministic simulator"] end Actor -->|"Event"| Core["on_event"] Sim -->|"Event"| Core Core -->|"Effect"| Actor Core -->|"Effect"| Sim

The crates/logic/Cargo.toml describes the constraint the same way: "Pure decision core: no async, I/O, clocks, randomness, locks, or dependencies." That constraint is what pays for the determinism.

The Aha Moment

Aha: the executor never mutates the cell. It only performs the effects the core returns. That is the whole reason the core can run in a simulator: with no side effects, replaying an event log yields the same state every time. A durability failure is reproducible as a function call, not a fleet incident.
