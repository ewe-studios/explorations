02 -- Wire traffic parsing: from bytes to facts

Every rule condition references facts the gateway extracted from the wire. This document follows the extraction for the three big protocol families: HTTPS, SQL, and the Kubernetes API.

The first gate is TLS (Transport Layer Security) Server Name Indication (SNI). Before the gateway knows which endpoint owns a connection, it peeks at the client's ClientHello and reads the SNI extension. This is a hand-rolled parser over the TLS record format, not a TLS library.

// Source: cmd/clawpatrol/main.go, lines 244-256
func peekSNI(c net.Conn) (string, []byte, error) {
	_ = c.SetReadDeadline(time.Now().Add(10 * time.Second))
	defer func() { _ = c.SetReadDeadline(time.Time{}) }()

	hdr := make([]byte, 5)
	if _, err := io.ReadFull(c, hdr); err != nil {
		return "", nil, err
	}
	if hdr[0] != 0x16 {
		return "", hdr, errors.New("not TLS")
	}
	recLen := int(hdr[3])<<8 | int(hdr[4])
	if recLen < 42 || recLen > 16384 {
		return "", hdr, errors.New("bad TLS record length")
	}

The handle function is the dispatcher for port 443. If SNI peek fails, it falls back to a direct-IP lookup for Kubernetes and HTTPS endpoints whose server field is an IP literal (kubectl dials by IP and never sends SNI). If the host is unknown, the configured unknown_host policy decides: deny, inspect under a synthetic endpoint, or pass through.

Once TLS is terminated, HTTP is easy: method, path, query, headers, and body become the http CEL (Common Expression Language) variable. SQL is harder. PostgreSQL and ClickHouse carry a binary protocol, and the SQL text arrives inside it. clawpatrol parses the SQL text with pgparser (the parser package of github.com/pgplex/pgparser — pgplex is the module org, pgparser the pure-Go port of PostgreSQL's grammar) and walks the abstract syntax tree (AST) to extract the verb, tables, and functions.

// Source: internal/config/plugins/endpoints/postgres_sql.go, lines 59-65
func parseSQL(sql string) (pgInfo, bool) {
	a := analyseAll(sql)
	if len(a) == 0 {
		return pgInfo{Statement: strings.TrimSpace(sql)}, false
	}
	return a[0].Outer, a[0].Unparseable
}

The AST walker maps PostgreSQL node types to lowercase verbs. A SELECT node becomes "select", an INSERT node becomes "insert", and so on.

// Source: internal/config/plugins/endpoints/postgres_sql.go, lines 165-176
func verbFromNode(stmt nodes.Node) string {
	switch n := stmt.(type) {
	case *nodes.SelectStmt:
		return "select"
	case *nodes.InsertStmt:
		return "insert"
	case *nodes.UpdateStmt:
		return "update"
	case *nodes.DeleteStmt:
		return "delete"
	case *nodes.MergeStmt:
		return "merge"

When the parser refuses an input, the gateway does not guess. parsePath returns nil for anything it cannot decompose, and the SQL parser returns an Unparseable flag. The downstream matcher turns both into a fail-closed deny, which 04-action-gating-approval.md covers.

The Aha Moment

Aha: the extraction layer is deliberately refusal-based. When a protocol parser cannot produce facts it trusts, it returns a sentinel meaning "I could not parse this," and the rule engine denies by default. This is the opposite of a best-effort parser that fills in a guess; a wrong-but-present fact would evaluate a rule to a clean false and let a deny rule miss.
