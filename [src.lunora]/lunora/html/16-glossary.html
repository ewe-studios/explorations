Glossary

Terms are in alphabetical order. Each entry points to the page that explains it.

TermMeaning
ActionA function that may call outside services. The code runs it on the shard without the gate and without a transaction (the architecture page says it runs in the Worker). See ShardDO
AdvisorA set of lints that warn about schema and runtime problems, such as hot_shard. See Testing and observability
AlarmThe single timer slot of a Durable Object. See Alarms
ArchiveChange log segments stored in R2 before rows are deleted. See Storage tiers
AttachmentA small value saved with a hibernating WebSocket, at most 16,384 bytes. Holds subscriptions
Bookmark (D1)A token for a position in a D1 session. Sent as the header x-d1-bookmark. See D1
Bookmark (PITR)A name for a moment in a Durable Object's 30-day history
CellThe word the celld daemon uses for a Durable Object instance
Change data capture (CDC)Recording each write in a log. In Lunora the table __cdc_log. See Change log
CodegenThe build step that writes _generated/* from the schema and function files
Commit cursorThe log high-watermark returned after a mutation (commitCursor). Used as a read-your-writes bookmark for replicas
commitOrderedA table option that adds the field _commitSeq
_commitSeqA per-shard commit counter stored inside each row's document
CompactionSetting doc to NULL for old log rows while keeping their keys
CoordinatorThe Worker code that fans a read out to many shards and merges answers. query-coordinator.ts
Default shardThe Durable Object named __root__
Dispatch claimAn in-memory mark that an action with a given id is running. See ShardDO
Drift gateA deploy check that compares the schema with a committed baseline file
Durable Object (DO)A single-threaded Cloudflare object with its own storage and optional alarm
EpochA random string in __cdc_meta. A change means the log timeline forked
Fan-outA read sent to every shard of a table
FloorThe oldest log position that can still be served. Key floor and payload floor
GateIn this document, blockConcurrencyWhile, wrapped by runSerialized
Global tableA table stored in D1 or Hyperdrive, set with .global()
HibernationA Durable Object with only idle WebSockets is removed from memory. Sockets stay open
HyperdriveCloudflare connection pooling for Postgres and MySQL
Idempotency rowA row in __idempotency keyed by identity and mutation id
JurisdictionA hard data residency rule (eu, fedramp, us) for Durable Objects
Location hintAn advisory region for creating a Durable Object
MemoA saved last result per subscription, used to skip duplicate pushes
MutationA function that writes. It runs inside the gate and a transaction
Outbox__schedule_outbox, the durable list of schedule calls not yet accepted
OwnerThe Durable Object that holds the true data for a shard, as opposed to a relay or replica
PayloadThe doc column of a log row
PITRPoint-in-time recovery. Native restore of a Durable Object's SQLite to a past bookmark
PokeA message that carries the membership diff for a shape. pokeStart, pokePart, pokeEnd
ponytail:A comment tag for a known limit the authors accept
QueryA read-only function. May be cached and subscribed
RegistryShardRegistryDO, the list of live shard keys per table
RelayA Durable Object named key::relay::n that re-broadcasts frames for a hot owner
ReplicaA Durable Object named key::replica::region that follows an owner's log for reads
ReactorA server-side subscription that runs a handler when its query result changes
RoleWhat a Durable Object does. It is fixed by its name
Root shardSee default shard
runSerializedThe ShardHost method that maps to blockConcurrencyWhile
SegmentOne R2 object of the change log archive
SeqThe AUTOINCREMENT position in __cdc_log
ShapeA named, parameterised partial replication of a table, with a predicate and optional columns
ShardOne Durable Object that owns one slice of state. Its name is the shard key
Shard keyThe string name of a shard, chosen by the caller
Sibling channelThe signed Durable Object to Durable Object control path at /_lunora/relay or /_lunora/replica
SinkA destination for observability events
TierWhere a table lives: root, sharded, global
Watermark (client)The last mutation sequence applied for a client, in __client_watermark
Watermark (archive)The last seq known to be in R2, in __cdc_archive
Wide eventOne span with many attributes, per request
waitUntilA platform call that keeps work alive after the response
WorkpoolA named pool in the scheduler with a concurrency limit
