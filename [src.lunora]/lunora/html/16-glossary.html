Glossary

Terms are in alphabetical order. Each entry points to the page that explains it.

TermMeaning
ActionA function that may call outside services. The code runs it on the shard without the gate and without a transaction (the architecture page says it runs in the Worker). See ShardDO
Actor modelA model in which an actor receives messages, runs in its own single thread, uses its own storage and sends messages. A Durable Object is an actor. See Cloudflare services
AdvisorA set of lints that warn about schema and runtime problems, such as hot_shard. See Testing and observability
AlarmThe single timer slot of a Durable Object. Cloudflare retries a failed handler up to 6 times. See Alarms and Cloudflare services
Analytics EngineCloudflare service for time-series data points. Writes are non-blocking and reads are sampled. See Cloudflare services
ArchiveChange log segments stored in R2 before rows are deleted. See Storage tiers
At-least-once deliveryA message may arrive more than once but is never lost. Queues and alarms work this way. A receiver must be idempotent. See Cloudflare services
AttachmentA small value saved with a hibernating WebSocket, at most 16,384 bytes. Holds subscriptions
BindingA named link from a Worker to a resource, such as D1, R2 or a Durable Object namespace. It appears on env. See Testing and deployment
blockConcurrencyWhileThe Durable Object call that holds back all other events until its callback ends. A throw inside resets the object, and a callback has a 30-second timeout. See Cloudflare services
Bookmark (D1)A string that names one point in the commit history of a D1 database. The Sessions application programming interface (API) returns it with getBookmark. The client sends it back as the header x-d1-bookmark, and a replica waits until it has reached that point before it answers. See D1
Bookmark (PITR)A string that names a moment in the 30-day history of one Durable Object. It is a different thing from a D1 bookmark. See Cloudflare services, section "Point-in-time recovery"
CellThe word the celld daemon uses for a Durable Object instance
Change data capture (CDC)Recording each write in a log. In Lunora the table __cdc_log. See Change log
CodegenThe build step that writes _generated/* from the schema and function files
Cold startThe first request after a Worker or object loads from nothing. In-memory state is empty. See Architecture
Commit cursorThe log high-watermark returned after a mutation (commitCursor). The client sends it back as x-lunora-min-seq, so that a replica read sees its own write. See Replication
commitOrderedA table option that adds the field _commitSeq
_commitSeqA per-shard commit counter stored inside each row's document
CompactionSetting doc to NULL for old log rows while keeping their keys
Compatibility dateA date in the Wrangler configuration that opts a Worker into runtime changes up to that date. See Testing and deployment
Consumer (log)Any reader of the change log: a subscriber, a replica, a connector or the archive. See Change log
CoordinatorThe Worker code that fans a read out to many shards and merges answers. query-coordinator.ts
Cron TriggerA schedule that runs the scheduled() handler of a Worker in Coordinated Universal Time (UTC). See Cloudflare services
Dead letter queueA queue that receives messages after the retry limit is reached. Without one, Cloudflare deletes the message. See Cloudflare services
Default shardThe Durable Object named __root__
DialectA small object that tells the shared Structured Query Language (SQL) store how one engine (SQLite, Postgres, MySQL) differs. See D1 and global tables
Dispatch claimAn in-memory mark that an action with a given id is running. See ShardDO
Drift gateA deploy check that compares the schema with a committed baseline file
Durable Object (DO)A single-threaded Cloudflare object with its own storage and optional alarm. Cloudflare runs at most one instance for each name. See Cloudflare services, section "Durable Objects from first principles"
EpochA random string in __cdc_meta. A change means the log timeline forked. See Change log
Eventual consistencyAfter writes stop, all copies will agree. Until then a read may return old data. Workers KV and D1 replicas without a bookmark behave this way. See Replication
Fan-outA read sent to every shard of a table. The Worker merges the answers. See Sharding design
first-primaryA D1 session constraint. The first query goes to the primary database instance. Lunora never uses it. See D1 and global tables
first-unconstrainedA D1 session constraint and the default. The first query may go to any instance. Lunora passes it when there is no bookmark. See D1 and global tables
FloorThe oldest log position that can still be served. Key floor and payload floor
Fork (after restore)A second history that starts when a restore moves a shard back in time and new writes follow. See Change log
GateIn this document, blockConcurrencyWhile, wrapped by runSerialized. See Cloudflare services
Global tableA table stored in D1 or Hyperdrive, set with .global(). See D1 and global tables
HibernationA Durable Object with only idle WebSockets is removed from memory. Sockets stay open. See Cloudflare services, section "WebSocket hibernation"
Hot shardA shard that gets far more traffic than its peers. One object can serve about 1,000 requests per second. See Sharding design
HyperdriveCloudflare service that pools connections to Postgres and MySQL and can cache read queries. See Cloudflare services
HysteresisTwo thresholds, one to switch on and a lower one to switch off, so that a system does not flip near one edge. See Replication
IdempotencyDoing an action twice has the same effect as doing it once. See Replication
Idempotency rowA row in __idempotency keyed by identity and mutation id. It makes a retried mutation return the saved result
Input gateA Cloudflare rule. While a Durable Object waits for its own storage, no new event is delivered to it. A fetch or a D1 call opens the gate. See Cloudflare services
IsolateA light sandbox inside the V8 engine in which a Worker runs. A process hosts thousands of them. See Cloudflare services
JurisdictionA hard data residency rule (eu, fedramp, us) for Durable Objects. See Cloudflare services
LeaseA claim with an expiry time. If the holder dies, the claim ends by itself. See Alarms
Location hintAn advisory region for creating a Durable Object. Only the first get() uses it. See Cloudflare services
MemoA saved last result per subscription, used to skip duplicate pushes
Monotonic readsA client never sees data go back in time. See Replication
MutationA function that writes. It runs inside the gate and a transaction
Namespace (Durable Object)The set of all Durable Objects of one class. See Cloudflare services
Optimistic concurrency control (OCC)Writers read a version and write only if the version is unchanged. See D1 and global tables
Outbox__schedule_outbox, the durable list of schedule calls not yet accepted. It is written in the same transaction as the data. See Alarms
Output gateA Cloudflare rule. While a storage write is pending, outgoing messages are held back until the write is saved. See Cloudflare services
OwnerThe Durable Object that holds the true data for a shard, as opposed to a relay or replica
PayloadThe doc column of a log row
PITRPoint-in-time recovery. Native restore of a Durable Object's SQLite to a past bookmark inside 30 days. See Cloudflare services
PokeA message that carries the membership diff for a shape. pokeStart, pokePart, pokeEnd
ponytail:A comment tag for a known limit the authors accept
Primary database instanceThe one D1 database copy that takes writes. Read replicas follow it. See D1 and global tables
QueryA read-only function. May be cached and subscribed
Queue (Cloudflare)A message buffer with producers and one consumer. Delivery is at least once and not ordered. See Cloudflare services
R2Cloudflare object storage with the S3 protocol, strong consistency and conditional writes. See Cloudflare services
ReactorA server-side subscription that runs a handler when its query result changes
Read replica (D1)A read-only copy of a D1 database in another region. It follows the primary with some lag. See D1 and global tables
Read-your-writesA client always sees its own earlier writes. See Replication
RegistryShardRegistryDO, the list of live shard keys per table
RelayA Durable Object named key::relay::n that re-broadcasts frames for a hot owner
ReplicaA Durable Object named key::replica::region that follows an owner's log for reads
Replication lagThe time between a commit on the primary and its arrival on a replica. See Replication
Re-seedTake a fresh full copy of the data and restart the cursor. See Change log
RoleWhat a Durable Object does. It is fixed by its name
Root shardThe default shard __root__. Tables with no shard modifier live here. See Sharding design
runSerializedThe ShardHost method that maps to blockConcurrencyWhile
SegmentOne R2 object of the change log archive
SeqThe AUTOINCREMENT position in __cdc_log
Sequential consistencyAll clients see operations in one agreed order, and each client sees its own in order. D1 gives this inside a session. See D1 and global tables
Service bindingA link that lets one Worker call another without a public uniform resource locator (URL). The binding is the permission. See Cloudflare services
Session (D1)A series of queries that D1 keeps sequentially consistent. Created with withSession. Lunora's session lasts for one request. See D1 and global tables
ShapeA named, parameterised partial replication of a table, with a predicate and optional columns
ShardOne Durable Object that owns one slice of state. Its name is the shard key
Shard keyThe string name of a shard, chosen by the caller. See Sharding design
Sibling channelThe signed Durable Object to Durable Object control path at /_lunora/relay or /_lunora/replica
SinkA destination for observability events
Strong consistencyA read returns the latest committed write. Inside one shard and in R2. See Replication
StubA client handle for a Durable Object. A call on it travels to the object. See Cloudflare services
SubrequestA request that a Worker sends to another service. Workers have a cap per request. See Cloudflare services
SweepOne cleanup pass over the change log. It archives old rows to R2 and then deletes them. See Storage tiers
Tag (WebSocket)A label on a hibernating WebSocket, used to find sockets. At most 10 tags of 256 characters. See Cloudflare services
TierWhere a table lives: root, sharded, global
VectorizeCloudflare vector database. Writes become visible later. See Cloudflare services
waitUntilA platform call that keeps work alive after the response
Watermark (archive)The last seq known to be in R2, in __cdc_archive. See Replication, section "Three kinds of watermark"
Watermark (client)The last mutation sequence applied for a client, in __client_watermark. See Replication, section "Three kinds of watermark"
Wide eventOne span with many attributes, per request
WitnessA fact from outside the SQLite file that proves a fork, such as a consumer cursor above the log. See Change log
Workers AICloudflare service that runs machine learning models. AI Gateway adds analytics and cost tracking. See Cloudflare services
Workers KVCloudflare global key-value store. Eventually consistent. Changes can take 60 seconds or more to show in other locations. See Cloudflare services
WorkflowA multi-step program. Cloudflare saves finished steps and does not repeat them after a failure. See Cloudflare services
WorkpoolA named pool in the scheduler with a concurrency limit
Write amplificationOne logical write that causes many physical writes. See Critical assessment
x-d1-bookmarkThe header that carries a D1 bookmark between the client, the Worker and the shard. See D1 and global tables
x-lunora-min-seqThe header that carries the commit cursor of the client's last write, for replica reads. See Replication
