TasteCode exploration: a server-owned workspace for coding agents

TasteCode is a local desktop workspace for Artificial Intelligence (AI) coding agents. It puts several engines in one application and keeps orchestration, project state, terminals, diffs, checkpoints, and history on the user's machine.

The product claim is direct.

# README.md:7
> A local desktop workspace for AI coding agents, with Design Mode built in.

The exploration has one thesis. TasteCode is interesting because it puts one local server in charge of state and wraps every agent engine in a typed protocol. The typing is not decoration. It decides where a credential lives, when a checkpoint is written, how a client recovers, and which design phase may run next.

The architecture rule states the shape.

# docs/ARCHITECTURE.md:11-12
**A local server owns all state and orchestration. Every client is a thin renderer over a
typed WebSocket protocol.**

The first mechanism is the server-owned state and typed protocol. The second mechanism is Design Mode. A brief becomes a sequence of ordered phases. Each model-driven phase returns typed JavaScript Object Notation (JSON). The server validates the answer before it advances. Five phases also write a .taste artifact.

# apps/server/src/orchestrator.ts:327-337
type DesignFlowPhase =
  | 'brief'
  | 'brand'
  | 'page'
  | 'assets'
  | 'build'
  | 'preview'
  | 'review'
  | 'repair'
  | 'complete'
  | 'response'

The pipeline is in packages/design-agent. The orchestrator is in apps/server/src. The separation matters. The package holds prompts and validators. The server holds order, state, budgets, previews, and screenshots.

What this package does not claim

  • No server was started. No WebSocket connection was opened. No push gap was induced.
  • No provider session was started. No model turn was sent. No adapter was run.
  • No build, test, lint, or type check was run. The verification record in

docs/verification/pr-quality-2026-09-09.md is quoted as history, not reproduced.

  • No design was generated. No page was rendered. The visual quality of Design Mode output is not

judged.

  • No installer was opened. The Windows and macOS installer behaviour is not verified.
  • No web page was fetched. The hosted release, the update feed, and the provider services are

outside this static reading.

  • No skill script was run. The taste-skill comparison uses documentation and source only.
  • Line numbers belong to pin c216616. A different checkout moves them.

The source calls the beta early and asks users to expect bugs (README.md:9-11). This package takes that statement at face value. It does not present the system as complete.

One limit deserves a separate sentence. The visual review reads screenshots and a Document Object Model (DOM) audit. It does not prove factual accuracy, working interactions, or performance (docs/DESIGN-AGENT.md:521-524). A passing review is evidence about a captured page, not proof that the page is correct.
