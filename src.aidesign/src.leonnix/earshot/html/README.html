earshot: sound as evidence for coding agents

An exploration of earshot 0.4.1 at local pin 4ac3d2a. Six documents explain how a command line tool on a central processing unit (CPU) turns sound into evidence that a coding agent can read and use.

The problem: an agent cannot hear

A coding agent can write the code for a film, a product demonstration or a game. The agent cannot hear the result. It cannot tell a good key press from a poor one. It cannot notice that a hit lands 80 milliseconds after the cut. It cannot hear that the music swells in the wrong place.

The usual feedback is a person with ears. That person listens, forms an opinion and writes a note. The loop is slow. The note is not repeatable. The agent cannot test the note.

earshot gives the agent a different feedback path. It measures the sound. It compares the sound to a description. It places the sound against the picture. Each result is a number, a time, a label or an image. The agent can read the result, change the code and measure again.

The thesis: sound becomes evidence

The thesis of this exploration is simple. Earshot does not give an agent taste. It gives the agent evidence. The evidence has four kinds:

EvidenceQuestion it answersExample
Calibrated matchIs this the kind of sound I asked for?A key press scores z +5.4 for "a single mechanical keyboard key press"
TimingWhere is the sound, and does it land on the picture?A hit starts at 0:04.12 and matches the cut within 4 milliseconds
Objective measurementWhat are the physical facts?Integrated loudness -14.2 loudness units relative to full scale (LUFS), true peak -1.1 decibels true peak (dBTP)
Learned classificationWhich broad class is it?AudioSet label "Typing" at probability 0.71, or a realness probability

AudioSet is a labelled sound taxonomy. Its tagger returns 527 class probabilities. Typicality is how close a sound sits to its nearest real references.

A model can be wrong. A measurement can also be wrong, but its error is visible. Earshot keeps the two apart. A "strong" match comes with a z score and a precision measured on held-out recordings at a stated base rate. A held-out recording is one that was not used to tune the model or the vocabulary. A base rate is the share of candidate pairs in a search that are true matches. A search over a large library has a low base rate. A loudness number comes from a standard formula. The documents show where each number comes from and where it stops being trustworthy.

Aha: the important design choice is not the use of a model. It is the calibration of the model against the vocabulary itself. A raw cosine between a sound and a sentence is hard to read. Earshot removes the bias of each term, divides by the spread of the terms on that sound, and reports a z score. The z score turns "0.42" into "strong, z +5.4". For one sound, suppose four corrected term scores are 0.40, 0.20, 0.10 and 0.00. Their mean is 0.175 and their population spread is 0.148. The z scores are +1.5, +0.2, -0.5 and -1.2. A real sound has 322 terms, so the mean and the spread use all 322. This example is arithmetic, not a recorded result. The same idea appears in realness, in forge typicality and in timeline event tags: a raw similarity is standardised against a reference spread before it is read.

# earshot/vocab.py:271-290
    def calibrate(self, A, Q=None, method='both'):
        """A (n, 512) audio, Q (m, 512) query embeddings -> dict of (n, T) term arrays and (n, m) query arrays:
        cos, u (bias removed when method is 'center' / 'both'), z (per-sound z when 'sound' / 'both', else u),
        pct (share of vocab terms the query beats)"""
        A = np.atleast_2d(A)
        C = A @ self.E.T
        U = C - self.mu_E if method in ('center', 'both') else C
        r = {'cos_t': C, 'u_t': U}
        if method in ('sound', 'both'):
            mu, sd = U.mean(1, keepdims=True), U.std(1, keepdims=True) + 1e-9
        else:
            mu, sd = 0.0, 1.0
        r['z_t'] = (U - mu) / sd
        if Q is not None:
            Q = np.atleast_2d(Q)
            Cq = A @ Q.T
            Uq = Cq - self.bias(Q) if method in ('center', 'both') else Cq
            r['cos_q'], r['u_q'], r['z_q'] = Cq, Uq, (Uq - mu) / sd
            r['pct_q'] = (U[:, None, :] < Uq[:, :, None]).mean(-1)
        return r

The verdict is a threshold on that z score. The thresholds are fixed and few: 3.0, 2.5 and 2.0. A reader can therefore compare two verdicts across files and commands.

# earshot/match.py:50-54
def verdict(z):
    for t, name in VERDICTS:
        if z >= t:
            return name
    return 'no match'

The command table is not the contract. Each command is a thin layer over a Python function. The Python application programming interface (API) exposes the functions. The MCP server exposes 16 of them as tools.

The dispatch is lazy. earshot describe imports only the describe module. This keeps a first call shorter when the agent needs one answer, because the unused command modules never load. The model load still dominates a cold call, as the limits document explains.

Two making loops

Earshot is not only a listener. It has two loops that make sound from code.

flowchart LR subgraph Forge loop R[Recipe module] --> P[Render parameters] P --> W[Waveform] W --> C[Critic: model and model-free] C --> S[Search: evolution strategy or separable covariance matrix adaptation evolution strategy (CMA-ES)] S --> P W --> B[Robust re-renders and seed bank] B --> F[Final picks and report] end subgraph Fit loop A[Recording] --> M[Analysis by synthesis] M --> K[Model JSON] K --> G[Recipe code generator] G --> T[Takes, knobs and morphs] T --> Q[Quality metrics against the recording] Q --> M end

The forge loop starts with a recipe and a target description. It renders candidates, scores them with a critic and searches the parameter space. The critic combines a contrastive language-audio pretraining (CLAP) match, a realness probability, a typicality score and several model-free checks. The output is a set of diverse final sounds, a report and an audition file.

The fit loop starts with a recording. The fitter chooses a model kind, such as modal, sines, spectral, gesture or hybrid. It fits a synthesis model by analysis by synthesis. It writes the model as a readable forge recipe module. The module stores structure, not samples. The user can render takes, turn knobs and morph between two recordings.

The two loops meet at the recipe contract. A recipe is a Python module with a render(params, rng) function. A take is one rendered audio file. A knob is a recipe parameter that the user can turn. A morph blends two fitted models. A fitted recipe has the same render(params, rng) shape as a hand-written recipe. The forge critic can search a fitted recipe without a special case.

Pin and terms

The source is a local Git checkout at 4ac3d2a. A pin is the exact Git commit that this exploration read. It has 287 tracked files. The package version is 0.4.1. The code and the documents use the Massachusetts Institute of Technology (MIT) licence. The models have their own terms. CLAP uses laion/larger_clap_general under the Apache License 2.0. The audio spectrogram transformer (AST) uses MIT/ast-finetuned-audioset-10-10-0.4593 under the BSD 3-Clause licence. The evaluation recordings and films are not redistributed.

The version has one naming detail. The package is 0.4.1. The launch film is a v0.4.0 release asset. A release tag is not a package version. A reader who sees the release asset can mistake its tag for the package version. The package version and the tag are separate.

What this exploration does not claim

  • It does not run earshot, a test, a model or an evaluation.
  • It does not load, analyse or listen to an audio file.
  • It does not make a network request.
  • It does not verify runtime behaviour. Every runtime number comes from a project document or a results file.
  • It does not recompute the evaluation data. The data is absent.
  • It does not resolve two project inconsistencies. The held-out library is 125 files in docs/VALIDATION.md and 126 in docs/DESIGN.md and eval/README.md. The validation record says 13 MCP tools, but the code registers 16. This exploration quotes the code count and marks the record as stale.
  • It does not verify the multi-agent build process that docs/DESIGN.md describes.
  • It does not independently judge the quality of the sounds. It records the project's measurements and their limits.
# earshot/audio.py:124-165
def load(path, sr=SR, mono=False, start=None, end=None, cache=True):
    """decode `path` to float32 (n, 2) or (n,) when mono; optional [start, end) in seconds"""
    if not os.path.exists(path):
        raise AudioError(f'no such file: {path}')
    ch = 1 if mono else 2
    x = None
    npy = None
    if cache:
        config.ensure_dirs()
        npy = os.path.join(config.DEC_CACHE, _key(path, sr, ch) + '.npy')
        if os.path.exists(npy):
            try:
                x = np.load(npy)
            except Exception:
                x = None
    if x is None:
        x = _decode(path, sr, ch)
        if npy:
            tmp = f'{npy}.{os.getpid()}.tmp.npy'
            np.save(tmp, x)
            replace_quietly(tmp, npy)
    bad = ~np.isfinite(x)
    if bad.any():   # one NaN / Inf sample breaks every analysis downstream (#12)
        bad = bad.any(axis=-1) if x.ndim == 2 else bad
        raise AudioError(f'{path}: {int(bad.sum())} NaN / Inf sample(s), first at {int(np.argmax(bad)) / sr:.3f} s: '
                         'the file is corrupt or the code that made it divided by zero')
    if start is not None or end is not None:
        a = max(0, int(round((start or 0.0) * sr)))
        b = len(x) if end is None else min(len(x), int(round(end * sr)))
        x = x[a:b]
    return x


def to_mono(x):
    return x.mean(axis=1) if x.ndim == 2 else x


def resample(x, sr_from, sr_to):
    if sr_from == sr_to:
        return x
    import soxr
    return soxr.resample(x, sr_from, sr_to, quality='HQ').astype(np.float32)

The loader is the first step of every listening path. It decodes a file to 48 kilohertz, keeps two channels, guards against not-a-number values and caches the result. The core mechanism document gives the cache key and the gap in it.
