src.leonnix: nineteen code-built design projects

src.leonnix is not one project. It is a container of nineteen separate Git checkouts. The container has no root repository, no root README.md, and no root package.json. Each child directory is its own project with its own history and its own commit.

The projects look unrelated. They include an offline piano film, a Greek temple world, a house at dusk, four agent skills, an audio analysis tool, a Backrooms game, a first-person shooter, and a desktop application for design work. They share one method. Each project builds its content from code. Most visual projects render frames offline. A seeded random number generator makes the output repeatable. Where judgement is needed, the project adds a deterministic check before it trusts a model report.

This page is the index. Each project has its own folder with its own spec.md, its own documents, and its own generated pages. Every project receives the same full exploration: six documents that cover the overview, the architecture, the core mechanism, the workflow and quality checks, and the limits. The depth is the same for every project. A small project divides a small surface into those five parts.

Thesis

The collection is a study in one idea: taste is a process, not a prompt.

The visual projects express the idea through geometry, light, and time. A scene is a program. A frame is a function of a seed, a time, and a camera. The film is a loop over frames, not a recording of a live session.

The skill projects express the idea through gates. An agent can claim that a page is good. A checker measures the page in a real browser. The finish gate blocks the agent until the measured result passes.

The two largest projects are the two poles of the idea. tastecode is the tool pole: a local server owns state, runs a phase pipeline, and stores every event in an append-only log. The model is one component inside a larger machine. taste-skill is the skill pole: a text skill and a set of Node scripts run inside another agent, and a stop hook turns the checker into a condition for finishing.

Both poles reach the same conclusion by different routes. A model's opinion of its own work is not evidence. A deterministic check is evidence.

A reader who wants the design argument should read tastecode and taste-skill as a pair. A reader who wants the graphics method should read one offline film and one real-time world. A reader who wants the smallest complete example should read cook, which has twelve files.

What this exploration does not claim

  • It does not claim that any project builds. No build was run.
  • It does not claim that any project renders correctly. No render was run.
  • It does not claim that any test passes. No test was run.
  • It does not claim that a stated licence is correct. Each package records what its files state.
  • It does not claim that a checkout matches its upstream repository. It records the local commit.
  • It does not compare visual quality. Quality claims need output, and no output was produced.

Each package repeats these limits in its own words, because each package is read on its own.
