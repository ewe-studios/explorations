taste-skill: a design skill with a finish gate

Taste Skill is an Agent Skill for web design. The source is a Git checkout at pin f6b7657. The version is 2.5.1 (skills/taste-skill/SKILL.md:4). The licence is MIT (LICENSE:1). The skill folder holds 1,631 tracked files, and the repository holds 1,663 (spec.md).

The thesis of this package is one sentence. The skill turns design taste into a set of checks that a machine runs, and it makes the checks a condition for ending a build. The written rules in SKILL.md tell the agent what to build. The scripts measure the result in a real browser. A Stop hook stops the agent from declaring the work finished before the gate passes.

This package explains how that arrangement works. It also explains what the arrangement cannot do. The reader needs no prior knowledge of the source.

The gate has three hook modes. Claude Code and Codex receive block. Antigravity receives continue (skills/taste-skill/scripts/gate.mjs:111).

The checker holds a fixed order of check identifiers. The order literal holds 98 entries, and three insert calls add four more. The order gives stable report output and stable repair priority (skills/taste-skill/scripts/consistency.mjs:10192-10195). The order is not the full fault set. After the insert calls, the checker appends the checks of each module (skills/taste-skill/scripts/consistency.mjs:10196). The two held warnings, hero-enter and moment-none, are checker warnings that the gate treats as failures. They are not order entries (skills/taste-skill/scripts/gate.mjs:482).

The written gate reference states the first rule of build tracking. A build stays active while its marker exists, and deleting the marker does not end the build (skills/taste-skill/references/gate.md:26-27).

# skills/taste-skill/references/gate.md:26-27
- **A build is active** while `.taste-skill/build.json` exists in the project folder (or one or two
  folders below), or while `.taste-skill/gate.json` says its rounds are still open: deleting the marker

What this package does not claim

  • No script was run. No browser was started. No page was built. The runtime behaviour is not

verified here. Every runtime statement comes from the source text.

  • The checker's false-positive rate is not measured here. The changelog states that version 2.5.1

fixed six false positives (CHANGELOG.md:20).

  • A GATE: PASS result is not evidence of good design. It is evidence that the listed checks

passed.

  • The hook behaviour of Claude Code, Codex, and Antigravity is not tested here.
  • TasteCode embeds the rules of version 2.5.0. The checkout under study is version 2.5.1. The

comparison in 04-limits-and-comparison.md applies to 2.5.0 where the embedded copy is the subject (../tastecode/packages/design-agent/references/tasteskill-web/provenance.json:3-9).

  • The 39 MB size of the skill folder and the 37 MB size of its assets folder are disk measures.

A file count is a different measure, and the two numbers must not be compared as the same.

  • The source is read only. This package does not modify the checkout.
