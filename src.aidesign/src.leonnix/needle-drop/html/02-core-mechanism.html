Stage 1: the time base

The film time base is a frame number and a time in seconds. Frame n covers the time from (n-1)/24 seconds to n/24 seconds. Frame 433 therefore starts at (433-1)/24 = 18.0 seconds.

The camera path samples the start of each frame, t = (f - 1) / 24 (scenes/set_c/c_common.py:40-42). The motion blur shutter is 0.5 at frame 433, so the render integrates from 17.9896 to 18.0104 seconds, a half-frame window centred on 18.0. This document follows the path value, not the integrated image.

Stage 3: the frozen beat

The film has 0.5 seconds of frozen time before the drop. The master makes it digitally silent from 17.500 to 17.998 seconds. At 120 beats per minute, one beat lasts 0.5 seconds, so the gap is one beat, not half a beat. The source docstring calls it a "half-beat". The helper tau returns the time before 17.5, 17.5 inside the silence, and the time minus 0.5 seconds after 18.0.

# scenes/set_c/c_common.py:59-62
def tau(t):
    """Frozen time for the half-beat of silence 17.5-18.0 (grains and kick rings hang)."""
    t = np.asarray(t, dtype=float)
    return np.where(t < 17.5, t, np.where(t < 18.0, 17.5, t - 0.5))

Grains and kick rings hang while the music is silent. The build applies the frozen clock to ring age at scenes/set_c/build.py:76, and the sand point sets use it as a node expression at scenes/set_c/c_fx.py:168. After 18.0 the frozen clock runs 0.5 seconds behind raw time. The front uses raw time.

Stage 4: the drop front radius

The front is a radius that starts inside the label edge and grows at a fixed speed. The function is a straight line with two clamps.

# scenes/set_c/c_common.py:150-155
def front_r(t):
    """Drop front radius. Before 18.0 it is far inside the label (no morph)."""
    t = np.asarray(t, dtype=float)
    fr = 240.0 + 880.0 * (t - 18.0)
    fr = np.where(t < 18.0, -200.0, fr)
    return np.where(t > 19.2, 1300.0, np.minimum(fr, 1300.0))

The base radius is 240 metres, inside the label mesa, whose outer terrace ends at 262 metres. The speed is 880 metres per second. The front stops at 1300 metres, outside the 1200 metre disc rim.

At 18.0 the front is at 240 metres and the record groove starts at 270 metres. The front reaches the groove start at about 18.034 seconds, inside frame 433. The line gives 1296 metres at 19.2 seconds. The branch returns 1300 metres for any later time, a 4 metre jump. The camera holds X 1120 and Y 0 until 19.2 seconds, so the front passes the lens at 19.0 seconds. The timing file names front_passes_lens at frame 457 (data/timing.json:110-113).

The front travels 1060 metres in about 1.2 seconds. Shot S4 holds 84 frames, or 3.5 seconds.

            return

            self.L.new(v, sock)
        else:
            sock.default_value = v

    def node(self, typ, **props):
        n = self.N.new(typ)
        for k, v in props.items():
            setattr(n, k, v)
        return n

        self._in(n.inputs[0], a)

        if c is not None: self._in(n.inputs[2], c)
        return n.outputs[0]

Stage 5: the morph curve

A vertex does not jump from the dune height to the record height. It follows a curve with an overshoot and four control points. The values are 0 at 0, 1.10 at 0.55, 0.96 at 0.78 and 1.0 at 1.0.

# scenes/set_c/c_common.py:158-162
def morph_curve(u):
    """Spring-overshoot morph: points (0,0) (0.55,1.10) (0.78,0.96) (1,1) (smooth)."""
    xs = np.array([0.0, 0.55, 0.78, 1.0]); ys = np.array([0.0, 1.10, 0.96, 1.0])
    u = np.clip(u, 0, 1)
    return np.interp(u, xs, ys)

The curve rises 10 percent past the target, falls 4 percent below it and settles. Height and colour use the raw morph, so the overshoot raises both. Only the ring fade clamps it. The Python function joins points with straight lines, because np.interp is linear. The docstring says "smooth", but np.interp is linear between points. The render uses the node curve.

The same four points form a float curve in the Geometry Node tree. Python serves the build checks; the node curve serves the render. The two curves agree at 0, 0.55, 0.78 and 1.0. The code does not set the handle type, so the between-point shape is not defined in this excerpt.

The input u is (front - r) / 60, clamped to the range 0 to 1. A vertex completes the morph while the front travels 60 metres past it. The 60 metre width is a soft edge, so the front is not a hard step. The source does not state why it is 60 metres.

The value m1 = min(morph, 1.0) scales the kick rings by 1 - m1. A ring fades where the morph is done, so it cannot add height to a finished groove.

Stage 6: two height fields

The disc has two height fields, the dune field and the record field. The morph blends them per vertex.

The record field is analytic at build time: a formula gives the height directly. The first excerpt gives label_mesa, spoke_mask and groove_window. label_mesa has two 20 metre terraces with 12 metre wide walls, a 30 metre deep crater and a 3.5 metre rim. groove_window fades the ridges in over 270 to 295 metres and out over 1135 to 1160 metres. spoke_mask makes eight rays. The trench is a flat annular run-out band from 1170 to 1200 metres, not a spiral. The groove band is 890 metres wide, from 270 to 1160 metres. Division by the 40 metre pitch gives 22.25, and half-step rounding gives ring indices 0 to 22, which is 23 logical rings. The zone is floor(k * 8 / 23), clamped to 0 to 7: eight groups. The mesh uses 1,054 rings and 3,600 angular segments, so groove sharpness depends on mesh density.

SPOKE_W = 0.24     # spoke half-width in cos(8 theta) units: constant ANGULAR width -> rays widening outward (~30 m at r 1000)


def label_mesa(r):
    # two 20 m terraces with 12 m wide sloped walls (strata read from above), a wide 30 m deep spindle crater with
    # a raised lit rim
    h = 20.0 * (1 - smoothstep(250, 262, r)) + 20.0 * (1 - smoothstep(234, 246, r))
    h = h - 30.0 * (1 - smoothstep(12, CRATER_R, r)) + 3.5 * np.exp(-((r - CRATER_R - 5.0) / 5.0) ** 2)
    return h


def spoke_mask(r, th):
    return np.exp(-(np.cos(8 * th) / SPOKE_W) ** 2)


def groove_window(r):
    return smoothstep(R_GROOVE0, R_GROOVE0 + 25, r) * (1 - smoothstep(R_GROOVE1 - 25, R_GROOVE1, r))

# scenes/set_c/c_terrain.py:101-115
def h_record(x, y):
    r = np.hypot(x, y); th = np.arctan2(y, x)
    win = groove_window(r)
    rr = r + 2.5 * np.cos(16 * th) * win
    xg = np.pi * (rr - R_GROOVE0) / RING_PITCH
    eps = 0.2
    s = np.sqrt(np.sin(xg) ** 2 + eps * eps) - eps
    c = np.clip(1 - s / (math.sqrt(1 + eps * eps) - eps), 0, 1)
    spk = spoke_mask(r, th) * win
    crest = CREST_H * c ** 1.4 * win * (1 - 0.8 * spk)          # ridges flatten into broad smooth spoke channels
    spoke = -2.5 * spk
    trench = -18.0 * smoothstep(1170, 1177, r) * (1 - smoothstep(1193, 1200, r))
    k = np.floor((rr - R_GROOVE0) / RING_PITCH + 0.5)
    zone = np.clip(np.floor(k * 8 / 23.0), 0, 7).astype(np.int32)
    return label_mesa(r) + crest + spoke + trench, crest, zone

The crest term uses a rounded absolute sine: c is 1 at the crest and 0 in the trough. The crest height is 11 metres and the ring pitch is 40 metres. An angular warp of 2.5 metres at 16 cycles makes the rings slightly non-circular. The spoke term removes 80 percent of the crest height in eight channels and lowers the surface by 2.5 metres.

The dune field comes from the banded marble noise in tools/nd_lib.py. The field returns the continuous raw value and its fractional part m. The dune profile is asymmetric: a cosine rise on the windward side and a quadratic drop on the lee side, with the crest at 0.71. The palette PAL at tools/nd_lib.py:9-14 puts chalk at 0.70, as does MARBLE_VEIN_POS at :28; the crest at 0.71 sits on the vein.

# scenes/set_c/c_terrain.py:155-163
def dune_profile(nb, m):
    """asymmetric dune: rounded windward rise to the crest at 0.71 (chalk vein), sharp lee drop."""
    c = 0.71
    w = nb.math('DIVIDE', m, c, clamp=True)
    hw = nb.sub(0.5, nb.mul(0.5, nb.math('COSINE', nb.mul(w, math.pi))))
    s = nb.math('DIVIDE', nb.sub(m, c), 1 - c, clamp=True)
    hl = nb.math('POWER', nb.sub(1.0, s), 2.0)
    lt = nb.math('LESS_THAN', m, c)
    return nb.add(nb.mul(lt, hw), nb.mul(nb.sub(1.0, lt), hl))

The profile is a shape from 0 to 1. The band width sets its amplitude, and the marble gradient sets the band width.

Stage 7: the dune bake

A per-frame gradient would cost too much, so the build bakes the dune height once. ND is the shared look library. _marble_vec at scenes/set_c/c_terrain.py:143-152 maps a position: take (x, y, 0), scale by S, rotate about Z by the handoff angle, add the handoff offset. The bake group evaluates the marble field at the mapped vector V and at V plus a 0.0025 offset. The offset is in the mapped vector. The field returns raw as q2.x * freq, so the world gradient divides by the step times S. Without S, the gradient would be per mapped unit, not per world metre. The inverse gradient gives the band width in metres. The width sets the dune amplitude.

Why the mechanism works

The mechanism has four cheap choices. First, the morph is a radius function: a vertex needs only its radius and the front value, with no neighbour lookup or simulation. Second, the dune field is baked once, so the live tree reads one float per vertex. Third, the record field is analytic: radius and angle give the height at build time, and the builder stores one value per vertex. A groove is as sharp as the mesh: at the rim the disc uses 3,600 segments, about 2.1 metres of arc. Fourth, the objects split by time: the live mesh runs to frame 516, the static mesh from 517, and the patch to 541. The static copy carries fixed heights outside the live tree. Aha: The drop is not an animation of a model but a data field that changes its meaning. The same vertex carries a dune height and a record height. The front radius selects a point on an overshoot curve, and that one value blends the two heights, the two colours and the kick-ring fade. One scalar moves a desert into a record.

What the mechanism cannot prove

This trace comes from source reading. The frame was not rendered. The vertex positions, the flash brightness, the morph timing and the final image are not compared with a rendered image. The code defines the mechanism; a render would define the appearance.
