04 Limits and comparison: what the repository proves and what it cannot

shanshui paints ten Chinese ink-wash landscapes and joins them into a one-minute film. This document tests the claims. It separates static facts from runtime values. It lists failure modes, internal inconsistencies and break-first risks. It then compares shanshui with athenaion and casa-ocaso, two sibling projects.

3. Static limits

3.1 The comparison loop has no fixed input

The style guide sets the bar: a still must read as the same painter as its reference (docs/STYLE.md:3). The ignore file excludes the whole ref/ folder (README.md:64, .gitignore:3-4).

# .gitignore:1-5
node_modules/
out/
# reference paintings are used only for side-by-side comparison and are not part of the code
ref/
*.log

A fresh clone holds the code for every tool. It can run a still or a film only with Chrome or Edge, and the film path also needs ffmpeg. It cannot run tools/still.mjs --compare, --side or --crop with the original images. These flags make stacked, side-by-side and crop images (tools/still.mjs:5-7). The user must supply ref/01.webp to ref/10.webp (README.md:64). Any reference supplied later can differ in crop, colour or compression. The comparison is therefore not reproducible from the repository alone.

3.2 The film is a release asset

The README links to the releases for the film (README.md:9). The out/ folder is ignored (.gitignore:2). No MP4, WAV or frame sequence is tracked. The source can rebuild the film. The repository cannot prove that the released film came from this commit.

3.3 No runtime assets means no asset checks

The project states that no image, texture, font or audio sample loads at runtime (README.md:7). This removes a class of failures: a missing file, a bad path or a licence problem. Every visual element must therefore come from code. A regression can change a brush or a shader and leave no asset diff to review.

3.4 No build, no test, no pinned engine

The package file has three scripts and two development dependencies (package.json:1-17).

There is no engines field. The README asks for Node 20 or later (README.md:45), but nothing enforces that version. No test script or test folder appears in git ls-files. No linter, formatter or continuous integration file is tracked (spec.md:50-56). The project uses direct modules with no build step (spec.md:221), so a broken import appears only when a browser loads the page.

The dependencies are puppeteer-core and ws (package.json:14-17). The first controls a browser; the second carries film frames. Both are development tools. The browser page itself has no package dependency.

4. Values that exist only at runtime

The following values cannot be read from the source. A bake is a one-time texture render. A card is a flat painted layer at a depth. A grade is a colour transform applied to a rendered scene before the transition composite (src/film.js:113-127). A pop is a one-frame jump. The forensics tool checks a finished video for these events. 5.1 Shader errors stop the page

The compiler throws on a failed shader (src/engine/gl.js:31-45).

# src/engine/gl.js:31-45
export function compile(gl, vsSrc, fsSrc, label = 'program') {
  const mk = (type, src) => {
    const s = gl.createShader(type);
    gl.shaderSource(s, src);
    gl.compileShader(s);
    if (!gl.getShaderParameter(s, gl.COMPILE_STATUS)) {
      const log = gl.getShaderInfoLog(s);
      // show only the lines around the error for readability
      const m = /ERROR: \d+:(\d+)/.exec(log);
      let ctx = '';
      if (m) {
        const ln = +m[1]; const lines = src.split('\n');
        ctx = lines.slice(Math.max(0, ln - 6), ln + 3).map((l, i) => String(Math.max(1, ln - 5) + i).padStart(4) + ': ' + l).join('\n');
      } else ctx = numbered(src).slice(0, 4000);
      throw new Error(`[${label}] ${type === gl.VERTEX_SHADER ? 'vertex' : 'fragment'} shader error:\n${log}\n${ctx}`);

The error includes the driver log and nearby source lines. The throw is not caught, so a scene shader error stops that scene load. In the still tool, the job returns an error. In the live viewer, the catch writes the error stack into the page and stops that run (src/main.js:229).

5.2 Frame cost is not bounded by the engine

The sub-frame renderer loops over the sample count and blends each result (src/engine/engine.js:553-566).

# src/engine/engine.js:553-566
  renderSceneFrame(scene, t, { samples = 1, shutter = 0.5, fps = 60 } = {}) {
    if (samples <= 1) {
      this.renderScene(scene, t, this.targets.sceneA);
      this.present(this.targets.sceneA, this.gradeAt(scene, t));
      return;
    }
    this.clear(this.targets.accum);
    for (let i = 0; i < samples; i++) {
      const ts = t + ((i + 0.5) / samples - 0.5) * (shutter / fps);
      this.renderScene(scene, ts, this.targets.sceneA);
      this.blit(this.targets.sceneA, this.targets.accum, 1 / samples, true);
    }
    this.present(this.targets.accum, this.gradeAt(scene, t));
  }

The cost is linear in the sample count. The film command uses two samples (README.md:42); the tool default is one (tools/render.mjs:20). The engine has no time budget and no automatic quality fallback, so a slow scene makes the film take longer.

The frame readback and send loop keeps at most two frames in flight (src/main.js:127-148). This bounds memory, not time.

5.3 A lost context has no recovery

The engine creates the WebGL 2 context once (src/engine/gl.js:3-25). No source file listens for webglcontextlost or webglcontextrestored. A driver reset or a memory event stops drawing. A long film render on a small GPU can hit this. The tool would see no more frames or a failed acknowledgment.

5.4 The daemon protects itself

The daemon is a warm browser server for still jobs. It has a 240 second default timeout and a page limit (tools/daemon.mjs:9-13, tools/daemon.mjs:40-43). A timed-out job releases its slot in a finally block (tools/daemon.mjs:49-52). One bad scene does not block later jobs. A browser crash is different. The daemon would need a restart.

The generated index has eleven sections (docs/LIBRARY.md:5-315). The library has twelve top-level modules (spec.md:64-66). src/lib/gust.js is not in the index. The generator reads every .js file but sorts by a fixed order list (tools/libdoc.mjs:8-10).

The list omits gust. A regenerated index would put gust.js first, because its order index is -1 (tools/libdoc.mjs:9). The checked-in index omits gust.js. This is documentation drift.

6.4 The render header is stale

The render tool header says frames stream as raw RGBA (tools/render.mjs:2). The encoder asks for YUV 4:2:0 (tools/render.mjs:44-48). The engine packs YUV on the GPU (src/engine/engine.js:207-236). The header can mislead.

11. Design logic

No runtime assets. The project wants every mark to come from code (README.md:7). This removes asset loading, atlas packing and licence files. It also removes the fastest way to add detail: a photograph.

2.5D cards. An ink painting reads as flat planes at different distances (docs/STYLE.md:18). Flat cards at depth give parallax with a simple projection (docs/ENGINE.md:23-29). The cost is that a camera move can show a card edge. The film guide turns that cost into an overscan rule (docs/FILM.md:31-36).

Two renderers. WebGL 2 draws shaders, mist, water and composites. Canvas2D draws brush marks at bake time and moving cranes, leaves and snow at frame time. The cost is two memory paths and a premultiplied alpha contract (docs/ENGINE.md:132-134).

Streaming film. The renderer never writes a frame to disk (tools/render.mjs:1-2). A 60 second 1080p film at 60 FPS is 3,600 frames. Streaming raw YUV to ffmpeg keeps at most two frames in flight (tools/render.mjs:54-66). The cost is a strict handshake: a slow encoder slows the render.

Synthesized audio. The soundtrack follows the same bars as the picture (tools/audio.mjs:13). A sample library would add assets and licences. Synthesis gives exact control of timing. The cost is code complexity and a mastering loop that depends on ffmpeg.

No test suite. The target is visual. A pixel test against a reference would need the absent references. A unit test would not catch a wrong brush. The project uses visual review instead (docs/ENGINE.md:124). A refactor can therefore break a scene without a failing check.

12. Limits of this exploration

This document is a static reading. It does not render a frame, open a browser, run a tool or measure audio. It does not compare a still with a reference (spec.md:214-223).

The counts come from this checkout at commit b5357c0 (spec.md:50-73). A GPU driver may show a defect that the source hides. The film may stutter even when every budget is met. The comparison sections use the other projects' README files and specs; the numbers are their numbers.

The document cannot judge beauty. It can show the intended value ladder and paper ground, not the effect on a viewer (docs/STYLE.md:18-27).

13. Aha

Aha: The largest risk in shanshui is not a code defect. It is missing evidence. The project excludes the two things that would prove its central claim: the reference paintings and the rendered film (README.md:9, :64). The source can prove the clock, layers, transitions and render path. It cannot prove that a frame reads as the same painter, or that 3,600 frames hold together. Athenaion records a 4K render and ships a reference comparison image (athenaion/README.md:33, :40-42). Casa Ocaso uses numeric colour fitting and checked-in atlas data (casa-ocaso/README.md:50). Shanshui leaves the proof to the release page and the viewer, so the quality claim sits outside the repository.
