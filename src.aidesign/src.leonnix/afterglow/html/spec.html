Afterglow is an offline-rendered film. A pianist in a suit plays a concert grand piano that stands in a shallow mountain lake at sunset. The film is 3 minutes and 51 seconds long. The music, the performance, the piano, the pianist, the sky, the mountains and the water are all made for the film. The renderer is three.js, driven frame by frame by Node.js in a headless Chrome page. No frame is captured from a live session.

2. Scope

This package covers the film as a system. It covers these areas:

  • The music: the score DSL, the note-by-note composition, the validators, and the

final score data.

  • The sound: the offline sampler, the damper and pedal model, the synthetic hall,

the mix and the mastering chain.

  • The performance: the solver that turns score onsets into fingering, hand pose,

finger inverse kinematics (IK), arm IK, body motion, pedal motion, key motion, hammer motion, damper motion, and water ripples.

  • The scene: the accumulation renderer, the thin lens, the depth-of-field (DOF)

gap fill, the final pass, the film light-transformation table (LUT), the procedural piano, the pianist asset, the sky, the clouds, the terrain, the boulders, the water, the camera edit and the integration checks.

  • The render drivers: still frames, chunked film render, resume, determinism,

snapshot, encode, verify and the GPU lock.

  • The edit: 26 shots, every cut anchored to a bar or beat, the focus hand track,

and the sun arc.

  • The quality record: the module documents, the measured numbers, the known

limitations, the credits and the licence scope.

It does not run the film. It does not render a frame, sample audio, solve the performance, launch Blender, start the preview server, or encode a file. It does not listen to the soundtrack or watch the release film. No network request is made.

4. Constraints

  • The source is read only. No project file is modified.
  • No render, sampler run, solver run, Blender build, browser launch, encode, or

preview server is executed.

  • No network request is made. The release film, the soundtrack, the samples and

the reference images are not downloaded.

  • Prose uses Aerospace and Defence Simplified Technical English, issue 100

(ASD-STE100). One idea per sentence. Thirty words maximum. Every abbreviation is expanded at first use in each file.

  • Prose avoids marketing language, em dashes, "simply", "just", and "obviously".
  • A value that the source does not define is recorded as not defined.
  • The pin is ced1038. Runtime behaviour is marked as not verified.
  • A quoted line must match the source byte for byte.
  • The exploration repeats the split licence. It does not call the whole

repository MIT.

5. Research questions

  2. How does one output frame become an average of N sub-frames, and which pass

  1. How does an offline renderer stay deterministic across sessions, chunk

boundaries and render order?

  1. How does the render pipeline survive a 21.8 hour run, and how does it resume?
  2. How does the encoder prove that sound and picture match the score?
  3. What did the render budget change, and what does the project state as a limit?

9. Limits

  • Static reading only. No frame, audio file, performance track, or film was

produced. The release film is not in the repository.

  • The visual quality is not evaluated. The README states its own visual limits.
  • The audio is not listened to. The measured loudness and peak values come from

the project documents, not from a new measurement.

  • The render times, sub-frame counts and file sizes come from the project

documents. No measurement was repeated.

  • The performance solver code changed after the released run. The README states

that a fresh solve is not the film's run (README.md:199).

  • Reproducibility is limited to one Windows machine and one integrated GPU. The

project states that other hardware gives slightly different pixels.

  • The released film, the soundtrack, the samples, the reference images and the

performance tracks are external assets or release files. The exploration reads only the tracked files.

  • The film licence is not MIT. Only the code and the listed generated data are

MIT.

10. Corrections and limits found during research

The inventory matched: pin ced1038, 351 tracked files, version 0.1.0, Node.js 22 or later. The following findings qualify the first reading.

  1. The manifest licence field is narrow. package.json:6 says MIT. The

LICENSE file and README.md:220-231 state a split scope. The composition, every file that encodes its notes, the performance tracks, the film, the audio renders and the stills are all rights reserved. A reader must not treat the repository as MIT.

  1. The film is not in the repository. build/ is excluded

(README.md:242). The checkout holds the source, the score data, the pianist asset and the documents. The film exists only as a release download.

  1. Two large binary assets use Git LFS. The pianist GLB and the Detmold

impulse response are LFS files (README.md:187-193). The released mix does not use the impulse response.

  1. The sun arc in the constants file is not the film's arc.

DEFAULT_SUN_KEYS starts at +0.6 degrees (scene/src/core/constants.js:12). The edit overrides it and starts at -0.8 degrees (scene/src/camera/shots.js:52-56). The README's -0.8 to -4.5 range follows the edit.

  1. The edit's N is not the release's N. The edit sets 32 for most shots and

48 for three shots. The final freeze lowered eight close-ups from 48 to 32 and one shot from 64 to 32 (scene/src/camera/shots.js:30-31). The release render then halves N after film time 1:50 (README.md:100). The released sub-frame count is 360,368, not the full-N 473,760.

  1. The motion-blur boost table covers 132 frames. The table holds boosts from

48 to 128 sub-frames on frames where a fast hand would otherwise show separate copies (scene/src/integration/motion_n.json). The README states that the release halves these boosts after 1:50.

  1. The soundtrack is longer than the film. The soundtrack is 227.5 s

(README.md:143). The film places it after a 4.0 s lead-in (scene/src/core/constants.js:5), so the audio extends about 0.55 s past the 230.95 s film. The encoder trims or pads the audio to the exact video duration (render/encode.mjs:19-21, :104-112). The tail is cut.

  1. There is no unit-test suite. The quality gates are the self test, the

determinism check, the performance QC, the integration checks and the encode verification. They are scripts, not a test framework.

  1. The README states the build method. It describes a multi-agent build

process (README.md:149-156). The exploration records this as a project statement. It does not verify the process or repeat the claim as its own.

  1. The film was made on one machine. The recorded run used a Ryzen 7 260, a

Radeon 780M integrated GPU, Windows 11 and headless Chrome 155 (README.md:125). The project states that other hardware gives different pixels.

  1. The render estimate is not the recorded run. The rebuild section projects

about 13.4 hours on an idle GPU (README.md:213). The recorded run took 21.8 hours of wall-clock time, about 9.7 hours of pure render time, with pauses for other GPU jobs (README.md:122).

  1. The score is frozen. The README calls music/final/ the frozen, approved

version (README.md:195). A later edit of the composition invalidates the camera hand track and the motion-blur table.

  1. No runtime claim is verified. No frame was rendered, no audio was

sampled, no performance was solved, and no encode was run.
