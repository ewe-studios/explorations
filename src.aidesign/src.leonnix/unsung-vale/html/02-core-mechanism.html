Core mechanisms traced end to end

This document follows six mechanisms from first input to last effect: the boot, the terrain pipeline, one rendered frame, one sword strike, the hero pose and one save. Each trace names the owning module and shows the data between steps.

From the entry page to the first frame

The browser starts at index.html. The page contains a small inline loader and one module script. The module script is the only entry to the game code.

The module system resolves the imports of src/main.js. The browser downloads the three.js modules, the game modules and the style sheet.

The boot is a sequence of awaited stages. Each stage updates the progress bar and changes the tip.

The stage function records a timestamp, scales the bar and writes the text. A 60 millisecond timer races an animation frame; the timer keeps a background tab loading.

The settings read the saved options and the graphics processing unit (GPU) name. FILM is true when the page runs a film capture. That mode uses the real rules with a puppet input and never writes a save.

From the height function to the terrain mesh

The terrain begins as a pure JavaScript function with no three.js dependency and no file access. The world builder imports it. The browser imports the layout constants and reads the baked maps.

# src/world/layout.js:208-232
  function height0(x, z) {
    const base = floorHeight(x, z);
    let h = base;
    const gi = Math.floor((x + half) / G), gj = Math.floor((z + half) / G);
    if (gi >= 0 && gj >= 0 && gi < gn && gj < gn) {
      const list = grid[gj * gn + gi];
      for (let k = 0; k < list.length; k++) {
        const m = list[k];
        const sd = mesaSd(m, x, z);
        if (sd > 1e8) continue;
        const rise = m.h - base;
        if (rise <= 0) continue;
        let mh;
        if (sd >= 0) {
          mh = base + rise * 0.1 * Math.exp(-sd / (0.1 * m.h + 8));       // talus skirt
        } else {
          const u = saturate(-sd / m.run);
          const t = cliffProfile(u, 0.07 * fbm(x / 190, z / 190, 2, m.seed + 9), m);
          const inside = saturate(-sd / (m.r * 0.5));
          const top = m.h + (m.pinnacle ? 5 * inside + 2.4 * fbm(x / 13, z / 13, 2, m.seed + 6) - 1.2 : 4.5 * fbm(x / 95, z / 95, 3, m.seed + 1) + 1.1 * fbm(x / 21, z / 21, 2, m.seed + 2) + 3 * inside);
          mh = base + (top - base) * (0.1 + 0.9 * t);
        }
        if (mh > h) h = mh;
      }
    }

height0 starts from the rolling floor. It visits each mesa near the sample. A positive signed distance gives a talus skirt; a negative distance gives the cliff profile and the noisy top. It keeps the highest mesa result. It then carves pools and notches their rims toward the outflow. The outer height function applies the paving pads. For each pad it computes a cap from a base height at a reference point plus an offset. An optional edge raises the cap near the rim. The pad blends the cap into the ground over a ring and only lowers it.

The world builder evaluates the function on a grid with four worker threads. Each worker receives a row range, the map size and the resolution.

# tools/build-world.mjs:14-23

A worker samples the height at the centre of each texel. The offset avoids a shift between the bake and the runtime query. The worker writes floating-point heights into a buffer. The main thread then quantises both maps to 16-bit integers and compresses them. The loader gunzips each file, reads 16-bit integers and scales each value by (max - min) / 65535 into a float texture (terrain.js:15-24).

The core map covers the playable 2,048 metres at one metre per sample. The region map covers 16,384 metres at eight metres per sample. The height query uses the core inside it. Near the edge it blends the core and the region. Beyond the edge it uses the region alone.

# src/world/terrain.js:532-547
  heightAt(x, z) {
    const sample = (data, res, size) => {
      const fx = (x / size + 0.5) * res - 0.5, fz = (z / size + 0.5) * res - 0.5;
      const ix = Math.max(0, Math.min(res - 2, Math.floor(fx))), iz = Math.max(0, Math.min(res - 2, Math.floor(fz)));
      const tx = Math.max(0, Math.min(1, fx - ix)), tz = Math.max(0, Math.min(1, fz - iz));
      const o = iz * res + ix;
      return (data[o] * (1 - tx) + data[o + 1] * tx) * (1 - tz) + (data[o + res] * (1 - tx) + data[o + res + 1] * tx) * tz;
    };
    const e = Math.max(Math.abs(x), Math.abs(z)) / (this.coreSize * 0.5);
    const hr = e < 0.9 ? 0 : sample(this.region, this.regionRes, this.regionSize);
    if (e >= 0.985) return hr;
    const hc = sample(this.core, this.coreRes, this.coreSize);
    if (e <= 0.9) return hc;
    const t = (e - 0.9) / 0.085, w = 1 - t * t * (3 - 2 * t);
    return hr + (hc - hr) * w;
  }

The sampler is bilinear. It converts the world position to a fractional texel coordinate, clamps the four corners and blends the four heights. The blend band runs from 0.9 to 0.985 of the core half size. That hides the resolution change.

The visible terrain is a quadtree of patches. The selector walks the tree and tests each node at a distance that doubles with the level. A node that fails the test is covered by a parent-level patch. A node that passes splits into children, or writes four half-size patches at the leaf.

# src/world/terrain.js:626-644
    const visit = (level, i, j) => {
      const P = pyr[level], s = leaf * (1 << level), x0 = -half + i * s, z0 = -half + j * s;
      const y0 = P.mn[j * P.n + i] - 4, y1 = P.mx[j * P.n + i] + 4;

      if (!_frustum.intersectsBox(_box)) return true;

      if (level === 0 || !sphereHits(x0, z0, s, y0, y1, base * (1 << (level - 1)))) {
        push(x0, z0, h, level); push(x0 + h, z0, h, level); push(x0, z0 + h, h, level); push(x0 + h, z0 + h, h, level);
      } else {
        for (let c = 0; c < 4; c++) {
          const ci = 2 * i + (c & 1), cj = 2 * j + (c >> 1);
          if (!visit(level - 1, ci, cj)) push(x0 + (c & 1) * h, z0 + (c >> 1) * h, h, level);
        }
      }
      return true;
    };
    const top = this.levels - 1;
    if (!visit(top, 0, 0)) { const s = this.regionSize / 2; push(-s, -s, s, top); push(0, -s, s, top); push(-s, 0, s, top); push(0, 0, s, top); }

The visit function first tests the node sphere against the distance for its level. If the sphere fails, it returns false, and the parent draws a patch at its own level for that quadrant. If the box misses the frustum, it returns true and draws nothing. At the leaf level, or when the child distance test fails, it writes four half-size patches. Otherwise it visits the four children. A failed child is covered by a half-size patch at the current level. That fallback keeps the surface watertight.

Each patch carries the height of its four corners and a morph weight. The vertex shader moves the vertices toward the coarser grid. The morph completes shortly before the level switch. The result has no cracks and no visible pop.

flowchart LR A[layout height function] --> B[Node world builder] B --> D[core_h.bin and region_h.bin] D --> C[Browser height query] C --> E[level of detail selector] E --> F[Instanced patch draw] F --> G[Terrain shader] G --> H[Colour and depth]

The bake feeds the collision floor, the map image and the note placement. A change to the function changes all of those systems at once.

One rendered frame

The pipeline render method is the frame contract. It runs in a fixed order because each pass depends on the output of the pass before it.

# src/engine/pipeline.js:296-313

    r.setRenderTarget(this.rtScene);

      r.render(this.sceneT, cam);

The sky shares the first colour target with the opaque scene. With a reversed depth buffer, the sky is drawn after the scene, and the depth test rejects covered pixels.

The transparent scene is drawn second. Before it, the pipeline copies the opaque colour into one texture and the linear depth into another. Water needs the colour and the depth behind it. The visual effects need the colour to bend the picture. The particles need the depth to fade against geometry.

The volumetric pass marches haze and mist at quarter resolution. It reads the depth texture and writes a low-resolution light volume. The fog pass then composites the scene colour, the volumetric result, the ambient occlusion and the mute-zone colour treatment. pipe.fog.mute holds up to eight spheres, each with a centre, a radius and a strength. The shader drains colour to a cold duotone and adds a warm rim at the edge. It keeps bright light and spares a small sphere around the hero. The audio director computes a separate mute value from the same spire data. The fog pass also upsamples the volume with a depth-aware filter, so a soft edge does not bleed over a near object.

The temporal anti-aliasing (TAA) pass reprojects the previous frame with the stored camera matrix. It clips the history colour against the current neighbourhood, then blends. The jitter is a Halton sequence of 16 offsets. The pass keeps its history when the render scale changes. The frame governor depends on that property.

Bloom builds six levels with a 13-tap down filter and a tent up filter. The first level uses a Karis average to stop a single bright pixel from flickering. The tone map then applies the AgX curve and writes to the canvas. AgX compresses highlights without a hard hue shift.

Water needs the depth copy. Fog needs the depth. Bloom must run in light space before the tone map. The pipeline encodes those reasons in one method.

One sword strike

A strike begins with the attack input. The player module checks stamina and chooses a descriptor. A ground attack starts combo step 0. A heavy input starts step 3. A sprinting attack with the dash skill starts step 2. An attack in the air after 0.08 seconds of air time starts the falling strike. During a combo, a queued attack advances to the next step after 62 percent of the current duration (player.js:215). The light combo uses player steps 0, 1 and 2. The heavy input uses step 3. The dash reuses step 2, so the hero table needs no fifth entry. Breath is the stamina resource. The start method spends the stamina, stores the attack descriptor and clears the hit set. The _wish vector is the stick direction, facing is the current forward vector, lockTarget is a hard target and aimAssist is a soft target query.

# src/game/player.js:106-125
  startAttack(desc, index) {
    if (!this.spend(desc.cost)) return false;
    this.attack = desc; this.comboStep = index; this.attackQueued = false; this.hitDone.clear();
    this.setState('attack');
    // Turn toward the lock target or the stick before committing.
    const want = this._wish.lengthSq() > 0.04 ? this._wish : this.facing;
    const foe = this.lockTarget ?? this.aimAssist?.(want.x, want.z) ?? null;
    if (foe && Math.hypot(foe.pos.x - this.pos.x, foe.pos.z - this.pos.z) > 0.4) this.yaw = Math.atan2(foe.pos.x - this.pos.x, foe.pos.z - this.pos.z);
    else if (this._wish.lengthSq() > 0.04) this.yaw = Math.atan2(this._wish.x, this._wish.z);
    const f = this.facing;
    // The lunge carries about lunge / 7.5 metres; with a foe ahead it ends at striking distance.
    let lunge = desc.lunge;
    if (foe) { const gap = Math.hypot(foe.pos.x - this.pos.x, foe.pos.z - this.pos.z) - (foe.def?.radius ?? 0.5) - desc.reach * 0.5; lunge = Math.max(0.6, Math.min(desc.lunge * 2, gap * 7.5)); }
    this.vel.x = f.x * lunge; this.vel.z = f.z * lunge;
    this.emit('swing', { index });
    return true;
  }

The method turns the hero toward the target and emits a swing event.

The attack is active only inside the window in the descriptor. The game update then walks the enemy list. For each living enemy it tests the distance, the height difference and the angle against the arc and reach. The core field is the body-centre height above the feet, and it extends the vertical hit band for a tall kind.

The test is a sector checked on each active frame, not a physical blade mesh. It is cheap, stable and matches the animation arc. A ranked lancer starts a second bolt at 62 percent of the windup (enemies.js:431). The check p.hitDone makes each enemy take one hit per swing. Each cadence level adds 0.08 to the damage multiplier. p.power adds 0.12 per blade upgrade. A riposte multiplies by 1.7. The challenge multiplier is 1 on gentle, 0.8 on hard and 0.9 on standard. In film mode the game uses gentle regardless of the challenge setting.

The enemy hit method applies the defences first. A shield blocks a light blow from the front. A shell or ward reduces damage. The Anvil Shard charm makes a heavy blow ignore a ward. A heavy blow on a staggered enemy gains a bonus, but a boss does not take it. The method then subtracts health and poise, adds knockback and starts the death path at zero health.

# src/game/enemies.js:233-257
  hit(e, dmg, from, heavy = false) {
    if (!e.alive || e.state === 'dormant') return false;
    if (e.fade > 0.6) return false;
    if (e.def.shield && e.state !== 'stagger') {
      // In front of the wall of shards a light blow only rings on it; a heavy one cracks it.
      const dx = from.x - e.pos.x, dz = from.z - e.pos.z, l = Math.hypot(dx, dz) || 1;
      if ((dx * Math.sin(e.yaw) + dz * Math.cos(e.yaw)) / l > 0.35) {
        if (!heavy) { e.poise -= dmg * 0.6; e.glow = 1.2; this.events.push({ type: 'blocked', enemy: e }); if (e.poise <= 0) { e.poise = e.def.poise; e.state = 'stagger'; e.t = 0; } return false; }
        dmg *= 0.5;
      }
    }
    if (e.shelled) { dmg *= 0.38; this.events.push({ type: 'warded', enemy: e }); }
    if (e.ward > 0 && !(heavy && this.anvil)) { dmg *= heavy ? 0.6 : 0.35; this.events.push({ type: 'warded', enemy: e }); }
    // Caught off balance, it takes a heavy blow half as hard again, and everyone hears it.
    if (heavy && e.state === 'stagger' && !e.def.boss) { dmg *= 1.5; this.events.push({ type: 'rung', enemy: e }); }
    e.hp -= dmg; e.poise -= dmg * (heavy ? (this.anvil ? 3.1 : 2.2) : 1);

    _v.copy(e.pos).sub(from).setY(0).normalize();
    if (!e.def.boss) e.vel.addScaledVector(_v, heavy ? 9 : 5);
    const c = e.center;
    this.particles.burst(c.x, c.y, c.z, heavy ? 26 : 14, { speed: 7, life: 0.45, size: 0.07, color: [3.2, 1.6, 6.0], gravity: 9, drag: 2, streak: 0.06, dir: [_v.x, 0.3, _v.z], bias: 3 });

    else if (e.poise <= 0) { e.poise = e.def.poise; e.state = 'stagger'; e.t = 0; }

The hero pose

tools/blender/hero.py builds the hero mesh, and public/models/hero.glb stores it in the Graphics Library Transmission Format (glTF). The game loads that file and replaces its materials.

The rig stores rest rotations in character space; a pose is relative to rest. The two-bone inverse kinematics (IK) solver places a foot or a hand on a world target. It uses the law of cosines to find the joint angle, then swings the upper and lower bones.

# src/anim/rig.js:79-108
  ik(upper, lower, end, target, pole, weight = 1) {
    const U = this.bones[key(upper)]?.bone, L = this.bones[key(lower)]?.bone, E = this.bones[key(end)]?.bone;
    if (!U || !L || !E || weight <= 0) return;
    const u0 = _q1.copy(U.quaternion), l0 = _q2.copy(L.quaternion);
    U.updateWorldMatrix(true, false); L.updateWorldMatrix(false, false); E.updateWorldMatrix(false, false);
    const a = _a.setFromMatrixPosition(U.matrixWorld), b = _b.setFromMatrixPosition(L.matrixWorld), c = _c.setFromMatrixPosition(E.matrixWorld);
    const lab = a.distanceTo(b), lcb = b.distanceTo(c);
    const dir = _d.copy(target).sub(a);
    const lat = Math.max(Math.abs(lab - lcb) + 1e-3, Math.min((lab + lcb) * 0.9995, dir.length()));
    dir.normalize();
    // The part of the pole that is square to the reach direction says which way the joint bends.
    const pp = _p.copy(pole).addScaledVector(dir, -pole.dot(dir));
    if (pp.lengthSq() < 1e-8) pp.set(dir.y, dir.z, dir.x).addScaledVector(dir, -(dir.x * dir.y + dir.y * dir.z + dir.z * dir.x));
    pp.normalize();
    const cosA = Math.max(-1, Math.min(1, (lab * lab + lat * lat - lcb * lcb) / (2 * lab * lat))), sinA = Math.sqrt(1 - cosA * cosA);
    const knee = _k.copy(a).addScaledVector(dir, lab * cosA).addScaledVector(pp, lab * sinA);
    // Upper bone: swing its child toward the joint position.
    _q.setFromUnitVectors(_v.copy(b).sub(a).normalize(), _v2.copy(knee).sub(a).normalize());
    this.worldQ(U, _q3).premultiply(_q);
    this.worldQ(U.parent, _q4).invert().multiply(_q3);
    U.quaternion.copy(_q4);
    U.updateWorldMatrix(false, false); L.updateWorldMatrix(false, false); E.updateWorldMatrix(false, false);
    // Lower bone: swing the end onto the target.
    b.setFromMatrixPosition(L.matrixWorld); c.setFromMatrixPosition(E.matrixWorld);
    _t.copy(a).addScaledVector(dir, lat);
    _q.setFromUnitVectors(_v.copy(c).sub(b).normalize(), _v2.copy(_t).sub(b).normalize());
    _q3.setFromRotationMatrix(L.matrixWorld).premultiply(_q);
    _q4.setFromRotationMatrix(U.matrixWorld).invert().multiply(_q3);
    L.quaternion.copy(_q4);
    if (weight < 1) { U.quaternion.copy(u0.slerp(U.quaternion, weight)); L.quaternion.copy(l0.slerp(L.quaternion, weight)); }

The solver clamps the target to the reachable length. It projects the pole vector onto the plane square to the reach direction. That projection decides which way the knee or elbow bends. The weight argument blends the solved rotation against the existing pose. The blend eases a planted foot in and out.

The hero module reads the player state. It builds a gait cycle from the ground speed. A planted foot stays in the world until the body moves away from it, then takes a step. The feet do not slide. The sword is described in chest space, so a chest turn moves the blade. Each ground attack is a key table indexed by the player step. Steps 0 and 1 are the first two combo cuts. Step 2 is the spinning cut, used by the third combo cut and the dash strike. Step 3 is the heavy strike. The falling strike uses a separate continuous coil, dive and impact pose.

A key gives a time and rotations for the sword, hips, chest, pelvis and feet. In each key, L and R are foot x, z, yaw and lift; la is the left arm. The animation interpolates between keys. The blade trail samples the hero key table between frames, so the arc is smooth at any frame rate.

The cape and tabard use spring chains of Verlet points. A Verlet point stores its current and previous position; their difference is its velocity. Gravity, wind and body motion change the next position. The solver pushes the points out of capsule colliders. A capsule is a line segment with a radius, and the colliders follow the hero's body and limbs. The cloth reacts to running, turning and landing without a baked animation.

One save and one load

The save is one local storage record. The game writes it at checkpoints and after progress events. The film mode never writes.

  load() {
    this.checkpoint = { ...this.sites.spawn };
    try {
      const d = JSON.parse(localStorage.getItem(SAVE_KEY) ?? 'null');
      if (!d) return;
      for (const s of this.spires) if (d.tuned?.includes(s.id)) { s.tuned = true; s.power = 1; s.zoneR = 0; s.zone.w = 0; s.crystal.material.uniforms.uPower.value = 1; s.beam.material.uniforms.uPower.value = 1; }
      if (d.checkpoint) this.checkpoint = d.checkpoint;
      this.xp = d.xp ?? 0; this.wildDone = d.wild ?? []; this.bought = d.bought ?? 0;

The load then restores the remaining progress fields.

The record stores tuned spire identifiers, not objects. On load the game finds each spire by identifier and applies the tuned state. A restored spire has power 1, silence radius 0, a lit crystal and a raised beam. Other fields name progress. wild is the completed wildlife packs, bought is the bench purchase count, slain is kills per enemy kind and falls is deaths. waves is the reached encounter wave and time is play seconds. The game sorted the array by the story order (sites.js:448-450). The second spire in the journey is Cantor's Rise. When that spire is tuned, the load method opens the bridge. The bridge is a light span that grows outward from the Choir Gate over the gap.

One compatibility rule revalidates an ended save. The journey stays ended only when every current spire is tuned. An older save with fewer spires is therefore reopened. A corrupt record can leave partial state.

The central mechanism insight

Aha: Every mechanism in this document has one owner and one contract. The height function owns the ground. The pipeline owns the frame order. The step index links the attack descriptor to the hero key table: the descriptor owns the hit window, and the key table owns the pose. The save owns the list of spire identifiers. The rest reads those contracts. A strike looks correct because the blade and the hit test share the step. The terrain looks solid because the mesh, the collision and the map read the same bake. The cost is coupling inside each contract. The descriptor and key table are hand-aligned; a timing change must be made twice.
