Unsung Vale is an original third-person open-world role-playing game (RPG) that runs in a browser. A player called the Cantor crosses a valley of mesas and waterfalls. The Cantor breaks the constructs that guard eight Tuning Spires and wakes each one. Every mesh and every texture is generated by code in the repository. The terrain, the rock, the trees, the buildings and the enemies all come from functions. The hero mesh comes from a Blender Python script. Only the music and the sound effects come from outside.

2. Scope

This package covers Unsung Vale as a system. It covers these areas:

  • The thesis: a complete open-world game world, made from code, inside a browser tab.
  • The world layout: the analytic height function, the hand-placed mesas, the pools, the pads

for courts, the paths, and the Node-based bake into two 16-bit maps.

  • The engine: the renderer, reversed depth, the frame order, the physically based sky, the

volumetric clouds, the lighting model, the static and cascaded shadows, the volumetric light, the fog composite, the temporal anti-aliasing, the bloom, the tone map and the frame governor.

  • The world rendering: chunked level of detail terrain, triplanar cliffs, the forge texture

layers, water, waterfalls, trees, leaves, vines, grass, meadows, rocks, architecture, floor reflections, boats, the Lattice rings, dressing and wildlife.

  • The rules: state machine, player movement, combat, cadence, riposte, the refrain,

collision, enemies and their kinds, encounters and waves, elites and affixes, bosses, bells, spires and tuning, strings of light, quests, trials, chimes, reliquaries and charms, notes, geodes, dyes, saving and loading.

  • The presentation: the procedural hero, inverse kinematics, the attack tables, the cape

springs, the camera, particles, effects, the interface and the map.

  • The audio: buses, cross-fades, ambience, positional one-shots, layering, reverb and the

manifest.

  • The film: the shot list, the depth of field, the sub-frame accumulation and the two outputs.
  • The tools: the world bake, the browser drivers, the measurement tools, the play bot and the

film render.

  • The quality record: the architecture document, the changelog, the performance targets and

the claims that the project does not test.

It does not run the game, the world builder, the film render, Blender or any tool. It does not load a browser, download a package, fetch an audio file or view an image. Every runtime number comes from the project documents and is marked as not verified.

10. Corrections and limits found during research

The inventory matched: pin 9f61b0d, 239 tracked files, version 0.1.0, MIT code. The following findings qualify the first reading.

  1. The architecture document says "the three spires" but the game has eight.

docs/ARCHITECTURE.md:145 says game.js owns "the three spires". The spire order in src/world/arch/sites.js:449 has eight identifiers: petal, cantor, choir, east, south3, aurel, south1 and crown. The sentence is stale. The README and the game code agree on eight.

  1. The enemy table has eleven kinds, not ten. src/game/enemies.js:160-172 defines eleven

entries. Ten are the field constructs that the README names. The eleventh is sovereign, "The Stillness", the Crown boss with three phases. The README names the ten field kinds and describes the Crown boss in a separate sentence.

  1. The note count is generated, not stored. src/game/notes.js:46 sets a note every 46

metres along the story paths. The total is the length of those paths divided by 46, plus the extra places. The source has no constant 70. The number 70 is the README statement, and 60 is a dye threshold in src/game/game.js:28.

  1. The hero is both code and a model file. The README says that no model was imported. The

repository does hold public/models/hero.glb. The model is generated by tools/blender/hero.py and is not an imported asset. The exploration must state both facts.

  1. The architecture document is a moving record. It describes later additions in a

separate section (docs/ARCHITECTURE.md:216). A reader must read the whole document, not only the first half, to see the full rule set.

  1. The changelog is dated 13 November 2026. The date is later than the package version

history. The exploration records the date as written and does not interpret it.

  1. The film length is 80 seconds. The README and the changelog agree. The older

architecture text does not give a length.

  1. The performance numbers are one machine. docs/ARCHITECTURE.md:125-131 gives about

60, 52, 45 and 39 frames per second for Low, Medium, High and Ultra at 1080p. The numbers come from one integrated GPU with nothing else running.

  1. The audio is the only outside asset. CREDITS.md lists the authors and the licences.

The exploration must not attribute the audio to the code.

  1. Seven spires teach a skill, not eight. SKILLS in src/game/game.js:43-49 has seven

entries. The Crown has no entry. The README sentence "tunes the spire and gains an ability" is true for the other seven spires and false for the Crown. The exploration states the count and the exception.

  1. The game states include intro and menu. The comment at src/game/game.js:183

lists home, playing, paused, ending and free. The code also assigns intro (src/game/story.js:54), menu (src/game/game.js:323) and photo (src/game/game.js:510). No code assigns free. The exploration gives the assigned set and marks free as a comment-only value.
