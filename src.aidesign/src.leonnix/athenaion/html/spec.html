Athenaion is a procedural ancient Greek world. The world has an acropolis, a large Doric temple, colossal statues, an aqueduct, a terraced city, a lagoon, a river, waterfalls, vegetation and a mountain range. It uses no image, model or audio assets. Every mesh, texture, shader, tree, statue and waterfall is built in code from a seed. The project renders nine fixed shots and one 54 second film.

The project states that an AI coding agent built the world over about two days, with 55 subagents and about 45 hours of wall clock time (README.md:3,30-34). The exploration records this as a project statement. It does not verify the process.

2. Scope

This package covers athenaion as a system. It covers these areas:

  • The master plan: one layout file holds every fixed position, dimension and heading.
  • The heightfield: analytic landform, water signed distance field, terraces, stair profile, far grid.
  • The module contract: build(engine), optional test(engine), engine.add, onUpdate, seeds,

footprints, slots and the shared registry.

  • The architecture kit: Doric, Ionic and Corinthian orders, fluting, entablature, roofs, tholos,

propylon, stoa, balustrade and ruin fragments.

  • Sculpture: signed distance functions, smooth union, the surface net mesher, the statue library,

the colossal figures, the pediment groups and the fallen head.

  • The render pipeline: sub-frame accumulation, jitter, motion blur, depth of field, bloom, AgX tone

map, local tone mapping, hue secondaries, auto exposure, auto levels and the lens effects.

  • The nine shots and the look system: per-shot camera, sun angle, exposure, grading overrides.
  • The film: eight segments, camera moves in metres and degrees, cross-dissolves, motion blur.
  • The tools: static server, headless render, video render, persistent session, snapshot, colour

statistics, saturation statistics, sample and bake.

  • The quality record: art bible, composition document, contract, prompt, reference comparisons and

exposure percentiles.

It does not run athenaion. It does not start the server, open a browser, render a pixel, build a mesh, run a bake, measure a colour or play the film. All runtime numbers come from the project documents and are marked as not verified.

4. Constraints

  • The source is read only. No athenaion file is modified.
  • No server, browser, render, bake, session, snapshot or statistics command is run.
  • No network request is made. No dependency is installed.
  • Prose uses Aerospace and Defence Simplified Technical English, issue 100 (ASD-STE100). One idea

per sentence. Thirty words maximum. Expand every abbreviation at first use in each file.

  • Prose avoids marketing language, em dashes, "simply", "just", and "obviously".
  • A value that the source does not define is recorded as not defined.
  • The pin is 9b8bd23. Runtime behaviour is marked as not verified.
  • A quoted line must match the source byte for byte.
  • The exploration does not repeat the build-process product names. It describes the process only as

the project records it.

5. Research questions

  1. What problem does a fully procedural world solve, and which fixed data does the plan hold?
  2. How does the heightfield combine an analytic landform, a water field, terraces and a stair profile

into one function that every module calls?

  1. How does one module join the world: which members does the engine give it, what must it publish,

and how do failures stay local?

  1. How do footprints and slots let producers and consumers meet without importing each other?
  2. How does the architecture kit turn an order, a column count and a size into a temple, a tholos or

a stoa with correct proportion?

  1. How does the signed distance sculpting pipeline turn a figure into a surface, and how is the same

library used for a 21 metre colossus and a 20 centimetre ornament?

  1. How does one still render move from camera to accumulated high dynamic range image to graded

pixel, and what does each sub-frame change?

  1. How do auto exposure and auto levels keep nine different framings in one narrow luminance band?
  2. How does the film reuse the shot cameras, and how do camera moves, shutter time and cross-dissolves

build motion blur?

  1. How do the reference images, colour statistics and side-by-side comparisons drive iteration?
  2. What does the quality preset change, and how does the project keep an integrated graphics

processing unit usable?

  1. What does the project say it cannot do, and where does the static reading stop?

9. Limits

  • Static reading only. No pixel was rendered and no frame was viewed.
  • The reference images and the media images are not compared here. Their numbers come from the code and

the documents.

  • No browser was opened. The WebGL behaviour, the shader compiles and the timings are not verified.
  • The far terrain grid in generated/terrain-far-v11.bin is binary and was not decoded.
  • The bake tools were not run. Their outputs are not checked.
  • The build process is a project statement. It is not reproducible here.
  • The render harness names Windows browser paths. The checkout was read on macOS, so the harness paths

do not match this machine.

10. Corrections and limits found during research

The inventory matched: pin 9b8bd23, 220 tracked files, version 0.1.0, MIT. The following findings qualify the first reading.

  1. The "57 waterfalls" figure is a runtime log value, not a constant. src/world/layout.js:154-179

lists 17 waterfall specifications. src/modules/waterfalls.js:1 adds every engine.registry.aqueductSpills entry. The module logs the final count at src/modules/waterfalls.js:293. The figure 57 comes from one build run (README.md:14).

  1. The "149k trees" figure is a runtime scatter result, not a constant. The scatter module scales

the count by quality.density and by the vegDensity parameter (src/vegetation/scatter.js:54). A preview build and a high build do not hold the same count.

  1. "168 modules" counts JavaScript files only. git ls-files src holds 168 .js files and 4

.mjs helper scripts. The .mjs files are preview, visualisation and worker helpers, not world modules. The count in README.md:34 is correct for .js.

  1. The film has eight segments, not nine. The header comment in src/video/sequence.js:1 says

"nine segments". The list at src/video/sequence.js:11-23 holds eight entries. The comment at :20-21 records that shot 3 was dropped because it hung the graphics processing unit in the video path. Eight segments at 30 frames per second with seven cross-dissolves give 54.3 seconds, which matches the 54 second film in README.md:33 after rounding.

  1. The podium height has two values. src/world/layout.js:28 says a 12 metre podium wall, and the

same comment gives a stylobate near 67.5 metres above a 54 metre plateau, which is 13.5 metres. docs/COMPOSITION.md gives 13 metres. The source does not reconcile 12, 13 and 13.5.

  1. The render harness browser paths are Windows paths. tools/render.mjs:50-52 and

tools/render-video.mjs:37 search C:/Program Files/... for Chrome and Edge. The tool has no browser-path option, so a reader on another operating system must edit the fixed list. The project README names a Windows laptop (README.md:3).

  1. The film does not use every shot. Shot 3 has a camera and a look, but it is absent from

SEQUENCE. The film uses shots 1, 4, 2, 7, 6, 5, 8 and 9 in that order.

  1. The nine shots use different camera distances. docs/COMPOSITION.md:20-21 gives 210 to 240

metres for shots 3, 8 and 9, about 100 to 110 metres for shots 1 and 6, and about 260 metres for shot 2. A reader must not assume one camera rig for all shots.

  1. The plan holds a default sun, but each shot changes it. src/world/layout.js defines the

default sun direction. src/world/looks.js:54-75 gives every shot its own sun value through sunRel, and also its own sky, exposure and grade. The pipeline reads the per-shot values.

  1. The quality presets trade sample count against density. src/core/quality.js:4-27 gives

preview 1 sample per pixel and density 0.45, high 12 samples and density 1.0, and ultra 48 samples and density 1.0. The preview also disables ambient occlusion.

  1. The project records a multi-agent build. README.md:32 says 55 subagents, up to 12 in

parallel, and about 147 agent-hours. docs/PROMPT.md holds the prompt. The exploration records this as a project statement and does not verify it.

  1. The film needs two external items that the repository does not hold. The music is not in the

repository (README.md:81). The encoder calls ffmpeg from the command path (tools/render-video.mjs:147). The baked grid names also carry their version, as terrain-far-v11.bin shows (src/world/heightfield.js:15), and loadOrBuild fetches the name without a further version check (src/core/cache.js:63-66).
