04 -- Categories: eight buckets for 2,094 works

The catalog splits its 2,094 works into eight categories. Each record in cases.json carries one category slug in its category field. Each category has an English title, a Chinese title, and one Markdown list per language under cases/. This document names all eight categories, gives their counts, and explains how the cases/ directory is organized.

The category is a coarse label. It tells the reader what kind of work the post shows: a motion-graphics reel, a product demo, an explainer, a story, a 3D scene, a game, a production trick, or a model comparison.

What each category holds

  • motion collects motion-graphics reels and animated user-interface (UI)

work.

  • product collects product demos and mock advertisements.
  • education collects explainers and educational videos.
  • stories collects character-driven and narrative works.
  • art3d collects 3D worlds, scenes, and physics simulations.
  • game collects playable games and game prototypes.
  • production collects music, video editing, and production workflow pieces.
  • comparison collects posts that compare two or more models or tools.

The cases directory

The cases/ directory holds sixteen Markdown files: eight categories times two languages. The file names are {slug}.md for English and {slug}.zh-CN.md for Chinese.

%%{init: {"flowchart": {"htmlLabels": false}}}%% flowchart LR SLUG["one category slug"] --> EN["cases slug .md English"] SLUG --> ZH["cases slug .zh-CN.md Chinese"] EN --> TABLE["a table with one row per work"] ZH --> TABLEZH["the same table, translated titles"]

There are no subdirectories. It is a flat directory of sixteen files.

The format of a category file

Each category file has a fixed shape. The English motion file starts like this, from cases/motion.md lines 1-7:

# Motion graphics & UI

282 works, 89 with a prompt. Titles link to the original post on X; prompt links open the page with the original text and its source.

| Work | Model | Creator | Length | Prompt |
|---|---|---|---|---|
| [Portfolio data dashboard and animation](https://x.com/bindureddy/status/2112606220293193965) | Opus 5.5 | [@bindureddy](https://x.com/bindureddy) | 1:05 | — |

Three parts repeat in every file. Line 1 is the category title. Line 3 is the header sentence: the work count, the prompt count, and where the links point. Then a table follows, one row per work. The table has five columns: Work, Model, Creator, Length, Prompt.

The Prompt column shows one of three values. It shows an em dash — when the work has no prompt. It shows Brief or Full prompt when the work has one, linking to the jasonzhu.ai page.

Why comparison is the largest category

The comparison category has 376 works, more than any other. This is the category for posts that pit one model against another. Many of these posts name two or more models, which is why the multi-model works cluster here. Both records that list three models belong to comparison. The README's phrase "comparisons count for each" refers to this category: a comparison post adds a mention to each model it names. See 02-model-family.md.

The Aha Moment

Aha: The category is stored once, as a slug, and expanded in three places. The README turns the slug into a section heading and a highlight table. The cases/ file turns it into a full list. The record keeps only the slug. The slug is the join key between the data and the prose, and the eight slugs are a closed set, so a script can group all 2,094 records by category and rebuild the directory structure from scratch.
