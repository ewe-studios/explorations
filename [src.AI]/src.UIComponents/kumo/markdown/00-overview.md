# kumo: Cloudflare's Component Library

Cloudflare's production React component library built on Base UI and Tailwind CSS v4. 35+ components, 30+ primitives, blocks, CLI, and AI registry.

**Source:** `/home/darkvoid/Boxxed/@formulas/src.rust/src.AI/src.UIComponents/kumo/packages/kumo/`

## Architecture

```
src/
├── components/     ← 35+ styled components (Button, Dialog, Sidebar, Chart, etc.)
├── primitives/     ← 30+ Base UI wrappers (generated by codegen)
├── blocks/         ← Composite page patterns (DeleteResource, PageHeader, ResourceList)
├── utils/          ← cn(), link-provider, portal-provider
├── registry/       ← Component metadata, AI schemas
├── catalog/        ← Component catalog system
├── code/           ← Syntax highlighting (Shiki)
├── command-line/   ← CLI (ls, doc, docs commands)
├── styles/         ← CSS build outputs
└── ai/             ← component-registry.json, schemas
```

## Installation

```bash
npm install @cloudflare/kumo
# Peer deps: react, react-dom, @phosphor-icons/react
# Optional: echarts (charts), zod (validation)
```

## Usage

```tsx
// Granular import (tree-shakable)
import { Button } from "@cloudflare/kumo/components/button";
import "@cloudflare/kumo/styles";

// Or barrel import
import { Button, Dialog, Sidebar } from "@cloudflare/kumo";
```

### Emphasis Token System

```typescript
const getEmphasisToken = (variant: KumoButtonVariant) => {
  if (variant === "primary") return "var(--color-kumo-brand)";
  if (variant === "destructive") return "var(--color-kumo-danger)";
  return undefined;
};

const getEmphasisStyle = (variant: KumoButtonVariant) => {
  const token = getEmphasisToken(variant);
  if (!token) return undefined;
  return {
    "--kumo-button-emphasis-ring": `color-mix(in oklch, ${token}, black 10%)`,
    "--kumo-button-emphasis-bg": `color-mix(in oklch, ${token}, white 30%)`,
    "--kumo-button-emphasis-gradient-start": `color-mix(in oklch, ${token}, white 15%)`,
    "--kumo-button-emphasis-gradient-end": token,
  };
};
```

**Aha:** Primary and destructive buttons use CSS `color-mix()` for gradient backgrounds. The emphasis style is computed as CSS custom properties and applied inline, so buttons automatically adapt to theme changes without needing separate dark variant classes.

### Discriminated Union for Accessibility

```typescript
type ButtonWithTextProps = ButtonBaseProps & {
  shape?: "base";
  icon?: Icon | React.ReactNode;
};

type ButtonWithIconProps = ButtonBaseProps & {
  shape: "square" | "circle";  // Required
  "aria-label": string;         // Required for accessibility
  icon: Icon | React.ReactNode;
};

export type ButtonProps = ButtonWithTextProps | ButtonWithIconProps;
```

Icon-only buttons (square/circle shapes) require `aria-label` — enforced by TypeScript.

## Theming: No `dark:` Variant

Kumo forbids Tailwind's `dark:` variant entirely, using CSS `light-dark()` instead:

```css
/* Generated by theme codegen */
--kumo-base: light-dark(#ffffff, #1a1a1a);
--kumo-text: light-dark(#1a1a1a, #ffffff);
```

Enforced by custom ESLint plugin (`lint/no-tailwind-dark-variant.js`).
