User-interface games and procedural models

This page is the shared index for explorations of small user-interface projects and the tools around them. The first entry is img2threejs, an agent skill that turns one reference image into a TypeScript factory for a Three.js model. Each exploration lives in its own directory with its own documents, its own index, and its own generated HyperText Markup Language (HTML) tree.

The output is an ObjectSculptSpec JavaScript Object Notation (JSON) file and a TypeScript THREE.Group factoryOverview, then the skill contract

The short answer

img2threejs answers a narrow question: can an agent build a faithful Three.js model from one image without spending model tokens on bookkeeping? The answer is a split. The agent looks and decides. Scripts measure and refuse. The split is why the project is small in runtime terms and why its quality depends on the gates, not on the model alone.

What makes it different from a rendering tool

A renderer takes a scene and produces pixels. img2threejs takes one image and produces a scene description plus code that rebuilds the scene at run time. The render is only evidence. The artifact that ships is text.

Reading order

A reader who wants the system shape should read the img2threejs overview, then repository anatomy. A reader who wants to run or extend the pipeline should read forge orchestration through rig and character. A reader who wants to judge the quality claims should read review, grimoire, and limits and findings.

What this index does not claim

The exploration did not run the pipeline. It did not generate a model, render a sheet, or call a host agent. Every statement comes from the source at the pinned commit, the tests, the reference library, or the project documents. Where the source and a project document disagree, the exploration names both and follows the source.
