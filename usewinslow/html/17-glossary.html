Glossary

This glossary defines the terms used across this documentation set. Terms are grouped by domain, not alphabetically, because the meaning of a term depends on the system it belongs to. Each entry gives the shortest accurate definition and, where useful, the place to read more.

Abbreviations are spelled out at first use. Some words carry more than one meaning in this product, so the domain is stated where it matters. "plan" is an insurance product in benefits and a pricing package in commercial terms. "tier" is a coverage level in benefits and a plan level in pricing.

The public record means the publicly reachable Winslow web pages, the product's own /winslow.md file, and the compiled application bundle, captured on 2026-11-06. A citation such as winslow.md:57 refers to that capture.

Core terms

TermDefinition
WinslowAn artificial-intelligence (AI) native Human Resources (HR) platform from NFTCo, Inc. It sells payroll, benefits, a Human Resources Information System (HRIS), and a Slack-based AI co-worker as one product.
WorkspaceOne customer tenant: the company account that holds employees, payroll, plans, and settings.
CustomerThe company that buys Winslow. A customer owns one or more workspaces.
Workspace memberOne user account in a workspace. A member may or may not have an employee record.
EmployeeA worker on the payroll. Each employee has one employee record.
EmployerThe customer, in its role as the payer of wages and the sponsor of benefit plans.
PlanTwo senses. In benefits, an insurance product that a carrier sells, with a plan type, a tier, and rates. In commercial terms, a pricing package such as Free, Team, or Scale. This page writes "plan" alone only where the sense is clear, and writes "benefit plan" or "pricing plan" where it is not.
TierTwo senses. In benefits, a coverage level such as employee only or family. In commercial terms, a level of the pricing package. The page writes "coverage tier" or "plan level" to separate them.

The agent is the AI co-worker. The AI co-worker is the employee-facing name; the Winslow Agent is the builder-facing name. All three names refer to one cloud runtime. The name shown to a reader depends on the page.

Platform terms

TermDefinition
Admin interfaceThe browser application at app.usewinslow.com. It is one client of the employee record, not the record itself. The other clients are the agent, the Model Context Protocol (MCP) server, and the REST interface.
AgentThe dedicated cloud runtime that a customer and its employees talk to in Slack. It has skills, a scheduler, event subscriptions, memory, personas, and connectors.
AI co-workerThe employee-facing name for the agent.
ArtifactA named data object attached to an employee record. Every artifact has an employee record identifier, an application identifier, a type, and a typed payload. The seven types are TEXT, MARKDOWN, IMAGE, FILE, JSON, CARD, and URL.
Artifact appA registered namespace for artifacts and custom properties. It is not an installed application, although the documentation uses the word "app" for both.
ConnectorAn external tool that the agent can call. Connectors come from the Pipedream directory or from a customer-managed MCP server. A connector is not a Winslow tool; it is a tool that the agent reaches outward to use.
Custom propertyA typed field added to the employee record. Its label is prefixed with the application identifier and a hyphen, so an application named performance-review with the label review-cycle stores the label performance-review-review-cycle. There are 14 types, listed in the HRIS.
Employee recordThe object that holds system fields, custom properties, and artifacts for one employee. It is the system of record for employment data.
Event subscriptionA saved instruction that runs an agent prompt when a Winslow event fires.
HRISHuman Resources Information System. The product category for software that holds the employee record. Winslow's HRIS covers the record, documents, the organization chart, time off, and the audit log.
MemoryFacts the agent keeps for a person or a company across conversations and tasks. Markdown is a plain-text format with light markup. Memory can be exported as Markdown.
PersonaA scoped agent identity with its own knowledge base, tone, and behaviour. A knowledge base is the set of documents that the agent searches.
SchedulerThe part of the agent that runs tasks on a time rule, such as "first payroll of the month" or "first Monday".
SequenceDurable state for multi-step agent work. Statuses are NEW, AWAITING, NUDGED, ESCALATED, COMPLETED, and CANCELLED. NUDGED means a reminder was sent; ESCALATED means the work was raised to a person.
SkillA Markdown playbook that the agent follows. Skills are versioned, so an older version can be kept or replaced, and they are shared across a workspace.
Vibe appAn application that a customer builds outside Winslow and mounts inside it. It appears in the sidebar and calls Winslow through MCP or REST.
Winslow ForwardA forward-deployed People Operations engineer, sold at $5,000 per month per engineer. "Forward-deployed" means the engineer works inside the customer's team rather than in a support queue.

Protocol and API terms

TermDefinition
APIApplication Programming Interface. A contract that lets one program call another.
API keyA workspace credential with the prefix wns_. It acts as the member who owns it. It is accepted on the MCP endpoint and rejected on REST.
AUTH_DENIEDThe error code for a failed scope or relationship check. The data.kind field says scope or relationship.
Bearer tokenAn OAuth access token sent in the Authorization header. REST requires it.
Field visibilityThe value of the fieldVisibility field on a response. It names the projection that was applied.
JSON-RPCJavaScript Object Notation Remote Procedure Call. The message format for MCP.
MCPModel Context Protocol. An open protocol that connects an artificial-intelligence application to tools and data.
MCP serverThe Winslow-hosted server at https://api.usewinslow.com/api/mcp. External clients call it to use Winslow tools. A customer-managed MCP server is the opposite direction: an endpoint that the customer hosts and the Winslow agent calls as a connector.
OAuth 2.0The authorization framework behind "Login with Winslow." It issues user-scoped access tokens.
PipedreamThe integration platform behind Winslow's connector directory. Winslow reaches long-tail applications through it instead of building each connector.
PKCEProof Key for Code Exchange. A security extension for public OAuth clients, meaning clients that cannot keep a secret, such as a browser application. The server supports S256, the SHA-256 challenge method.
ProjectionThe field set that a response contains, decided by the caller's relationship to the subject. The four values are: FULL for an administrator; SELF for the subject; DIRECT_REPORT for the subject's manager; and PUBLIC for any other workspace member, which returns directory fields only.
RelationshipThe link between the caller and the target record. The allowed values are self, direct manager, and administrator.
RESTRepresentational State Transfer. The plain Hypertext Transfer Protocol (HTTP) interface at api.usewinslow.com, under /api/employee-records/, /api/employee-artifacts/, and /api/artifact-apps/*, plus workspace paths such as the event-trigger route.
ScopeA named permission such as payroll:approve. There are 25 MCP scopes and 7 OAuth scopes. The two sets use different naming conventions and the mapping is not published.
Streamable HTTPThe MCP transport, meaning the way messages travel between client and server. It supports JSON responses and server-sent events.
ToolOne callable operation on the Winslow MCP server. The catalog has 185. A connector is a separate object: it is an external tool that the agent calls.
x-client-tokenA Universally Unique Identifier version 4 (UUID v4) header required on REST calls. The reason for it is not documented, and the source of the value is not documented.

The block below is part of the OAuth authorization-server metadata that the discovery endpoint returns. scopes_supported lists the scopes a client may request, and code_challenge_methods_supported lists the accepted PKCE methods:

{
  "scopes_supported": [

    "write:employees",

The seven OAuth scopes above are not the 25 MCP scopes. The mapping between the two is not published. Read the MCP server for the authorization model.

The authorization chain

Three terms are easy to confuse:

  • A scope says what kind of action is allowed.
  • A relationship says which record the action may touch.
  • A projection says which fields may return.

The payroll run

A payroll moves through draft, calculation, refresh, review, approval, and payment. Approval is the only step that starts payment, and it has its own scope. The debit leaves the company bank account on the funding date, which falls before the pay date. A refresh recalculates a run and reports its status; a compare shows what changed between two refreshes; a review is the check a person makes before approval.

The benefits election

An election starts as PENDING. It becomes ELECTED or WAIVED. An ELECTED election can go to IN_REVIEW and back to ELECTED. It becomes CONFIRMED when the carrier returns a member identifier. A CONFIRMED election or a WAIVED election becomes FINALIZED at the end of open enrollment. Finalization is what sends the deduction to payroll; a waived election sends nothing.

Aha: The vocabulary itself shows where the product is unfinished. The data terms are precise. A reader can look up fieldVisibility, DIRECT_REPORT, FINALIZED, and AUTH_DENIED and find one exact meaning for each. The commercial terms are not precise. One word, "app," means an artifact app namespace and also an installed vibe app. Six plan names, described on four different pages, describe what is probably three pricing plans. A reader can trust the data terms and must check the commercial terms against a written quote. That split is the clearest signal of which parts of Winslow are engineered and which parts are still being marketed.
