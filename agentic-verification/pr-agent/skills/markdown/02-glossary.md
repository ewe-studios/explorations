# Glossary

| Term | Meaning |
|------|---------|
| Adversarial pass | A review whose goal is to find errors rather than agree, returning CORRECT, WRONG, or OVERSTATED per claim (`SKILL.md:87-97`) |
| Baseline | The count of passing tests before a change, used as a reference for the revert check |
| Confidence | A number from 0 to 10 stating how sure the draft is, shown in the presentation table |
| Continuous integration (CI) | Automated builds and tests that run when code is pushed |
| GraphQL | Graph Query Language, a query language for the GitHub application programming interface (API) |
| Hunk header | A line in a diff (`@@ -1,370 +1,386 @@`) that states the file position of a change |
| Maintainer | A person with permission to merge, close, or comment on the repository |
| Pull request | A proposed change to a repository that waits for review and merge |
| Secure Hash Algorithm (SHA) | A fixed-length hash that names a specific commit |
| Skill | A Markdown file of instructions an agent loads for one kind of task |
| Verbatim | Exactly as written, with no change |
| Worktree | A second checkout of the same repository, isolated from the main one |
| `uv` | The Python package and environment manager PR-Agent uses for its own builds |
| `gh` | The GitHub command-line tool used to read and change issues and pull requests |
