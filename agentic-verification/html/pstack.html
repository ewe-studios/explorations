Project Exploration: pstack, a plugin for rigorous agent workflows

Overview

pstack is a Cursor and Claude Code plugin by Lauren Tan (poteto), version 0.15.36, under the MIT license. Its tagline is if you want to go fast, go deep first — a working method for shipping quality software. It packages 58 skills (24 principles plus 34 workflow skills), 2 subagents, 23 playbooks, and a statechart formal-verification tool.

The one idea: throughput without quality is not the goal. Write less, but higher-quality code, and get fearless parallelism by trusting an agent that holds a high bar. See Overview.

The philosophy in one minute

The 24 principles are grouped into core (how to think), architecture (how to shape), verification (how to prove), delegation (how to fan out), and meta (make rules structure). Three through-lines hold them together: verify against the real artifact; structure beats prose; converge before you build. The poteto-mode skill indexes all 24 inline so a delegate reads every rule in one file. See Philosophy and principles.

The verification spine

A repeated theme runs through pstack: verify against the real artifact, not a proxy. prove-it-works states it; the verification skills make it a tool. create-verification-skill generates a project-local verify skill with a feature map; create-formal-verification-skill handles cases tests cannot reach — races, retries, and state machines — with a model checker; statechart checks a TLA+ model and draws the states that break a rule. See Verification skills.

The statechart tool

The most substantial component is a TypeScript tool that drives TLC (the TLA+ model checker), finds every state that violates an invariant, and draws a Mermaid statechart coloring breaks versus mayBreak states. It verifies the drawing against the model bidirectionally (regionsLie) and escapes Mermaid input as hostile text. See The statechart tool.

Confidence as a first-class type

why's references/epistemics.md turns epistemic honesty into five tiers — Direct, Supported, Inferred, Speculative, Unknown — each with its own phrasing. "Because" is banned in inference, "obviously" is banned outright, and "an honest we-don't-know is one of the most valuable outputs." See Understanding and evidence.

The five most important ideas

  1. Confidence is a typed tier. Five levels, each with phrasing rules, so a claim cannot sound more certain than its evidence.
  2. Structure beats prose. encode-lessons-in-structure and the fix ladder (architecture → types → lint → test → docs) make the wrong thing impossible in the repo, not discouraged in a document.
  3. Verify against the real artifact. A writeup reads as convincing whether or not it is true; the check must run the real thing.
  4. The cross-judge is a different family. A judge from the parent's own model family shares its biases, so arena forces a different one.
  5. A real formal-verification tool ships in a skills plugin. The statechart tool drives TLC, colors violating states, and honestly reports when a chart cannot be drawn faithfully.

Verdict

A strong, coherent, opinionated method with real implementation behind it. The philosophy and the epistemics are portable and free to copy; the costs are a whole vocabulary (58 skills, 23 playbooks), hardcoded model slugs, and a high barrier to the formal-verification tool. Aha: the plugin's credibility comes from the fact that its rules are backed by scripts that fail loudly — the statechart tool, check-plan.mjs, and log.sh are the proof of the prose. See Critical assessment.
