23 -- Supporting Crates: The Belt, the Bridge, and the Bake Step

Proa's "render is serialization" discipline does not stop at the render core. The six supporting crates apply the same build-time-vs-runtime split to everything that surrounds a component: harden the markup boundary at compile time (proa_html_policy plus the validation pass inside proa_dsl), generate the JavaScript half of an island from a single component definition (proa_codegen and proa_react), and bake class merging and JSON serialization into const fn so they never run on a request (proa_tailwind_merge and proa_const_json). None of them is a render trait, yet each one removes work from the hot path: the belt rejects XSS before any byte is emitted, the bridge turns one manifest into matching server markup and client modules, and the bake step turns runtime computation into static data embedded in the binary.

CrateLinesRole

`proa_const_json` (+ proc macro)~1,140`const fn` JSON serialization plus a zero-copy, allocation-free parser

The dependency direction is the same discipline as the fonts and docs pipelines: crates that do real work (proa_dsl, proa_codegen) run at build time and are dependencies of proa_macros, while crates that sit in the serving binary (proa_html_policy, proa_react, the const halves of the last two) are small, #![no_std]-friendly, and infallible.

Part 1 -- proa_html_policy: One Function, Three Escapes

The entire public surface of proa_html_policy is one function. It is #![no_std], #![forbid(unsafe_code)], marked #[inline] so release builds fold it into elem::write_attr, and it exists because a naive starts_with("javascript:") check is defeated three distinct ways. The function returns true when a URL value is dangerous and should never be written to href, src, action, or any other URL-bearing attribute:

// proa_html_policy/src/lib.rs (shape, abbreviated)
#[inline]
pub fn has_dangerous_url_scheme(url: &str) -> bool {
    // 1. javascript: / vbscript:  (ASCII case-insensitive)
    // 2. data: whose MIME is one of the executable set:
    //    text/html, application/xhtml+xml, application/xhtml,
    //    application/xml, image/svg+xml   (svg can carry <script>)
    // 3. all checks run on a normalized cursor that skips ASCII
    //    whitespace + NUL and decodes numeric character references
}

The three escapes it defends against, each with a source reference in the doc comment:

  1. Scheme case. JavaScript:, VBScript: — matched case-insensitively.
  2. Control characters in the scheme prefix. WHATWG URL §4.3 directs browsers to strip tab, LF, and

CR before parsing, so java\tscript:alert(1) and \njavascript:alert(1) still navigate. A NormalizedAsciiCursor skips ASCII whitespace (space, tab, LF, CR) and NUL throughout the prefix, not just at the leading edge.

  1. Numeric character references. The HTML5 parser decodes &#NNN; and &#xHH; in attribute values

before URL parsing, so javascript:alert(1) smuggles past a string-prefix check. This is the exact bypass behind CVE-2026-39315 (Unhead hasDangerousProtocol()). decode_numeric_entity runs one pass with no digit cap, optional semicolon, saturating arithmetic, and maps 0, >0x10FFFF, and surrogates to U+FFFD; a non-ASCII decoded code point is treated as a non-match because it cannot spell an ASCII scheme or MIME type.

flowchart TD A["raw URL value"] --> B["NormalizedAsciiCursor<br/>skips space/tab/LF/CR/NUL"] B --> C["decode_numeric_entity<br/>&#NNN; / &#xHH; / &#XHH;"] C --> D{"prefix is<br/>javascript: / vbscript:?"} D -->|"yes"| X["return true (blocked)"] D -->|"no"| E{"prefix is data: and MIME<br/>in executable set?"} E -->|"yes"| X E -->|"no"| F["return false (allowed)"]

The function is called from elem::write_attr on every URL-bearing attribute in the hot render path, which is why the whole crate is #![no_std] and #[inline]: the security check must not allocate and must not survive as a function call the optimizer cannot see through.

Part 2 -- proa_dsl: The Template Language Shared by Both Macro Families

proa_dsl is the front end every Proa template macro (html!, html_sync!, md!, md_sync!) shares. It owns the grammar, the AST, the consolidation walk that folds adjacent static markup into byte runs, and the validation pass that turns template mistakes into compile errors or #[must_use] warnings. The entry point is parse_str, which returns a HtmlRoot; the node grammar is deliberately small:

// proa_dsl/src/ast.rs (shape, abbreviated)
pub enum Node {
    Element(Element),
    Fragment(Vec<Node>),
    Text(LitStr),
    Block(Expr),          // a {dynamic} expression in child position
    Doctype(String),
}

pub struct Element {
    pub name: MarkupName,
    pub attrs: Vec<Attribute>,   // Static | Dynamic | Bool
    pub children: Vec<Node>,
    pub self_closing: bool,
    pub opening_end: proc_macro2::Span,
}

pub enum Attribute {
    Static { name: MarkupName, value: LitStr },
    Dynamic { name: MarkupName, value: Box<Expr> },
    Bool { name: MarkupName },
}

Parsing is parameterized by a ParseMode { Html, Xml } that changes case handling, boolean-attribute spelling, and void-element lists (HTML void elements vs the SVG void set). What the parser produces is then walked once by consolidate::walk::consolidate_root, which emits a representation-neutral event sequence into a ConsolidationSink rather than directly producing TokenStream:

// proa_dsl/src/consolidate/sink.rs (shape, abbreviated)
pub trait ConsolidationSink {
    fn static_run(&mut self, pre_escaped: &str);          // one run per static region
    fn dynamic_node(&mut self, expr: &Expr);              // a {expr} in child position
    fn dynamic_attr(&mut self, attr: DynamicAttr<'_>);    // name={expr}
    fn begin_raw_text(&mut self, kind: RawTextKind);      // <script> / <style>
    fn end_raw_text(&mut self, kind: RawTextKind);
}

This seam is what lets one walk drive two emitters: the TokenStream emitter in proa_macros::static_consolidation::emit_tokens for the macro path, and any downstream program emitter that serializes the same events as data. DynamicAttr carries four fields — name_prefix, bool_form, value, and is_url_position — so emitters never re-derive dialect rules; the walk decides that href/src/action is a URL position and the emitter must apply runtime dangerous-scheme validation (CVE review Gap O). The walk accumulates static bytes in one String and flushes exactly at dynamic boundaries, so a fully static template produces exactly one static_run.

flowchart TD A["parse_str(src, ParseMode)"] --> B["HtmlRoot AST<br/>Node / Element / Attribute"] B --> C["consolidate_root<br/>single walk, one String accumulator"] C --> D["compile-time escape<br/>escape_text/attr_compile_time"] D --> E["event stream:<br/>static_run / dynamic_node /<br/>dynamic_attr / raw_text"] E --> F["ConsolidationSink impl"] F --> G["proa_macros emit_tokens<br/>(TokenStream)"] F --> H["program emitter<br/>(serialize as data)"]

The validation pass (validate_security / validate) walks the same AST and enforces four rule families. URL attributes are whitelisted in URL_ATTR_NAMES (13 entries — href, src, action, formaction, poster, ping, cite, data, background, longdesc, manifest, plus both xlink:href and xlink-href; srcset is deliberately excluded because its comma-separated grammar is not a single URL). Any without an explicit rel gets noopener injected or merged. Raw-text content (textarea, title, xmp, noscript, noframes) and foreign-content roots (svg, math, foreignObject) trigger content-mode switching and mutation-XSS warnings. ARIA is checked against VALID_ARIA_ROLES (82), ABSTRACT_ARIA_ROLES (12), VALID_ARIA_ATTRS (51), and six prohibited elements (meta, head, style, script, col, colgroup) that may carry no role or attribute. A performance pass (gated by the no-perf-hints feature, each warning suppressible with perf_ok(...)) flags nine allocation patterns in the render hot path — format!(), vec![], .to_string(), .to_owned(), .join(), .collect(), String::from(), a string literal in braces, and a dynamic attribute holding a literal value.

Part 3 -- The JavaScript Bridge: proa_codegen and proa_react

Where proa_dsl handles the server side of a component, proa_codegen and proa_react handle the client side. proa_codegen takes a JSON manifest of component definitions and emits a TypeScript tree — a CVA-style recipe plus a typed React component per component. The manifest shape is the four structs below; ComponentType selects the rendered element (Button by default, or Svg):

// proa_codegen/src/types.rs (shape, abbreviated)
pub struct ComponentDef {
    pub name: String,
    pub base_classes: String,
    pub variants: Vec<VariantDef>,
    pub component_type: ComponentType,   // Button (default) | Svg
}

pub struct VariantDef {
    pub name: String,          // e.g. "size"
    pub enum_name: String,     // e.g. "Size"
    pub default_value: String,
    pub options: Vec<VariantOption>,
    pub optional: bool,
}

pub struct VariantOption {
    pub name: String,          // "sm"
    pub value: String,         // "sm"
    pub classes: String,       // "text-sm px-2"
}

TsGenerator lowers each ComponentDef into lib/utils.ts (a cn helper over clsx), a metadata.json, a manifest.ts, a per-component directory holding recipe.ts (the CVA recipe), {Name}.tsx (the component), and index.ts re-exports. The component props interface extends React.ComponentPropsWithoutRef<'button' | 'svg'> plus VariantProps, and the component body branches on ComponentType for Spinner/Button special cases. CodegenConfig controls React version and two flags, with three presets: react_18() (forwardRef), react_19() (ref-as-prop, named functions), and shadcn_v4() (the shadcn/ui v4 pattern). The CLI is proa-codegen --input [--output generated] [--react 18|19] [--no-data-slot].

proa_react renders the runtime half. ReactBootstrapConfig's defaults show the design intent — an external React runtime behind an import map for cross-page caching, and a single global trigger:
