07 -- The HTML Macros

The html! family is a compile-time pipeline with four stages: parse, validate, consolidate, emit. The key idea is a seam. A walk over the template produces a linear event sequence. A separate sink turns that sequence into Rust code. The walk never sees tokens. The emitter never walks. Every macro in the family is the same walk into a different sink.

The Macro Family

Eight macros share this pipeline. They differ only in dialect, async mode, and whether they also build a component tree.

Every HTML entry point does the same two things. It parses the input into an HtmlRoot, then runs validate_security. The validator returns either compile errors or a stream of warnings. The entry point then hands the root to its emitter.

// proa/proa_macros/src/lib.rs:156
#[proc_macro]
pub fn html_sync(input: TokenStream) -> TokenStream {
    let root = parse_macro_input!(input as HtmlRoot);

    let warnings = match static_consolidation::validate_security(&root) {
        Err(errors) => return TokenStream::from(errors),
        Ok(w) => w,
    };

    let expanded = static_consolidation::generate_optimized(&root);

    TokenStream::from(quote::quote! { { #warnings #expanded } })
}

The html! and html_send! entries are identical except for the emitter call. The xml! entries parse XmlRoot and call validate_xml, which skips HTML-only rules because XML vocabularies are application-defined. The html_hot_sync! entry parses a HotInput and switches emitter based on the PROA_DEV_HOT_STATIC environment variable. Without that variable it emits the ordinary consolidated path, so hot mode has no cost outside development.

Stage 1: Parse

The parser lives in proa_dsl/src/parse.rs. It turns template tokens into an AST with five node kinds.

// proa/proa_dsl/src/parse.rs:48
pub enum Node {
    Element(Element),
    Fragment(Vec<Node>),
    Text(LitStr),
    Block(Expr),
    Doctype(String),
}

Element (line 62) holds a MarkupName, an attribute list, a child list, and a self_closing flag. Attribute (line 155) has three shapes: Static { name, value: LitStr }, Dynamic { name, value: Box }, and Bool { name }. A Block(Expr) is a {expr} interpolation. A Fragment is the <>... grouping form.

MarkupName (line 96) is the subtle type. It keeps two spellings of the same name. The first is the raw source form, rsjs-island or svg:path. The second is a legacy identifier form where dashes and colons become underscores. Emitters read the raw form. Older consumers read the identifier form. This split lets hyphenated custom elements and namespaced SVG attributes survive the parser while existing code keeps working.

Parsing is recursive descent. parse_node (line 215) peeks at the next token. A < begins an element or fragment or doctype. A string literal is a text node. A { begins a block expression. parse_element (line 355) reads a tag name, then attributes, then either a self-closing slash or children until a matching closing tag. is_void_element (line 327) knows the void set so
and both work. parse_attribute (line 478) distinguishes the three attribute shapes by whether the name is followed by = and whether the value is a literal or a brace.

The parser is shared by every macro, which is why it lives in proa_dsl and not proa_macros. The runtime template compiler in later documents parses the same AST.

Stage 2: Validate

validate_security (proa_dsl/src/consolidate/mod.rs:335) is the security boundary. It returns Result. The Err side is a list of hard compile errors. The Ok side is a stream of soft warnings. A hard error aborts compilation. A warning lets compilation succeed but prints a lint.

The warning mechanism is worth understanding because stable Rust limits it.

// proa/proa_dsl/src/consolidate/mod.rs:96
pub struct Warning {
    pub span: proc_macro2::Span,
    pub title: String,
    pub message: String,
}

Warning::into_tokens (line 133) generates a #[must_use = "message"] struct at the warning's span. When nothing consumes that struct, rustc's unused_must_use lint fires and prints the message with file, line, and column. The block wraps itself in #[warn(unused_must_use)] so the lint fires even if the caller crate allowed it. This is the best possible output on stable Rust, which lacks the proc_macro_diagnostic API. The doc comment tracks that stabilization as issue 54140.

The validator checks several rule families. The order of names here matches the validator call graph, not a priority ranking.

URL schemes. is_url_attr_name (line 189) matches thirteen URL-bearing attributes: href, src, action, formaction, poster, ping, cite, data, background, longdesc, manifest, xlink:href, and xlink-href. srcset is deliberately absent. Its comma-separated url descriptor grammar is not a single URL, so a whole-string scheme check would be defeated. A static value that is_dangerous_url_value flags (line 247, a re-export of proa_html_policy::has_dangerous_url_scheme) is a compile error. That check blocks javascript:, vbscript:, and executable data: schemes per OWASP XSS Rule #7.

Event handlers. is_event_handler_attr_name (line 236) matches on followed by ASCII letters. A dynamic value in an event handler runs as script, so attribute escaping cannot make it safe. The validator rejects dynamic values there.

Raw text. is_raw_text_element (line 320) names textarea, title, xmp, noscript, and noframes. A dynamic value inside one of these can break out of the element's raw-text parsing mode. The validator rejects that.

Foreign content. is_foreign_content_root (line 332) names svg, math, and foreignObject. These are mutation-XSS vectors in browsers. The validator applies stricter rules inside them.

Content model and ARIA. validate_element (line 884) checks nesting, child restrictions, and child ordering. validate_attribute_semantics (line 846) checks attribute meanings.
