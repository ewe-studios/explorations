Proa Documentation

Proa is a Rust server-side rendering framework that compiles HTML templates authored in Rust into pre-escaped byte sequences at compile time, streams them over a chained-bump buffer, and hydrates interactive islands via the RSJS Rust-to-JavaScript compiler. This is the complete reference: 27 documents that trace a component from WebRenderSync through html_sync! to emitted bytes, then follow the bytes through streaming, islands, and out to the browser.

The guiding idea throughout is that rendering is a serialization problem, not a component-tree reconstruction problem: emit as much HTML and as little JavaScript as possible, as fast as possible, from one typed, compiled source of truth that renders as HTML for people, targeted behavior for browsers, and dense machine-readable output for agents.

How to read this

Each document teaches its key idea in the first paragraph, then goes deeper through numbered Part dividers. Mermaid diagrams render every process; code snippets carry a // path header pointing at the exact source file they abbreviate. Every document ends with an Aha Moment (the one insight the chapter exists to deliver), a Cross-References section, and a Continue to footer that chains the set into a single reading order.

The source of truth is the code. Every name, number, and flow in these pages was checked against the Rust source in the Proa repository, and the rendered HTML is produced by build.py (Python 3 stdlib only): cd /Users/darkvoid/Dev/explorations && python3 build.py proa.
