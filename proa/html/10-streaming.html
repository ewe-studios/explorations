10 -- Streaming: Suspense, Drivers, and Page Pool

Streaming in Proa is a scheduling problem, not a serialization problem. The shell renders first. Each deferred boundary renders into its own buffer. A driver polls all boundaries at once and emits whichever finish first. The wire format carries boundary HTML as base64 inside an inert template, so the browser swaps it in only when it is ready. This document covers the render mode, the boundary types, Suspense, the out-of-order and in-order drivers, the runtime script, and the page pool.

RenderMode and Priority

RenderMode (proa_core/src/render/mode.rs:9) selects how one request streams.

// proa_core/src/render/mode.rs:9
pub enum RenderMode {
    ChunkedInOrder,
    ChunkedOutOfOrder,
    #[default]
    Static,
    Agent,
}

Static renders the whole document into one buffer. ChunkedInOrder streams chunks in document order. ChunkedOutOfOrder detaches each boundary and emits them as they complete. Agent targets dense machine-readable output. as_str maps each to a snake_case string. from_header and from_query_param parse friendly aliases like in-order or out_of_order.

Priority (proa_core/src/render/priority.rs:14) orders ready boundaries, not their starts.

// proa_core/src/render/priority.rs:14
pub enum Priority {
    #[default]
    Critical,
    Optional,
    Defer,
}

All boundaries start concurrently. Priority never delays or serializes work. When several complete in the same driver turn, Critical is emitted before Optional, then Defer. Equal priorities use their boundary id. priority_rank collapses the enum to 0, 1, 2 for sorting.

The Boundary Model

The boundary types live in proa_core so WebContext and Suspense can schedule deferred work without depending on proa_stream. PendingBoundary is the scheduled work.

// proa_core/src/render/stream.rs:75
pub struct PendingBoundary {
    pub id: u64,
    pub future: PendingBoundaryFuture,
    pub priority: Priority,
    pub timeout: Option<Duration>,
}

PendingBoundaryFuture is a Pin> + 'static>>. SendPendingBoundary is the same shape with a Send future, kept as a separate type. A local future cannot be relabeled into the send path through type erasure. This is the compiler proof the direct streaming path relies on.

RenderedBoundary is the successful output of one detached branch.

// proa_core/src/render/stream.rs:27
pub struct RenderedBoundary<B = crate::RenderBuffer, N = PendingBoundary> {
    pub html: B,
    pub artifacts: RenderArtifacts,
    pub nested: Vec<N>,
}

The html and its artifacts travel together. A stream driver can publish exact RSJS and React deltas only after the boundary commits. nested holds boundaries discovered while rendering the detached branch. They stay speculative until their parent is published, so a nested update cannot arrive before its placeholder exists in the DOM.

Two recorder traits schedule boundaries. StreamBoundaryRecorder (stream.rs:157) has next_boundary_id and push_boundary. SendStreamBoundaryRecorder is the Send variant. Two transport traits flush chunks. StreamChunkView (stream.rs:174) exposes ordered slices without a contiguous copy. StreamChunkFlusher (stream.rs:209) has flush_chunk and a default flush_chunk_view that flattens.

StreamContext and Identity

StreamContext (proa_stream/src/context.rs:17) is the request-scoped registry.

// proa_stream/src/context.rs:17
pub struct StreamContext {
    handle: Arc<StreamHandle>,
    mode: RenderMode,
    pending_boundaries: Rc<RefCell<Vec<PendingBoundary>>>,
}

It implements StreamBoundaryRecorder. next_boundary_id delegates to the shared StreamHandle::next_token. push_boundary appends to the RefCell vector. drain_boundaries_into moves newly registered work into a reusable staging vector, so nested boundary admission does not reallocate on every driver turn.

StreamHandle (proa_stream/src/handle.rs:10) pairs a RequestId with an AtomicU64 counter starting at 1. RequestId (proa_stream/src/request_id.rs:8) draws from a process-global AtomicU64 starting at 1. LocalBoundaryBranch (context.rs:84) is a branch-owned registry for a detached boundary that is still speculative. Nested futures do not enter the live scheduler until their parent commits.

SendStreamContext (context.rs:114) is the Send twin, using Arc>> instead of Rc>. The RefCell variant is deliberately single-threaded. The Send variant exists only for compiler-proved Send graphs.

Suspense

Suspense (proa_stream/src/suspense.rs:30) is one type with three personalities.

// proa_stream/src/suspense.rs:30
pub struct Suspense<C, Fb> {
    pub child: C,
    pub fallback: Fb,
    pub priority: Priority,
    pub timeout: Option<Duration>,
}

new defaults to Priority::Critical and no timeout. priority and timeout matter only in out-of-order HTML streaming. Buffered, in-order, and Markdown rendering preserve document order and ignore both, because reordering would break their wire contract and cancelling a flushed in-order child could leave partial markup on the wire.

The WebRender impl branches on mode. In ChunkedOutOfOrder with a recorder, it detaches the child.

// proa_stream/src/suspense.rs:142
if matches!(cx.render_mode(), RenderMode::ChunkedOutOfOrder) {
    if let Some(recorder) = cx.stream_recorder().cloned() {
        let boundary_id = recorder.next_boundary_id();
        let context_parts = cx.context_parts();
        let nested_stream = Rc::new(LocalBoundaryBranch::new(Rc::clone(&recorder)));
        // ...
        recorder.push_boundary(PendingBoundary::with_options(
            boundary_id,
            Box::pin(async move {
                let mut child_cx =
                    WebContext::<L, RenderBuffer>::with_loader_buffer_and_context_parts(
                        RenderBuffer::new(),
                        loader,
                        context_parts,
                    )
                    .with_render_mode(RenderMode::ChunkedOutOfOrder);
                child_cx.set_stream_recorder(child_stream);
                // render child, recover error fallback, commit artifacts
                let out = child_cx.into_output();
                let nested = nested_stream.take_boundaries();
                Ok(RenderedBoundary::with_nested(out, artifacts, nested))
            }),
            priority,
            timeout,
        ));
        // write start comment, fallback, end comment
        return RenderOutcome::Done(...);
    }
}

The detached child owns its RenderBuffer and its artifact delta. The only shared mutable state is the boundary registry. The shell gets a start comment, the fallback, and an end comment. The child's future is scheduled for later.

In ChunkedInOrder with a flusher, the child renders inline on the same context, flushing chunks.

// proa_stream/src/suspense.rs:204
if matches!(cx.render_mode(), RenderMode::ChunkedInOrder)
    && cx.stream_chunk_flusher().is_some()
{
    let pre_flush = cx.flush_stream_chunk();
    let future = Box::pin(async move {
        pre_flush?;
        let mut output_guard = ClearRenderBufferOnDrop::new(&mut cx.out);
        // render child, recover error fallback, commit or rollback
        let result = cx.flush_stream_chunk();
        output_guard.disarm();
        result
    });
    return RenderOutcome::Pending(future);
}

ClearRenderBufferOnDrop (suspense.rs:52) holds a raw pointer to the shared RenderBuffer. If the in-order boundary is cancelled or unwinds before its final flush, the drop guard clears only the unflushed suffix. Nested successful flushes already cleared the buffer and stay committed.

The default path ignores the fallback and renders the child inline.

// proa_stream/src/suspense.rs:257
let _ = fallback;
RenderOutcome::Pending(Box::pin(
    async move { proa_core::render_child(cx, child).await },
))

let _ = fallback marks the deliberate discard. A static or in-order render never shows the fallback. The MdRender impl does the same with a RestoreMarkdownBoundaryOnDrop guard that restores MdState on cancellation. The WebRenderSend impl mirrors the three branches for SendWebContext.

The Out-of-Order Driver

OutOfOrderBoundaryDriver (proa_stream/src/driver/out_of_order.rs:176) is the runtime-independent scheduler.

// proa_stream/src/driver/out_of_order.rs:176
pub struct OutOfOrderBoundaryDriver {
    in_flight: FuturesUnordered<ScheduledBoundaryFuture>,
    scheduled: BTreeMap<u64, ScheduledBoundary>,
    ready: VecDeque<BoundaryEvent>,
    deadlines: DeadlineIndex,
}

in_flight polls all admitted futures concurrently. scheduled maps id to priority, deadline, and an AbortHandle. ready buffers events already produced but not yet returned. deadlines tracks the earliest timeout.

The observable event is BoundaryEvent (out_of_order.rs:159).

// proa_stream/src/driver/out_of_order.rs:159
pub enum BoundaryEvent<R = RenderedBoundary> {
    Finished { id: u64, rendered: Result<R, WriteError> },
    TimedOut { id: u64 },
}

push admits a boundary, computing its deadline from now + timeout. It wraps the future in Abortable so the driver can cancel a stalled child. next_completed batches every result ready in the same poll, sorts by (priority_rank, id), and returns the first. expire cancels every boundary whose deadline passed and emits TimedOut events in the same priority order.

The deadline index switches representation at a crossover.

// proa_stream/src/driver/out_of_order.rs:35
const DEADLINE_HEAP_THRESHOLD: usize = 64;

Below 64 boundaries, deadlines live in a dense Vec scanned on each wake. Above it, the index rebuilds as a min-heap of (deadline, id) pairs. Stale entries are checked against the live BTreeMap, so an id whose deadline changed never produces a wrong expiry. The rebalance method shrinks back to dense below half the threshold.

The non-tokio next_event (out_of_order.rs:565) has no clock. It conservatively expires every timed boundary at admission, so a timeout never becomes an unbounded wait. Hosts that want elapsed-time semantics drive next_deadline and expire with their own clock.

SendOutOfOrderBoundaryDriver (out_of_order.rs:190) is the structurally separate Send twin. A local future cannot enter the direct path through type erasure.

The Transport Frame

The out-of-order wire format carries HTML as base64 inside an inert template.

// proa_stream/src/driver/out_of_order.rs:770
const BOUNDARY_TEMPLATE_OPEN: &[u8] = b"<template id=\"proa-tpl-";
const BOUNDARY_TEMPLATE_ENCODING: &[u8] = b"\" data-proa-encoding=\"base64-v1\">";
const BOUNDARY_TEMPLATE_CLOSE: &[u8] = b"</template>";
const BOUNDARY_SCRIPT_OPEN: &[u8] = b"<script";
const BOUNDARY_SWAP_OPEN: &[u8] = b">$proa(";
const BOUNDARY_SWAP_CLOSE: &[u8] = b");</script>";

append_boundary_template_slices writes the open tag, encodes the HTML slices directly into the template with a streaming EncoderWriter, then writes the close tag. append_boundary_swap_script_with_nonce appends a script that calls $proa(id). A same-ready batch writes several templates then one $proaBatch([ids]) script. A timeout writes with no swap, preserving the fallback already in the shell.

The drain loop ties it together.

// proa_stream/src/driver/out_of_order.rs:658
pub async fn drain_pending_boundaries_with_nonce_and_artifacts<F, Fut>(
    stream: &StreamContext,
    nonce: Option<&CspNonce>,
    mut emit: F,
) where
    F: FnMut(OutOfOrderBoundaryChunk) -> Fut,
    Fut: Future<Output = bool>,
{
    let mut driver = OutOfOrderBoundaryDriver::new();
    let mut pending_boundaries = Vec::new();
    loop {
        stream.drain_boundaries_into(&mut pending_boundaries);
        driver.extend(pending_boundaries.drain(..), Instant::now());
        let Some(event) = driver.next_event().await else { break; };
        // build OutOfOrderBoundaryChunk from Finished/TimedOut
        if !emit(chunk).await { return; }
    }
}

OutOfOrderBoundaryChunk (out_of_order.rs:627) is id, bytes, and artifacts. A successful boundary carries its exact RenderArtifacts. Failures and timeouts carry an empty snapshot, because their speculative subtree is not published. The callback must emit metadata before bytes. The swap script dispatches proa:boundary-ready at the end of bytes, so metadata appended after the frame arrives too late.
