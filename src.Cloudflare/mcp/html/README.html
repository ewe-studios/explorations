Cloudflare Model Context Protocol Server — Source Exploration

This set studies the official Cloudflare Model Context Protocol (MCP) server for the Cloudflare Application Programming Interface (API) at /Users/darkvoid/GitSources/src.Cloudflare/mcp, from git@github.com:cloudflare/mcp.git. This document set lives under /Users/darkvoid/Dev/explorations/src.Cloudflare/mcp/markdown/. The source path is a read-only checkout. This study writes only under the study path. The main question is how Code Mode works: how a model calls a large API by writing code against a catalog that stays on the server. The study is source-grounded: each factual claim cites a file and line in the repository, written as path:line or path:line-line.

Scope and sampling rule

The src/generated directory measures 53,784 KiB by the disk-usage command du -sk in this checkout. Here KiB means kibibyte (1,024 bytes), MiB means mebibyte (1,048,576 bytes), and MB means megabyte (1,000,000 bytes). That value is 52.5 MiB, or about 55.1 MB. The generated tools account for 27,692 KiB (27.0 MiB). The spec directory accounts for 26,092 KiB (25.5 MiB). The two values sum to the total. The single spec.json.txt file inside the spec directory is 26,325,766 bytes (25.1 MiB, or 26.3 MB). The directory is slightly larger than the file because it also holds the other two artifacts and because of block allocation.

This study samples generated code, and does not enumerate the catalog. The sample is one product group (d1), one shared schema file (d1/outputs.ts), the forge runtime (_/tool.ts), the index, and one spec artifact (spec.json.txt). Counts come from directory measurement and one parse of that spec artifact. The generation pipeline is described from its script. A product not sampled may differ in size, but the generated shape comes from one generator. See 13-limitations-and-open-questions.md.

The study is read-only. It makes no network call, installs no package, and changes no source file.

Reading order

Read 00 and 01 first. Then read 02, 03, 04, and 05 as one block: they describe the Code Mode mechanism from surface to sandbox. Documents 06 and 07 cover generation. Documents 08 through 12 cover serving, authentication, permissions, results, and operations. Document 13 lists what the repository cannot prove.

Central finding

The model never sees the OpenAPI document. It sees a small tool surface, and it writes code. The code runs in a fresh dynamic Worker. The credential stays in the parent Worker and enters the sandbox only as an outbound proxy property. The proxy is GlobalOutbound, a Worker entrypoint that receives the sandbox's fetch calls. That property belongs to the entrypoint's props. It never becomes a variable in the sandbox module. In Code Mode, the API response returns to the model as text, capped at about 6,000 tokens unless the search or execute call sets truncate: false. See 04-execute-tool.md and 05-the-isolate-boundary.md.
