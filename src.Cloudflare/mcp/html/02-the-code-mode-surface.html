The Code Mode Surface

Four tools, two modes

This document uses short forms. OAuth means Open Authorization. URL means Uniform Resource Locator. SDK means Software Development Kit.

Model Context Protocol (MCP) is the protocol this server answers. In the default mode the server registers docs, search, execute, and whoami (src/server.ts:91-98). The first three cover discovery of documentation, discovery of endpoints, and calls to the Cloudflare Application Programming Interface (API). The fourth reports the identity behind the credential (README.md:101-106).

A client changes the mode with a query parameter. ?codemode=false registers one direct tool for each generated API method (src/mcp-handler.ts:49-57, src/server.ts:83-88). The default is Code Mode because the parser treats only the exact string false as off (src/mcp-handler.ts:53).

The parameter handling is in src/mcp-handler.ts:49-63, and the defaults are in src/server.ts:18-41. The last row is a test override, not a product feature (src/mcp-handler.ts:59-63). A scope challenge is a 403 response that names an OAuth scope the caller must grant. http delivers it as that response. tool delivers it inside the tool result. The mechanism is in 10-permissions-and-refusals.md.

The server reads only the exact strings. codemode=0 does not turn Code Mode off. experimentalOutputSchema=1 does not turn output schemas on.

registerCapabilities({ tools: { listChanged: false } }) declares that the server will never send a tools/list_changed notification (src/server.ts:78-81). The tool set is fixed for the life of one request, so such a notification would be false.

docs

docs takes one string argument, query. It calls env.AI.autorag, a Cloudflare Artificial Intelligence (AI) Search instance named docs-mcp-rag (src/tools/docs-search.ts:155-171). An AI Search instance is a managed retrieval service. A binding is a Worker configuration entry that gives the Worker access to another service. The instance returns documentation chunks, meaning text fragments that match the query. Each fragment has a similarity score, source identifier, URL, title, and text (src/tools/docs-search.ts:19-25). The tool returns both text and structuredContent. Structured content is a machine-readable result that MCP carries next to the text. The text uses , , </code>, and <code><text></code> elements (<code>src/tools/docs-search.ts:101-113</code>, <code>src/tools/docs-search.ts:173-185</code>).</p> <p>The tool is registered in both modes. In direct mode it is one entry in the precomputed tool listing, with its own wire definition (<code>src/tools/docs-search.ts:57-99</code>). The AI Search call retries up to five times with exponential backoff (<code>src/tools/docs-search.ts:216-235</code>).</p> <p>If the <code>AI</code> binding is absent, the tool returns a clear error instead of throwing (<code>src/tools/docs-search.ts:101-104</code>). The top-level default configuration has no <code>ai</code> block. The staging and production blocks add one (<code>wrangler.jsonc:69-72</code>, <code>wrangler.jsonc:124-127</code>).</p> <h2><code>search</code></h2> <p><code>search</code> takes <code>code</code>, a JavaScript async arrow function, and an optional <code>truncate</code> Boolean (<code>src/tools/search.ts:62-67</code>). The value crosses the protocol as source text, not as an executable object. The sandbox splices that text into a module and calls it. The description lists products and the <code>spec</code> types, then gives three examples: find endpoints by product, read a request body schema, and read parameters (<code>src/tools/search.ts:26-58</code>).</p> <p>Two functions share the name <code>runSearch</code>. The main Worker has a small <code>runSearch</code> wrapper. It calls <code>env.FORGE_TOOLS.search(code)</code>, a Remote Procedure Call (RPC) to the forge tools service, and returns the inner value or throws the inner error (<code>src/tools/search.ts:15-19</code>). The service has its own <code>runSearch(loader, code)</code>, which builds the sandbox (<code>src/forge-tools/search.ts:26-53</code>). The handler formats the result with the truncation policy (<code>src/tools/search.ts:94-101</code>). The main Worker never holds the 27 mebibyte spec (<code>src/tools/search.ts:10-14</code>).</p> <p>The tool is read-only with respect to the API, but its annotations do not claim <code>readOnlyHint: true</code>. They set <code>readOnlyHint: false</code>, <code>openWorldHint: false</code>, and <code>destructiveHint: false</code> (<code>src/tools/search.ts:87-92</code>). The three hints are MCP tool annotations for clients. <code>readOnlyHint</code> says a call does not modify state. <code>openWorldHint</code> says a call reaches an external system. <code>destructiveHint</code> says a call can destroy data. The reason for the conservative setting is not stated. The annotation cannot grant network access. The sandbox configuration controls network access, and the tool description and the sandbox are the contract.</p> <h2><code>execute</code></h2> <p><code>execute</code> takes <code>code</code>, an optional <code>account_id</code>, and an optional <code>truncate</code> Boolean (<code>src/tools/execute.ts:419-426</code>). Its description embeds TypeScript declarations for <code>cloudflare.request()</code> and <code>accountId</code> (<code>src/tools/execute.ts:395-414</code>, <code>src/constants.ts:27-58</code>). TypeScript is a typed language built on JavaScript. The declarations show the types that the model should use.</p> <p>The description is identical for every client. The comment states the reason: MCP clients cache tool metadata and may serve one user's list to another. The description therefore must not name an account or depend on token shape (<code>src/tools/execute.ts:387-394</code>). Account resolution happens only in the handler (<code>src/tools/execute.ts:463-476</code>).</p> <p>The handler resolves the account, calls <code>runExecute</code>, formats a success, or builds a failure with account hints, GraphQL guidance, and a scope challenge (<code>src/tools/execute.ts:441-516</code>). The mechanism is in <a href="04-execute-tool.html">04-execute-tool.md</a>.</p> <h2><code>whoami</code></h2> <p><code>whoami</code> takes no arguments. It returns <code>{ id }</code>, plus <code>name</code> for an account token or <code>email</code> for a user token (<code>src/tools/whoami.ts:80-97</code>). The <code>id</code> is <code>user:<id></code> or <code>account:<id></code>. The source calls this format a permanent contract because clients store it across reconnects (<code>src/tools/whoami.ts:80-87</code>).</p> <p><code>_meta</code> is MCP's reserved metadata field on a tool. The tool carries <code>_meta['openai/profile']</code> and an OAuth security scheme with <code>user:read</code> and <code>account:read</code> (<code>src/tools/whoami.ts:39-48</code>). An account token belongs to one Cloudflare account. A user token belongs to a user and can reach that user's accounts. <code>openai/profile</code> is an OpenAI extension key. The scheme lists the scopes the profile call needs. This marker lets ChatGPT tell connected accounts apart (<code>README.md:118</code>).</p> <h2>The direct-tool surface</h2> <p>With <code>?codemode=false</code>, <code>tools/list</code> returns <code>docs</code>, <code>whoami</code>, and the generated tools (<code>src/tools/forge-tools.ts:54-60</code>). The generated tools live in the forge tools service. The main Worker asks for the listing once per isolate and caches it (<code>src/isolate-cache.ts:69-89</code>).</p> <p>The listing is large. The source comment says about 3,800 tools and 3.7 mebibytes (<code>src/tools/tool-list-response.ts:59-64</code>). The measured generated count is 3,040 tool names, so the comment is probably stale or counts another surface. A 2025-era request is an MCP request on a protocol version before 2026-07-28. The SDK helper <code>isLegacyRequest</code> decides that, and the exact version list is in the external SDK (<code>src/tools/tool-list-response.ts:1</code>, <code>src/tools/tool-list-response.ts:55</code>). The listing is encoded once per isolate. A legacy <code>tools/list</code> request gets that encoded listing directly. Such a request must be a single <code>tools/list</code> call with no cursor (<code>src/tools/tool-list-response.ts:13-21</code>, <code>src/tools/tool-list-response.ts:74-87</code>).</p> <p>Tool names come from forge. A name joins the group and the method with an underscore, such as <code>d1_list</code> or <code>zeroTrust_access_applications_list</code> (<code>AGENTS.md:205</code>). Arguments are grouped by location: <code>path</code>, <code>query</code>, <code>headers</code>, and <code>body</code> (<code>README.md:52</code>, <code>AGENTS.md:205</code>). The schema nests each argument under the part of the HTTP request where it goes.</p> <div class="mermaid"> flowchart TB Request["One request with query string"] --> Code{"codemode=false?"} Code -->|"no"| CodeSurface["docs, search, execute, whoami"] Code -->|"yes"| DirectSurface["docs, whoami, generated tools"] DirectSurface --> Output{"experimentalOutputSchema=true and 2026-07-28?"} Output -->|"yes"| WithSchema["direct listing carries output schemas"] Output -->|"no"| WithoutSchema["direct listing without them"] </div> <p>The rule is per request, not stored state. The same client can use both modes by changing the query string of the same URL (<code>src/mcp-handler.ts:49-57</code>).</p> <h2>Result shaping differs by mode</h2> <p>In Code Mode, the default cap is on. <code>search</code> and <code>execute</code> each accept a <code>truncate</code> argument. When the argument is absent, the connection default applies. That default comes from the request's <code>truncateToolResult</code> query parameter (<code>src/server.ts:34-40</code>, <code>src/truncate.ts:41-50</code>). The cap is about 6,000 tokens (<code>src/truncate.ts:19-22</code>).</p> <p>In direct mode, the default cap is off. The README explains that clients which disable Code Mode usually run their own code mode. They parse each result, so a cap would lose data (<code>README.md:85</code>). A caller can still set <code>?truncateToolResult=true</code> (<code>src/mcp-handler.ts:51-55</code>).</p> <h2>Metrics wrapping</h2> <p><code>attachMetrics</code> replaces the server's <code>registerTool</code> method with a wrapper (<code>src/metrics.ts:320-371</code>). The server calls it before it registers the four Code Mode tools, so the wrapper is in place for all of them (<code>src/server.ts:83-99</code>). Every tool registered after that call records a <code>tool_call</code> event. The event goes to the <code>MCP_METRICS</code> Analytics Engine dataset. Analytics Engine is Cloudflare's metrics store. The wrapper also copies <code>tool.title</code> into <code>annotations.title</code> when the annotations lack a title (<code>src/metrics.ts:338-345</code>).</p> <p>Direct tools are not wrapped by that function. The direct branch returns before <code>attachMetrics</code> runs. Its own <code>tools/call</code> handler registers no tools, so a wrapper would see no calls. The handler records one event per call instead (<code>src/tools/forge-tools.ts:94</code>).</p> <blockquote><strong>Aha:</strong> The tool surface is deliberately token-independent. Tool descriptions, schemas, and account guidance are the same for every user. This is unusual for a multi-tenant server. It follows from client behavior: a client may cache a tool list and show it to a different client.
