2. Scope

This exploration explains how Kitesurf parses HyperText Markup Language (HTML), applies Cascading Style Sheets (CSS), runs page JavaScript, records a paint scene, and serves the Chrome DevTools Protocol (CDP) from a Cloudflare Worker. It covers the repository as one system: the Rust core, the page script runtime, the worker engine, the renderer, the command-line tool, and the build and test machinery.

It does not cover Cloudflare Dynamic Workers as a product, the Workerd JavaScript runtime internals, or the commercial hosting plan.

3. Method

  1. Read the repository instructions in AGENTS.md, CONTRIBUTING.md, and

README.md.

  1. Map every package under packages/, every Bazel target, and every script

under scripts/.

  1. Read each package from its entry point to its leaves. Record the data

flow across the Worker-to-WebAssembly boundary.

  1. Write one document for each layer. Quote the source byte for byte and cite

the file and line range.

  1. Review every document against the pinned source, then with a fresh reader.

5. Constraints

  • Aerospace and Defence Simplified Technical English (ASD-STE100) applies to

every sentence. Expand each abbreviation at first use in each file.

  • Every document has at least two Mermaid diagrams, at least ten byte-exact

code snippets, at least one Aha insight, and path:line citations.

  • A snippet shows the source as it is. It does not paraphrase and it does not

join several files into one block.

  • The documents state when the repository does not define a value or a

behaviour. They do not fill a gap with a guess.
