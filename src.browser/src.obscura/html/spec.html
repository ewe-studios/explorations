2. Scope

This exploration explains how Obscura parses HyperText Markup Language (HTML), runs page JavaScript on the V8 engine, applies Cascading Style Sheets (CSS), serves the Chrome DevTools Protocol (CDP), renders screenshots and Portable Document Format (PDF) files, and exposes a Model Context Protocol (MCP) server. It covers the ten workspace crates, the command-line interface, the vendored patches, and the test and release machinery.

It does not cover the hosted Obscura Cloud service or the commercial stealth proxy network.

  2. Map every crate in Cargo.toml and every feature flag.
  3. Read each crate from its public entry point to its leaves. Follow one

navigation, one script call, and one screenshot from start to finish.

  1. Write one document for each layer. Quote the source byte for byte and cite

the file and line range.

  1. Review every document against the pinned source, then with a fresh reader.

10. Corrections and limits found during research

First readingWhat the source showsEvidence
The browser is one programThe repository is a ten-crate workspace with one binary crate and several library cratesCargo.toml, crates/
Rendering is always availableThe render feature is off by default. It adds layout, paint, and a JavaScript geometry bridgecrates/obscura-js/Cargo.toml
Stealth is a separate productThe stealth feature replaces the HTTP client and routes script requests through the same fingerprintcrates/obscura-js/Cargo.toml, crates/obscura-net
JavaScript runs in a separate processV8 runs in the same process through deno_core, with an explicit operation boundarycrates/obscura-js/src
The prose architecture says nine cratesThe workspace has ten members. The folder crates/test-support is not a member and holds one Rust source fileCargo.toml:1-14, crates/test-support/
The architecture document says one V8 isolate with one global lockEach Page owns a JsRuntime with its own isolate. The lock is a field of the connection context, not a process-wide valuecrates/obscura-cdp/src/dispatch.rs:756-768, crates/obscura-js/src/runtime.rs:437-458
The renderer is present in every buildEvery crate sets default = []. A release archive contains the renderer because the release workflow requests --features rendercrates/obscura-js/Cargo.toml:8-17, .github/workflows/release.yml:108
The MCP server exposes a short fixed tool listThe server defines 38 tool names. Two are gated on render, so a default build exposes 36crates/obscura-mcp/src/lib.rs
